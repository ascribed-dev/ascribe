# ascribe-templates

The page templates Ascribe ships: The Good Docs Project's, converted into Ascribe pages, and carried as they were committed. The plan is [project-docs/page-templates/README.md](../../project-docs/page-templates/README.md). This README is about the code.

## Pieces

| Path | What it is |
|---|---|
| `set/` | The copies, generated by [`scripts/templates/convert.ts`](../../scripts/templates/convert.ts) from the release [`scripts/templates/upstream.toml`](../../scripts/templates/upstream.toml) pins: for each template, `<name>.md`, the template as a page, and `<name>.guide.md`, their guide with a line saying where it's from. `set.toml` lists them, with their tag, commit, and license, and their index's summary of each. |
| `src/lib.rs` | `FILES`: each file of `set/`, as committed. |

## Rules

- **Nobody edits a file in `set/`.** A change to one is a change to the script, to a rule in `scripts/templates/rules.toml`, or to their repository. `node scripts/templates/convert.ts` rewrites them, and `--check` lists the stale ones.
- **A template carries no line saying where it came from:** a page copied from it would carry the line too. Its guide says it, and `set.toml` does.

## Tests

- `tests/all/set.rs`, with no network: `FILES` and `set.toml` list what `set/` holds; each template is a page `ascribe check` has nothing to say about, in a project that declares its type, and that `ascribe fmt` leaves as it is; and none has a level-1 heading or a block quote.
- `scripts/templates/convert.test.ts`: the conversion's steps, and the copies being what the pinned release gives, which needs their repository and an `ascribe` binary. CI runs that comparison after its build, in `rust.yml`.
