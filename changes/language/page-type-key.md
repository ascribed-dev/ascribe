- **Behavior change: a page names its content type in its frontmatter, with `type`.** In a project whose `ascribe.toml` declares types, every page says which one it is, such as `type: guide`, wherever its file is, and a folder can hold pages of every type. A page that names no type is an error (`content-type-missing`, ASC196), with a fix for each declared type, and one that names a type that isn't declared is an error at the value (`content-type-unknown`, ASC197), with a fix to the closest name. `[types.<name>]` no longer takes `files` or `default`: each is an unknown key (`model-unknown-key`), whose message says to name the type with `type:` on its pages. Their checks, ASC051, ASC071, and ASC072, are retired. A project that declares no types has the implicit type `page` and needs no change; `type` is now a reserved frontmatter key everywhere. The Zod output gives each type `type: z.literal("<name>")`, and `schema` is a `z.discriminatedUnion("type", …)` of the types when there are several; `contentTypes` is gone. The JSON of `ascribe model`, `ascribe templates eject`, and `ascribe init` is at `schema_version` 2: a type has no `files`, and `eject` lists the pages that name no type as `untyped`. The starter templates begin with `type:`. See `docs/content/reference/content-model.md` and [decision #450](project-docs/decisions/450-page-type-key.md).
