- **The specification tells its own errors from a content check a project raises to an error.** §8.2's errors make a page non-conforming and are never quieted. A content check's level is the project's to set in `[checks]`: one raised to `"error"` fails the build as an error does, but the page is still conforming, and a review check raised this way can still be acknowledged ([SPEC.md](SPEC.md#82-diagnostics) §1.3, §4.9, §7.2, and §8.2). [Quieting a problem](docs/content/checks/check.md) compares `@intended`, `[checks]`, and the baseline. Ascribe already worked this way; the spec now says so.
