- **Behavior change: a code block's info string has a grammar, and the outputs drop the checker's pairs.** [SPEC.md](SPEC.md) §3.3.1 says how a fenced code block's `phrases`, `title`, `tested`, `request`, and `response` are read: after the language, in any order, each a key, `=`, and a token or a quoted value whose `\"` and `\\` escape, and the first pair with a key counts. Words that aren't pairs are left for your highlighter. `phrases=true` inside a title no longer opts a block in to phrases, and `title="say "hi""` is no longer a title: write the quote `\\\"` in the page. The site and plain outputs leave out `request` and `response`, whose links are your repository's paths, and the plain output no longer repeats a tested example's `tested` in its info string above its "Tested with" line.
