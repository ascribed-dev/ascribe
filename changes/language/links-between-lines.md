- **Behavior change: a link to a page a line doesn't publish leads to another line.** In a line of a versioned build, the link lands on the page that replaces it, or that it replaces, else on the page in the nearest line that has it, the closest newer line first. A link out is marked with its line: `data-ascribe-release-line` in the site output, which the elements' stylesheet shows as " (3.5)", and " (3.5)" after the link in the plain output. Only a page no live line has is still `link-page-dropped`. A link from the current line into an older one is advice, `link-into-older-line`, and a `#id` the page it lands on doesn't have is dropped, with advice, `link-fragment-dropped`. See [Versions](docs/content/versions/index.md#links-between-lines).
- **Behavior change: `replaces` is a reserved frontmatter key.** A page rewritten under a new path says which page it takes the place of, `replaces: configure-legacy.md`, and a versioned build follows it. It must name a page; a chain that comes back to the page is an error, and so is a line that publishes a page and the page it replaces. A content model can no longer declare a field named `replaces`. See [A page that replaces another](docs/content/writing/directives.md#a-page-that-replaces-another).
