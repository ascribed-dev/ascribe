- **`@ascribed/astro` gives Astro the site's address.** When `astro.config.mjs` leaves out `site`, `base`, or `trailingSlash`, the integration takes it from `ascribe.toml`'s `[consumer]` (`site`, `base-path`, `trailing-slash`), so the address is written once, and a preview built for its own address changes only `ascribe.toml`. A setting the Astro config gives must still agree, as before. With `projects`, `site` and `trailingSlash` come from the first entry whose project sets them, and `base` stays the site's. **Behavior change:** Astro can't tell an integration an unset setting from its default, so with `build`, `base: "/"` now becomes `base-path`, and `trailingSlash: "ignore"` becomes `trailing-slash`. A site with a home page at `/` in front of one project's docs lists the project in `projects` instead (`projects: [{ name: "docs", build: "site" }]`, and `name: "docs"` in its collection) to keep `base` at `/`. See the [Astro guide](docs/content/guides/astro.md).
