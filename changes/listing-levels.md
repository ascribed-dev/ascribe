- **A project can set how a folder's, a type's, or the whole site's pages are listed.** `[listing]` in `ascribe.toml` has `default` for every page, `[listing.folders]` for the pages under a folder, and `[listing.types]` for the pages of a content type, each `listed`, `unquoted`, or `unlisted`, so `"internal/" = "unlisted"` keeps a folder out of the sitemap and `llms.txt` with no change to its pages. A page gets the strictest that applies. A page can set a stricter value than its rule, and one that sets a looser value is an error that quotes the rule and its line (`listing-loosened`), with a quick fix that removes the page's own setting; a rule looser than one it's under is an error too. Each page's record in `_ascribe/pages.json` says where its listing came from, in `listing_from`. `@ascribed/astro`'s `Head.astro` now asks search engines not to quote an `unquoted` page (`nosnippet`). In the editor, `listing:` completes its values, and hovering it names the rule the page is under. See the [`ascribe.toml` reference](docs/content/reference/content-model.md) and the [Astro guide](docs/content/guides/astro.md).
