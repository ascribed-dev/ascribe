- **`ascribe build` and `ascribe report` hold back what `ascribe.baseline` lists, as `ascribe check` does.** A project with a baseline no longer sees its whole backlog of advice from the build and the report while `ascribe check` reports only what's new. The build's summary line and JSON count what it held back (`, 3412 in the baseline`, and `summary.baselined`), and so do the report's `problems` section and its JSON (`problems.baselined`), a measure of the backlog. `--no-baseline`, which `ascribe check` had, now works on both and reports everything. A baseline that can't be read stops them, as it stops `ascribe check`. The first report after updating counts the advice the baseline now holds back as gone since the last report, once. See `docs/content/checks/baseline.md`.
