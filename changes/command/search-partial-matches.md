- **`ascribe search` lists partial matches when no block has every word, and skips common words.** `ascribe search "webhook signature"` said "No place matches." beside a section called "Sign webhook events"; it now says "No block has both words. These have 1 of 2:" and lists the closest places, at most 10, each with the words it lacks. In JSON they're `partial_places`, and `places`, `total`, and the exit code `1` keep their meaning. Common English words outside quotes, such as `how`, `I`, and `the`, needn't match, unless they're all the query has, so `ascribe search "how do I publish llms.txt"` finds what `"publish llms.txt"` finds; `stop_words` names them. The editor's search and `ascribe_search` read queries the same way. See `docs/content/command/questions.md`.
