- **`ascribe report links` holds a link that answered before until it keeps failing.** A link whose address answered on an earlier run and fails now is listed as unconfirmed, with what it answered, the last day it answered, and the day it's reported from, until it has kept failing for `[checks.links] confirm-days`, 3 days unless set; `0` reports every failure at once. A 404 or a 410 is reported at once, a moved link isn't held, and an acknowledged link stays acknowledged. An unconfirmed link isn't counted, doesn't fail `--exit-code`, and is left out of `--format prompt`. What each address last did is kept in `.ascribe/history/links.json`, so the report also says which problems are new since the last run and how many it reported are gone. A first run, or one with `--no-history`, reports every failure, and says so. The JSON's `links` gains `previous_run`, `new`, `resolved`, and `unconfirmed`, and `schema_version` stays `1`. The scheduled job in [The project report](docs/content/guides/report.md#on-a-schedule) keeps the history with `actions/cache` too. Deleting `.ascribe/history/` costs one noisier report, and never a missed problem.
