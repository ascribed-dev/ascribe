---
section: The binary
---

**`source.fixAll.ascribe`, Apply the safe fixes in this page, applies in one edit every safe fix of the problems the editor shows in a page or a fragment, and runs on save only where someone sets it in `editor.codeActionsOnSave`.** It takes the fixes from the diagnostics last published for the document, and only when they're for its current version; advice comes last, then the rest by range, and `ascribe_check::fix::Settled`, which `ascribe check --fix` uses too, settles two that edit the same text: the first is kept, and the other's problem stays for the next run. A problem that needs every build to tell, such as `intended-unused`, isn't one the editor shows, so its fix is applied by `ascribe check --fix` alone, and the editor's page says so. It's in the Source Action menu, and first among the actions bar's fixes when a page has two or more; nothing sets `editor.codeActionsOnSave` for anyone. Every editor with a language client gets it. _Why:_ a page with several safe fixes took one light bulb each; the editor knows only the problems it shows, and sharing `Settled` with `--fix` keeps the two from settling a page's fixes differently. _From:_ the maintainer, on the editor's views plan ([README](../editor-ui/README.md), decision 15) and its [proposal](../proposals/editor-ui.md#in-the-editor), 16 October 2026, which had it apply the set `ascribe check --fix` applies to the file; kept to the problems the editor shows in [#563](https://github.com/ascribed-dev/ascribe/pull/563), 17 October 2026; recorded when the plan closed, with [#544](https://github.com/ascribed-dev/ascribe/issues/544).
