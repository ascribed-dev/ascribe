section: The npm packages
---

**`npx @ascribed/astro init` writes a stylesheet for the starter's layout, which the layout imports.** It's [`docs.css`](../../packages/astro/starter/src/styles/docs.css), written to the site's `styles` folder, and the site's own from then on, like the other starter files: a readable column, the sidebar beside the page and behind a **Menu** (a `<details>`) on a phone, the table of contents beside the page where there's room, both color schemes, and spaced previous and next links. It writes no color of its own: its colors and spaces are the element library's `--ascribe-*` properties, and the page's background and text the browser's `Canvas` and `CanvasText`, so a site restyles the layout as it restyles the elements. Deleting the file and its import leaves a layout whose markup reads in order. It isn't an export of `@ascribed/astro`, so a site's styles never change under it in a release. _Why:_ the first site a new user published rendered in browser defaults, Times on white with the sidebar above the page, which is what Ascribe output looked like to their readers. _From:_ the maintainer, on [#1003](https://github.com/ascribed-dev/ascribe/issues/1003), 26 October 2026, from the human-reader and technical-writer reviews.
