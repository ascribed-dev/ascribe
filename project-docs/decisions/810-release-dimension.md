---
section: The language
---

**`[releases.<target>]` declares a target no declared dimension has as a value of an implicit dimension, `release`.** A target a declared dimension already has stays that dimension's value, as `self-managed` stays `deployment`'s, and adds nothing. The implicit dimension exists only while it has a value, comes after the declared dimensions in their order, and is named everywhere a dimension is: `@variant {release=…}`, a switcher's `sync`, a build's `variants`, `dimension:` targets in `ascribe refs`, and the elements' `dimension` attribute; `ascribe model` lists it with the others. While a target is left to it, `release` is reserved: a project that declares its own `[dimensions.release]` gets `model-releases-target` at each such target, naming both. It has two labels, for two things: `[releases] label` is the dimension's, `Release` unless set, and `[releases.<target>] label` is the target's, its name unless set; both are rows in the settings registry. A target a declared dimension has takes no `label` (`model-releases-target`), since that dimension's `labels` already labels it and a second home could disagree. The contract's §7.1 and the elements contract's choice of `sync` say so. The docs and the site's own pages drop `[dimensions.release]` for `[releases.ascribe] label = "Ascribe"`, with the same outputs. _Why:_ a release target had to be declared twice, once as a dimension's only value and once as a `[releases]` table, and a project whose product is the only thing it versions had a dimension it never varied content along. _From:_ piece 3 of [the shorter content model](https://github.com/ascribed-dev/ascribe/blob/bb56bfb3/project-docs/proposals/shorter-content-model.md#3-releases-declare-their-targets), made the maintainer's issue [#810](https://github.com/ascribed-dev/ascribe/issues/810), 22 October 2026.
