section: The docs and the site
---

**A permalink's address forwards with a 301 on a host that takes redirects, a retired one answers 410, and each permalink's section is served as Markdown beside its JSON.** With `[consumer] host = "netlify"`, the current line's `_ascribe/host/_redirects` gets, after the moves and the retired addresses, the rules for each name in `_ascribe/permalinks.json`: for each dimension, `<address> <dimension>=:<dimension> <address> 200!`, which keeps the forwarding page for an address with that parameter, so its script takes the reader's choice; then `<address> <route>#<fragment> 301!`. A retired name has `<address> <address> 410!`, serving its page with that status, since it tells a fetcher the page is gone on purpose. Each is forced (`!`) past the forwarding page, which stays for hosts without redirects; `@ascribed/astro` reads the query parameters and `!`, and doesn't count a forced rule as one that hides a page. `redirects.json` (output-layout contract §1.8) doesn't list them: they come from the permalinks list, and its format is unchanged. `@ascribed/astro` serves each help entry's section at `<path><name>.md`, and `<base>go/<name>.md` for an older line, as `# <title>`, a blank line, and the entry's `text`, so the edge function's `.md` lookup answers a permalink's address asked for as Markdown with no change; the forwarding page names it and the JSON with `<link rel="alternate">`, and `headers.json` gives the `.md` `Access-Control-Allow-Origin: *` and the `.json` a `Link` to it, `rel="alternate"; type="text/markdown"`. The title is a heading because an agent reading the section alone has nothing else naming it. _Why:_ most agent fetchers follow neither a meta refresh nor a fragment, so a permalink cost an agent a second fetch and then the whole 49 KB page instead of its section. _From:_ [#1019](https://github.com/ascribed-dev/ascribe/issues/1019), the agent-reader review's finding F1, with the product decision on the issue, 26 October 2026.
