section: The binary
---

**Project Settings draws `ascribe/settings` for the text the editor has, edits simple values in place with `setSetting`, and links to the file for the rest.** The language server answers `ascribe/settings` from the registry (`crates/ascribe-model/settings.toml`) and `ascribe.toml` as it is now: the open buffer, unsaved text included, or the disk, even while it doesn't load, with each setting's value, default, description as plain text and code spans, the range that sets it, and the problems published on that range. Each answer names the version of the open buffer it read, or `null` for the disk, and the tab draws only an answer whose version is the open document's (none when the file isn't open); any other is dropped and asked for again. `ascribe/edit`'s `setSetting` changes one value the file writes, through `ModelFile`, from the same text, and is refused for any version but the one the tab drew, which it's sent as `shown`, the disk's `null` included, so an answer from the disk can't edit a buffer nor a buffer's the disk; the tab applies the edit only if the document is still at that version when the edit comes back, checked in the same tick as the apply, so typing while the server plans it isn't written over; it isn't refused for a problem the model then has, which shows under the setting, as typing would show it. The edit is applied as a workspace edit, so `ascribe.toml` changes unsaved and Undo puts it back, and every change to the document, the tab's own included, reaches the tab the same way: the document changes, and the tab asks again. The tab edits only a switch, a choice, a number, a text, or a level the file sets, and links to the file for everything with structure (tables, lists, types, builds, sources) and, until the next phase, for a key the file leaves out. It's a webview panel on the This page base (decision [#651a](651a-this-page-webview.md)): its shell, policy, handshake, and numbered answers, with its own messages for a change, a link to a line, and the editor's settings, beside the base's. _Why:_ the riskiest seam of the proposal is the round trip, and a tab that drew an answer for older text, or made an edit against it, could show a value the file no longer has or write over what was typed; tying both to the buffer's version makes that impossible rather than unlikely (but for one case: VS Code numbers a reopened document from 1 again, so an answer for version 1 of an earlier open, still in flight across a close and a reopen, would pass; that takes all three at once, and an edit made from it is still planned against the text as it is, so it changes only the one value), and leaves VS Code's own undo and dirty state as the record of every change. _From:_ the [Project Settings proposal](../proposals/project-settings.md#settled), settled by the maintainer, and [the editor's next views](../roadmap.md#track-s-project-settings), 20 October 2026; built in [#658](https://github.com/ascribed-dev/ascribe/issues/658).
