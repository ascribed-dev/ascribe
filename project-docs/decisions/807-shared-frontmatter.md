---
section: The language
---

**Every page type has a required string `title`, declared or not; a content model can declare fields every type shares, in `[frontmatter]`, which a type's own field of the same name replaces whole; and a field named `description`, `review-date`, or `owner` takes that role unless the type gives it to another field.** A page's title is still its frontmatter `title` (SPEC §5.2). Declaring `title` changes only how it's read, and one declared optional, with a default, or of another type is an error (`model-field-reserved`); `model-type-title` is gone. A type can have no keys, as `[types.index]`, and the implicit `page` type has the shared fields too. A type's own `role` beats a shared field's, and a role given to no field goes to the field of its name when the field's type takes it. SPEC §7.2 says it. *Considered:* merging a type's field with the shared one key by key, and an error for a type that declares a shared field. _Why:_ a model's types repeated the same `title` and `description` on every type, and named the `description` role on each, so the docs' six types were mostly copies. Types differ by whole fields, as an index page's optional `description` does: an error would push a field out of `[frontmatter]` for every type the moment one differs, and merging would split one field's declaration across two tables. _From:_ the maintainer, 21 October 2026, Settled 3 of the [proposal for a shorter content model](../proposals/shorter-content-model.md#settled), with breaking changes acceptable; built in [issue #807](https://github.com/ascribed-dev/ascribe/issues/807). Replaces [decision #689c](689c-page-title.md).
