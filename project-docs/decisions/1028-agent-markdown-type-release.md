section: The binary
---

**In the Markdown a build publishes for agents (`[consumer] agents`), each page says what it's for after its title, and, for a project with `[releases]`, which releases the build describes.** After the title and the availability line, a blockquote gives the page's type, its first letter capitalized, and its description as `llms.txt` shows it, joined by ` · `: `> Reference · Every option of ascribe.toml.` The type is left out for the implicit `page` type of a project that declares no types, and the blockquote when that leaves nothing. The blockquote at the top of each page, and each `llms.txt`'s summary, end with the releases the build describes, each target by its label: a line of a versioned build its line, a build that filters for a version that version (and one that filters for a target without lines nothing), and any other build each target's live lines, with a sentence that what's marked with the planned label is in none of them when a target has a planned line. A page that a version line follows leaves the line to it. A project without `[releases]` writes nothing new. _Why:_ an agent that lands on a page from a search never saw its description, which the site shows under the title, and whether a page is a contract or a how-to tells it how far to trust the page as normative; and without the release, an agent helping someone on the live release can't tell whether an option without an availability mark exists for them. _From:_ the maintainer, on [#1028](https://github.com/ascribed-dev/ascribe/issues/1028#issuecomment-6418263617), from the agent-reader review's findings F4 and F8, 26 October 2026.
