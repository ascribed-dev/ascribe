section: The language
---

**SPEC.md specifies the implicit dimension `release`: a `[releases.<target>]` table whose target no declared dimension has, as a value or as its name, makes that target a value of `release`, labeled by the table's `label`.** §4.4 says a target is a value of a dimension, declared or implicit, and that `release` names all such targets; §7.2's Dimensions and Releases rows name the implicit dimension, and a paragraph after the table says it's used in `@available`, in `@variant` attributes, in a page's `variant` frontmatter, and in a build's selection, as a declared dimension is, and that a declared `[dimensions.release]` takes the name, making each target left to the implicit dimension an error. The conformance case `directives/available/release-target` covers a target from `[releases]` alone. _Why:_ the implementation has had the implicit dimension since [#810](https://github.com/ascribed-dev/ascribe/issues/810), and the content model reference documents it, but the spec didn't, so a reader of it couldn't tell why `@available: agent 2.1` is valid in a project with no `[dimensions]`, or that `release` is a reserved dimension name. _From:_ Kyle, [#964](https://github.com/ascribed-dev/ascribe/issues/964), 26 October 2026.
