---
section: The docs and the site
---

**The JSON contracts show each published schema's fields as tables generated from it, and link the schema at the release's tag instead of printing it.** `crates/ascribe-cli/src/shapes/fields.rs` writes them into `docs/content/_generated/json-*.md`: the document's fields first, then one table for each type a field names, in the order first named, with each field's path, type, whether it's required, whether it's nullable, and its description. An object, or a type named once, has its fields as rows under the field's path; a union of objects has a table per option, named by its tag; a union of names, a table of the names. Nullable means a required field that can be `null`, since a field that isn't required is left out instead. _Why:_ the pages were the raw schema, `$defs` in alphabetical order, so finding a field's type meant following `$ref`s. Printing the schema too, behind a `@details` as the issue first asked, put four pages at 64,000 to 76,000 characters, over `page-size`'s 50,000, and three of them are one schema each, so no split helps; the schema is a file at a fixed address, and in `@ascribed/cli` ([decision #1261a](1261a-schemas-ship-per-version.md)). _From:_ the maintainer, in [issue #1261](https://github.com/ascribed-dev/ascribe/issues/1261), 3 November 2026, for the tables, and on pull request #1366, 4 November 2026, for linking the schema instead of printing it.
