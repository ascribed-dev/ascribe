section: The language
---

**A page names its content type in its frontmatter, with the reserved key `type`, and `[types.<name>]` has no `files` or `default`.** In a project that declares types, every page has `type: <name>`, naming a declared type, wherever its file is; a page with none is `content-type-missing` (ASC196, next step `choose`), with an unsafe fix per type that adds the line first in its frontmatter, and a page naming a type that isn't declared is `content-type-unknown` (ASC197) at the value, with a fix to the closest name when there's one. A project that declares no types needs nothing: its pages are of the implicit `page` and name no type, and a `type` there is `content-type-unknown` with a fix that removes it. A fragment can't use `type` (`frontmatter-reserved-in-fragment`), and no type or fragment schema can declare a field `type` (`model-field-reserved`). `files` and `default` in a type's table are `model-unknown-key`, with a message that says to write `type:` on the type's pages instead; there's no migration. `content-type-unresolved` (ASC051), `model-type-multiple-defaults` (ASC071), and `model-type-unreachable` (ASC072) are retired, since a page can't match several types or none, and any declared type can be used. The type is read once, in the source index, and every check, output, and editor feature reads it from there. Tools that write a page put `type` first: the starter set's templates carry it, as `scripts/templates/convert.ts` writes them, and New Page, `new-page`, and `ascribe templates eject`'s pages start with it; `ascribe fmt` doesn't move it. The site output's Zod schema gives each declared type `type: z.literal("<name>")`, and its `schema` is a `z.discriminatedUnion` on it; `contentTypes`, which said which files each type covered, is gone. `ascribe model`'s JSON drops `files` and `default` (`schema_version` 2), as `ascribe templates eject`'s does a type's `files`, `folder`, and `pages` and the default type's pages, for `untyped`, the pages naming no type (`schema_version` 2, and `ascribe init`'s with it). `[listing.types]` is unchanged: it names types, which pages now declare. SPEC §2.1, §2.2, §7.2, §8.2, and Appendix B say so. This replaces the content-model contract's decision 2, and amends the page-templates plan's decision 16. _Why:_ a type assigned by folder put each kind of page in a folder of its own, which isn't how documentation is organized, and made eject's folders a migration for every project with pages; a page that says what it is reads the same to a person, an agent, and every tool, wherever it's moved. _From:_ the maintainer, on [#450](https://github.com/ascribed-dev/ascribe/issues/450), 12 October 2026.
