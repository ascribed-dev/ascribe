section: The binary
---

**`ascribe diff` lists a page whose output changed through a declared API's spec, and names the operation among its causes.** `because` in `schemas/diff.schema.json`, and in the editor's and the site's review, which share its shape, takes a third kind of name at `schema_version` 1, after the snippets and before `ascribe.toml`: an operation whose spec changed what the page writes for it, an `@operation`'s method, path, summary, or deprecation, or a link's address, named by its spec's path from the project root, `#`, and the fragment the page names it by, as it's written after decoding (`api/openapi.yaml#createWidget`). A rename is named by the old id, since that's what the page still says. A spec change no page shows, such as a schema or a description, lists nothing. The text says `1 changed (through api/openapi.yaml#createWidget)`, as for a snippet. A consumer tells the kinds apart as the field's description says: a content file's path ends in `.md`, a snippet's address has its source's name and `:` before its path, and an operation's has a `#` and neither. No field is removed and none changes meaning, so the version stays. The base revision's tree now holds each declared spec, outside the project's folder too, so the base reads its specs from git as it reads its pages. _Why:_ a spec edit that changed published guides went unreported, so a reviewer reading the diff never saw it; a cause of the same kind already exists for snippets. _From:_ [#1000](https://github.com/ascribed-dev/ascribe/issues/1000), the software engineer review's finding, with the product decision on the issue, 26 October 2026.
