---
section: The language
---

**A term's id is its heading's id, its definition is the paragraph that opens its section, as a reader reads it, and a glossary page is otherwise an ordinary page.** The id is the heading's source id, from its `@id` or its text, and it's the name the term has everywhere: the site output's `data-ascribe-term`, the JSON output's terms, `ascribe model`'s `id`, and `ascribe refs term:<id>`. An `@id` keeps it when the heading is reworded, and renaming the `@id` renames the term. The definition is that paragraph as plain text, derived for each build: phrases substituted, emphasis and inline code reduced to their text, a link to its text, an image to its alt text, inline HTML dropped, and line breaks and whitespace runs one space. It's the site output's link title, the editor's hover, and, with each use, the JSON output's `definition`. `[glossary] pages` is a list of paths from the content root, written as in a link, and a project with no `pages` has no glossary; `[glossary] match` and `case-sensitive` are what every term starts from, and `marked` is a term's setting only. `ascribe model`'s `page` for a term is the file its heading is written in, from the content root, the glossary page or a fragment it includes, and `line` is the heading's line there. A glossary page has a type, frontmatter, a route, a place in the navigation, fragments, `@available`, and variants, as any page does, and `@term` renders nothing. _Why:_ a term written as a heading takes the heading's name, so a reader, an output, and a command all call it one thing; a definition shown where there's room for one sentence is the words a reader reads, without what only a renderer sees; and a writer learns nothing new to write a glossary page. _From:_ the maintainer, on the glossary pages plan ([README](../glossary-pages/README.md) decisions 2, 4, 7, 8, 15, and 18; [phase 1](../glossary-pages/phase-1-decisions.md) decisions 1 and 4), 14 to 16 October 2026; recorded when the plan closed, with [#548](https://github.com/ascribed-dev/ascribe/issues/548).
