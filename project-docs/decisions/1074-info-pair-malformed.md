---
section: The language
---

**A word after a fenced code block's language that starts like a pair a processor reads, and isn't one, is a SPEC §8.2 warning, `info-pair-malformed`; SPEC §3.3.1 says processors report it, instead of saying they don't.** "Starts like a pair" is one of the keys in §3.3.1's table (`phrases`, `title`, `tested`, `request`, `response`), in any case, then optional spaces or tabs and `=`; `ascribe_core::info_string` decides what's a pair. The word is still left to the consumer. Where what was meant is clear (spaces around `=`, a key not in lowercase, a quote inside a quoted value, a quote that doesn't close), the message names the pair and an unsafe fix writes it, with each backslash doubled for CommonMark. `code-language-missing`'s message names a pair written as the first word, which renderers take as the language. Other words, such as `{1,3}` or `showLineNumbers`, stay unreported. _Why:_ in each of these cases the author meant a pair, and the block quietly lost its title, its phrases, or its example marker; a title with a quote escaped once, which worked before #1072, lost its title without a word. _From:_ Kyle, [#1074](https://github.com/ascribed-dev/ascribe/issues/1074), 26 October 2026.
