section: The language
---

**A project lists each versioned target's release lines in `[releases.<target>]`, and the rest is worked out from the list: the current line is the newest live one, and a version in a line newer than it is planned.** Versions are four levels a project opts into one at a time: none, the list, a build for each live line ([decision #502b](502b-versioned-builds.md)), and an archive ([decision #502j](502j-archive.md)); a project with no `[releases]` works and writes exactly what it did without it. The table takes `live`, `planned`, `ends` (a live line's last day of support), and `archived` (each entry a table with `url` and `ended`, both optional), and `[releases]` itself takes `planned-label`, `"planned"` unless a project sets it. A line is a version as the list writes it, and holds every version that starts with it: `3.4` holds `3.4`, `3.4.2`, and `3.4.2.1`, and `live = ["0.2.0"]` is a line too. Every line of a target has the same number of parts (`model-releases-line`), each line is in one list, and planned lines are newer than every live line and archived lines older (`model-releases-order`); a version with fewer parts than the lines starts none, and is in whichever lines follow it by order. The current line isn't written down anywhere, and planned isn't a lifecycle state: a mark for a planned version reads "planned" in every output, as decisions [#496a](496a-json-availability-targets.md) and [#496b](496b-planned-attribute.md) say, and stops when the line moves to `live`, with no edit to a page. A feature key, such as `next`, stays the way to mark work not released yet. Against the list, a version newer than every line is an error, `available-version-ahead`, with a fix to the newest line; one between two declared lines and in neither is advice, `available-line-undeclared`, with a fix to each line beside it, declaring it or correcting the number; one older than every line is before the window and reports nothing, so a project needn't declare its old releases; and a live line whose day in `ends` has passed is advice, `release-line-ended`, by `ASCRIBE_TODAY` when it's set. An archived entry without a `url` declares a line that's readable nowhere, and a `url` can be any address, a site Ascribe didn't build included, so a product's major rewrite is a new set of lines and not a version of its own. A phrase can be a target's line, `version = { line = "ascribe" }` (`model-phrase-line` when the target has no live line): the current line, and in a line's own output that line; no phrase is reserved. `numeric` stays the only version scheme, and Ascribe sets no limit on how many lines are live. `[versions] current` is gone, as [decision #494](494-versions-current-removed.md) says. _Why:_ versions belong to a target, so the list does; a current or a planned version written down beside the list is a second home that drifts from it, and "not released yet" kept by hand was a step after every release; an author writing about unreleased work often doesn't know its number. _From:_ the maintainer, on the [versions plan](https://github.com/ascribed-dev/ascribe/blob/395fe80d/project-docs/versions/README.md), decisions 1 to 6, 18, 19, 22, 23, 25, 26, and 27's label, 10 to 15 October 2026 (25 to 27 on [#494](https://github.com/ascribed-dev/ascribe/issues/494#issuecomment-6195368949)), built in its phase 3, [#505](https://github.com/ascribed-dev/ascribe/pull/505); recorded when the plan closed, with [#502](https://github.com/ascribed-dev/ascribe/issues/502).
