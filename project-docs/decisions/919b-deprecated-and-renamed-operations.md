section: The language
---

**A link to an operation the spec marks `deprecated` is advice, `link-operation-deprecated` (ASC276), and a link to an id the spec no longer has gets, as its first fix, the operation now at the method and path the id had, safe when it's the only one there and its id is new there.** Where the id was comes from an earlier reading of the spec, kept as the language server reads it again on a change, or from the review's base, the spec at the revision Review compares with; `ascribe check` has neither, so it offers the closest ids, unsafe, as before. An operation whose new id was somewhere else in the spec moved, and isn't offered as safe. The language server reads a declared spec again when the file watcher reports it, and watches a spec outside the folders the editor opened by its folder and name, as it watches `[from]`'s files. Go to definition opens the spec at the operation's method key, which the reader finds by reading the text's lines, since neither parser keeps positions. _Why:_ a regenerated spec renames operations, and the method and path are what's left to recognize one by, which only a reading from before the rename knows; a deprecated operation still works, so a link to one is worth knowing about, not an error. _From:_ [#919](https://github.com/ascribed-dev/ascribe/issues/919), [OpenAPI, phase 3](https://github.com/ascribed-dev/ascribe/blob/9162c25a/project-docs/openapi/phase-3-editor.md), 25 October 2026.
