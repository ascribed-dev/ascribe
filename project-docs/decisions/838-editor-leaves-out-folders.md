section: The binary
---

**The editor leaves out of its projects what git ignores, a list of folders named for output, dependencies, and caches, and a source's copies.** In a workspace folder that's a git repository, an `ascribe.toml` that `git check-ignore` reports isn't a project; one git tracks is. Every folder named `.ascribe`, `node_modules`, `bower_components`, `vendor`, `.venv`, `venv`, `__pypackages__`, `target`, `dist`, `.output`, `.next`, `.nuxt`, `.svelte-kit`, `.astro`, `.turbo`, `.vercel`, `.netlify`, `.cache`, `coverage`, `.gradle`, `.vscode-test`, `.tox`, or `.nox` is left out whether or not git ignores it (`LEFT_OUT_FOLDERS` in `packages/vscode/src/projects.ts`), but not `build`, `out`, or `bin`. `sources/<name>/` in a project's folder is left out too. A workspace folder's own `ascribe.toml` is always a project, which is how one left out is brought back; `ascribe.projects.exclude` stays the way to leave out anything else. _Why:_ `cargo test` writes 17 projects into `target/tmp/`, and each was listed and started a server when a test run rewrote it; every repository with a build or dependency folder that holds an `ascribe.toml` meets the same thing first. VS Code's `findFiles` doesn't read ignore files, so the extension asks git. `build`, `out`, and `bin` are also folders people write in, and git's rules cover them where they're output. _From:_ the maintainer, 22 October 2026, in #838.
