section: The binary
---

**`ascribe build`'s text shows each error of its checks in full and counts the rest in one summary line that points to `ascribe check`, then prints one line per build.** The summary line is `checked 8 files in every build: 0 errors, 1 warning, 3 advice: ascribe check for each`, the command carrying the build's `--config` and `--build` as given, and `checked 8 files in every build: no problems` when the checks found nothing; there's no `reported on`, since a build always reports on every file it checks. Each build's line names the outputs it wrote, `built site: 6 pages, 2 assets (site, plain, json)`; outputs whose counts differ are listed apart, `; ` between them, and the stale files removed are added up across the outputs. `--format json` is still exactly `ascribe check --format json`'s, and the errors stop the build as before. `ascribe check`'s own summary line doesn't change. `@ascribed/astro` reads the new line to decide whether to log the report as a warning. _Why:_ a build should say what it built, and only say more about a problem when it blocks the build; the advice blocks and a line per output buried that. _From:_ [#954](https://github.com/ascribed-dev/ascribe/issues/954), from the clarity and noise review, with the technical writer's wording for the summary line in its comments, 26 October 2026.
