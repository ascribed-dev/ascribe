section: The binary
---

**`ascribe resolve go:<name>` shows a permalink's help, and its JSON is the entry as `_ascribe/help.json` writes it.** A page argument starting `go:` is a permalink's name, never a page path. The text is the entry's title, its summary when `text` doesn't start with it, its text, and "Read more: " with its address when it has one. `--format json` is one object: `schema_version` and `ascribe_version`, as every command's JSON has, then `version` (`help.json`'s format version, which the entry is in), `build`, `line` (as the file has it), `name`, then the entry's own keys, `title`, `summary`, `text`, `address`, and `source`, each meaning what it means in the file; its schema is `resolve-permalink.schema.json`. The entry comes from the function that writes the file, so the two can't disagree. A name the build doesn't publish exits `1`, naming the closest names it does; a retired one exits `1` with its reason, and where its address leads. Neither writes JSON. `ascribe_resolve` takes the same `page`, returning the same object, or the same message as an error. The rules `ascribe agents sync` writes for a project that declares a permalink say that a product's message can read what the docs will show with it. _Why:_ an agent writing a product's error message reads what the docs will show for a permalink before naming it, and a product team checks an entry without building the site. _From:_ the maintainer, 22 October 2026, in [the embedded help plan](https://github.com/ascribed-dev/ascribe/blob/0c2b6372/project-docs/embedded-help/README.md)'s decision 15, built in #884.
