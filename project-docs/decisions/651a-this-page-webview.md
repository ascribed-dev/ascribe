section: The binary
---

**This page is a webview view; Review, Pages, and Content model stay native trees.** It replaces the part of [decision #544a](544a-sidebar-views.md) that has the views native trees, for This page alone. The model stays `sidebar.ts`'s (`thisPageRoots`, `thisPageChildren`, `thisPageLook`), and the webview only draws what it builds: each section a `<details>` and `<summary>`, each row that opens something a button, and the rows of a label and a value a description list, with no ARIA tree roles. Its rows wrap, and only About starts open; which sections are open is the view's state (`setState`), the same for every page. It shows the page of the last active editor of a page, while that editor is open, so focus in the view, the preview, a panel, or an editor of no page leaves it on its page. Its webview is never kept alive while it's hidden (`retainContextWhenHidden`): the extension keeps the newest answer, and sends it when the webview says it's ready. The base it's built on is for the views that follow it: `packages/vscode/src/webview/`'s `view.ts`, `viewProtocol.ts`, `viewShell.ts`, and `views.css`, and `packages/vscode/src/ui/webviewView.ts` with `handshake.ts` beside it. Their rules: nothing is sent until the webview says it's ready, every ready gets the newest answer, answers carry a number that rises and the webview ignores one older than it drew, it posts what it drew and the tests wait for that, the content security policy allows the script by its nonce and the extension's stylesheet and font and nothing inline, text is set as text, a choice names an item of the newest answer by its key and the extension opens it, Escape gives the focus back to the page's editor, and the stylesheet uses `--vscode-*` variables alone, with no fallback, listed in `design/tokens.toml`'s `[emit]` so the color test reads it. _Why:_ a tree draws each row on one line and cuts it off, and what it cuts off is what an author needs to see; This page uses almost nothing else a tree gives, and what it does use is cheap to build again; Pages and Content model use dragging, revealing, file decorations, and menus, which a tree does well. _From:_ the maintainer, on the [This page as a webview proposal](../proposals/this-page-webview.md#settled) and [the editor's next views](../roadmap.md), 20 October 2026; built in [#651](https://github.com/ascribed-dev/ascribe/issues/651).
