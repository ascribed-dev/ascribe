section: The binary
---

**Apply Every Safe Fix and Format Every Page are one workspace edit each, which the language server makes for the whole project (`ascribe/projectEdit`) and the extension applies after asking with its counts, leaving the files unsaved.** Apply Every Safe Fix reaches the editor's build: it takes, in every source file, the safe fixes "Apply the safe fixes in this page" takes in one, from the problems last published for it, settled by `ascribe_check::fix::Settled` as `ascribe check --fix` settles them, and its caption says they're the editor build's; every build's fixes stay `ascribe check --fix`'s, as [decision #544e](544e-fix-all.md) has it. Format Every Page formats every source file with `ascribe_fmt::format`, the code `ascribe fmt` runs. The server answers once the diagnostics queued before the request are published, so the fixes are those of the text it edits; each open document's edit names the version it's for, and the extension applies nothing when one changed after the edit was made. The question names the counts, "Apply 6 safe fixes in 4 files? They're left unsaved, to read before you save them.", and both are in the Command Palette too. _Why:_ the language server knows the editor build's problems, and a fix only every build can tell is one the editor doesn't show; a workspace edit is what the editor already makes for one page, so it can be undone and edits an open file's unsaved text, never the disk under it; and on a large project it can be hundreds of files, so they're left to read before they're saved, and the count comes first. _From:_ the maintainer, on [the Project view proposal](../proposals/project-view.md#actions) and decision 2 of [the editor's next views](../roadmap.md#decisions), 20 October 2026; built in [#656](https://github.com/ascribed-dev/ascribe/issues/656).
