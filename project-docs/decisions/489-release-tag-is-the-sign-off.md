section: Process
---

**Pushing a release's `v*` tag is its sign-off: the release workflow's publishing jobs wait for no approval, and the GitHub release is published, not drafted.** The `release` environment, which npm's trusted publishing, the Marketplace's managed identity, and `HOMEBREW_TAP_TOKEN` trust, has no required reviewer and runs only from a `v*` tag; the tag ruleset `Release tags` lets only a repository admin create, move, or delete one. A run started from the tag with `publish` checked goes from the build to npm, the Marketplace, the GitHub release, and the tap's pull request without stopping. Merging the tap's pull request is still the maintainer's ([decision #463b](463b-homebrew-tap-pull-request.md)). This replaces the "approved" in decision 18's "Releases stay manual and approved". _Why:_ the four approvals, one per job, and the draft to publish by hand before the last, guarded only against someone with write access pushing a tag, which the ruleset stops for any account or app that isn't an admin; by the time the draft could be reviewed, npm and the Marketplace were already public. _From:_ the maintainer, 14 October 2026, while releasing 0.3.1.
