section: The language
---

**A project's order is `ascribe.nav`, beside `ascribe.toml`, and what it leaves out has a default order (SPEC §7.8).** The file is TOML: `version = 1`, and a `[[sections]]` table for each section it lists, with `folder` (a path from the content root ending in `/`, `""` for the root), `pages` (file names in that folder, in order, which may name the page beside a nested folder to place that subsection), and `label`, and nothing else. A section is a folder with a page at any depth, fragments and `_` folders left out; its own page is its `index.md`, or else the page beside the folder with its name, which is also one of the parent's pages. The default order is the sections in path order, the root first, and in each its own page, then its pages by type in `ascribe.toml`'s order, then by title; a nested section whose own page is beside its folder sits where that page sits, and one with an `index.md` comes after the parent's pages. The file's sections come first among their siblings, in its order, and a section's listed pages first, the rest by title. A section's label is its `label`, else its own page's title, else its folder's name capitalized, and the root's is "Start". Each build shows its share: the pages it publishes and offers, and the sections left with one. A file that doesn't read is `nav-invalid`, and the project has the default order; a `folder` or a `pages` entry that names nothing is passed over until the checks report it. _Why:_ one order, written once in the project, for every sidebar and table of contents, in place of a list kept in each site's code that fails its build whenever a page is added; the default is the order Ascribe's own site keeps by hand. _From:_ the maintainer, on the navigation plan ([README](https://github.com/ascribed-dev/ascribe/blob/395fe80d/project-docs/navigation/README.md), decisions 1 to 13 and 24), 12 and 16 October 2026; recorded with [#537](https://github.com/ascribed-dev/ascribe/issues/537).
