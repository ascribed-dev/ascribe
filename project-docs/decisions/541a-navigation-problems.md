section: The language
---

**What `ascribe.nav` names wrongly is an error where it's written, and what it leaves out is advice with a safe fix.** A file that can't be read as SPEC §7.8 gives it is `nav-invalid` (ASC230, `write`), and the project has the default order. In a file that reads, each error is at the value, and what it names wrongly is passed over until it's fixed: `nav-page-unknown` (ASC231, `choose`), a `pages` entry that isn't a page in its section's folder, has a `/`, or names the section's `index.md`, and `nav-folder-unknown` (ASC232, `choose`), a `folder` that isn't a section, each with an unsafe fix to the closest name; and `nav-duplicate` (ASC233, `fix`), a folder listed twice or a page named twice in one section's `pages`, at the second, with a safe fix that removes it, the first counting. A folder with both an `index.md` and a page beside it with its name is `section-page-both` (ASC234, `choose`), on the `index.md`, naming the page beside the folder; until it's fixed, the `index.md` is the section's own page. The advice is `nav-page-unplaced` (ASC235), reported on a page its section's `pages` doesn't name, and `nav-section-unplaced` (ASC236), reported on a section's first page when the file lists one of its siblings and not it; a section with no `pages`, a section's own page, and a parent none of whose sections the file lists report nothing. Both are `fix`, and their safe fix edits `ascribe.nav`, appending every page or section left out, in the order each comes in now, so the navigation reads the same after `ascribe check --fix` and the file keeps its comments and layout. Both, and `nav-label-long`, are configurable in `[checks]`. _Why:_ a misspelled name that does nothing and says nothing is the one silent mistake the file would otherwise allow; a page beside its folder is how a long page is split (decision [#394](394-long-pages-split.md)), so the `index.md` is the one that came second whatever the paths' order says; and the advice is on the page, where an agent that wrote it sees it, while a section the file never orders already has the default order and nothing to fix. _From:_ the maintainer, on the navigation plan ([README](../navigation/README.md), decisions 2, 7, and 21, and [phase 1](../navigation/phase-1-decisions.md), decision 4), 12 and 16 October 2026; built in [#577](https://github.com/ascribed-dev/ascribe/pull/577), which narrowed `nav-section-unplaced` to a section whose siblings the file lists, 17 October 2026; recorded when the plan closed, with [#541](https://github.com/ascribed-dev/ascribe/issues/541).
