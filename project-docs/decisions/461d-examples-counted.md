section: The binary
---

**`ascribe report`'s `inventory.examples` counts `@snippet` lines, and `ascribe model` says a source's examples only when it has an `ascribe.examples.toml`.** The report counts each `@snippet` line that shows one of a source's examples, in pages and fragments alike, once whatever includes it, by the status the JSON output gives that snippet, for each source with a config, in the content model's order. For a source in another repository, the config and the observations are the copies `ascribe sources fetch` puts in its folder ([#460a](460a-fetched-examples-files.md)), so its examples are counted from them as its pages show them. `ascribe model` adds `examples` to such a source: whether its config can be read, how many of the files the source makes readable it makes examples, and each observation that can be read, with its environment, its tested line, how many files it lists, and how many of those are as it found them. For a source in another repository, an observation's files are counted only where there's a copy, since the others were never copied. _Why:_ a project with no config must see no change in any output ([README rule](../tested-examples/README.md)), so a source without one says nothing rather than "no config"; counting lines, not rendered blocks, gives the same count in every build. How many of an observation's files are as it found them is what says, after one environment is run again, that the other one is behind. Counting every source keeps the report's counts equal to what the pages show once a source in another repository has a status. _From:_ the implementation of [issue #461](https://github.com/ascribed-dev/ascribe/issues/461), following [phase 4](../tested-examples/phase-4-status.md), for Kyle's review in its pull request, 13 and 14 October 2026.
