section: The binary
---

**The Ascribe sidebar's views are, in order: Project, Review while review is on, This page, Pages, and Content model; Project is a webview view on This page's base, shown while `ascribe.active`.** It replaces the order in [decision #544a](544a-sidebar-views.md), which had Review first and no Project view; the rest of that decision stands. Project shows the sidebar's project, the one Pages and Content model show (`SidebarViews.project`), so it follows the active file and keeps its project when the active file belongs to none, and a click in it never moves it. Its counts are shown as current only while they are: the problems in every build are current while Check Every Build's `isCurrent` holds, and a check goes out of date on a change to any file of the project, not only those under the content root: `ascribe.toml`, `ascribe.nav`, `ascribe.permalinks`, `ascribe.lock`, the memos, and the templates, saved or not, and any file in a source's folder. Only a nested project's files, and those in the output directory, the project's `.ascribe` folder, `node_modules`, or `.git`, don't count. Switch Project stays where decision #544a puts it until the Project view's title bar takes it, in the roadmap's V5. _Why:_ the view is about the whole project, so it heads the sidebar, above the views about a change, a page, and a list; and a count from a check that a changed `ascribe.nav` or permalinks list has overtaken, shown as current, misleads more than a dash does, so the rule errs toward out of date: a change the check doesn't read costs a check. _From:_ the maintainer, on [the Project view proposal](https://github.com/ascribed-dev/ascribe/blob/62bf76a9/project-docs/proposals/project-view.md#what-changes-besides-the-code) and [the editor's next views](https://github.com/ascribed-dev/ascribe/blob/62bf76a9/project-docs/roadmap.md), 20 October 2026; built in [#654](https://github.com/ascribed-dev/ascribe/issues/654).
