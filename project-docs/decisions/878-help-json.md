section: The language
---

**Every build's site output holds `_ascribe/help.json`, each permalink's section for a product to show (output-layout contract §1.7).** Version 1 has `version`, `build`, `line` (absent for a build that isn't versioned, and for a versioned build with one live line, which writes what it would unversioned), and `help`, keyed by name: each permalink the build publishes, and each alias under its own name with its target's entry, resolved by the code `permalinks.json` uses; a retired permalink has none. Each entry has `title` (plain text), `summary` (the section's first block of content when it's a paragraph, past `@id` and `@available`; a page's description, else its opening's first paragraph; absent otherwise), `text` (the section as the plain renderer writes it, images as their alt text), `address` (absent without `[consumer] site`), and `source`. A heading's section runs to the next heading at its level or above, or the end of its container; a page's is its opening. The text is rendered from the section's blocks by the plain output's own block loop, and a test holds every entry of every project in the repository to its page's plain output. _Why:_ a product shows the docs' own words, for its release line, where its user is, by the name it already links to, and a section rendered by the same code can't read differently from its page. _From:_ the maintainer, 22 October 2026, settling the [embedded help proposal](../proposals/embedded-help.md)'s questions, and [the plan](../embedded-help/README.md)'s decisions 1 to 13, built in #878.
