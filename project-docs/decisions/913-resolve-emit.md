section: The binary
---

**`ascribe resolve` takes `--emit <plain|site>`, one output, `plain` by default, and its JSON says which with `emit`.** `--emit site` writes the page as `ascribe build --emit site` writes its file: resolved for the build and written through `emit_page` with the build's `SiteEmitter`, the code the build and the preview use, without source anchors, its assets named where a build would put them and none copied. `--frontmatter` under `--emit site` writes the site output's frontmatter block, with its reserved keys (`type`, `formatted`, `available` as targets, `source`); without it, the block is left off and the body written alone. A line of a versioned build (`--build site@3.4`) writes the line's links, under its base path. `--emit` is `ascribe build`'s word with the same values, but one output, not a list: a list, or any other value, is clap's usage error naming the values, exit `2`. `--emit` with `go:<name>`, either value, is a usage error, exit `2`, since a permalink's help has one form, `help.json`'s; `--emit` is absent unless given, so the default doesn't trip it. `resolve.schema.json` gains `emit`, `"plain"` or `"site"`, in every page answer, and stays at `schema_version` 1 (decision 4); `text` is the page as the output named writes it. `resolve-permalink.schema.json` doesn't change. _Why:_ an agent, a reviewer, or a test of a site's integration sees what the site output gives a site for one page without building the project, and `emit` is an enum so a later `json` is a value added, not a new field. _From:_ the maintainer, 24 October 2026, in [the proposal](../proposals/resolve-emit.md)'s Settled 1 to 3 and [the plan](../resolve-emit/README.md)'s decisions 1 to 3, built in #913.
