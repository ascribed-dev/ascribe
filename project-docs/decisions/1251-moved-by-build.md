---
section: The language
---

**A `[moved]` key that only some builds published is written in a table of its build, `[moved.<build>]`, and only the builds declared with that name serve it.** A build serves `[moved]`'s own keys and its table's, and no other build's; each build of a line reads its build's table, so `site@3.5` reads `[moved.site]`. `ascribe versions retire` writes each address it records into the table of the build whose line published it. A key whose value is a table is a build's name, since every source key's value is a string; a table naming a build `ascribe.toml` doesn't declare is `addresses-build-unknown`, an error, and a key in a build's table and in `[moved]` or `[retired]` is twice. A build's table holds no permalink: every build answers to one. The check accounts for an address with `[moved]` and its own build's table. SPEC §7.10 says so. _Why:_ a `[moved]` key starting with `/` applied to every build, so retiring quill's 3.4 line gave `cloud`, which never published `/3.4/`, redirects for it. Leaving out the keys a build never published was turned down: once a line is retired, nothing in `ascribe.toml` says `/3.4/` was its folder, and two builds can share a base path, as quill's do, so the file alone can't decide it. _From:_ the maintainer, in [issue #1251](https://github.com/ascribed-dev/ascribe/issues/1251), 3 November 2026.
