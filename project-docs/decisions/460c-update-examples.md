section: The binary
---

**`ascribe sources update` lists, for each source, the tested examples snippets use whose status the new pin changed, as `examples` in its JSON: each with `path`, `status`, and `was` (`current`, `stale`, or `unobserved`; `was` null when the file wasn't an example, or had no copy).** Both statuses are read from the copies, before and after the update copies again, and an example whose status didn't change isn't listed. The text and the Markdown say the same, with one line in the Markdown saying the pages show no tested line until `ascribe observe` passes in the code's repository. For these sources, `example-stale` and `example-unobserved` take the message variant `other-repository`, which names the source and says the fix arrives with the next `ascribe sources update`. _Why:_ phase 3's summary gains the examples that went stale, lost their observation, or became current, and a `was` lets a script tell "became current" from "gained one" without a fourth status. The variant's name avoids `remote`, which `crates/ascribe-cli/tests/all/network.rs` reads as a `git` command that reaches another repository. _From:_ the implementation of [issue #460](https://github.com/ascribed-dev/ascribe/issues/460), for Kyle's review in its pull request, 13 October 2026.
