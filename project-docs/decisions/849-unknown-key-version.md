section: The language
---

**An unknown key's message names the Ascribe that read it, and says the project may need a newer one.** `model-unknown-key`'s message, with or without a suggestion, ends "this is ascribe {version}, and the project may need a newer one", where `{version}` is the binary's version, as Cargo has it; the variants for keys that were removed (a type's `files` and `default`, `[glossary] terms`, `[[intended]] term`) don't, since they say where the setting went. A command or MCP tool that stops because `ascribe.toml` has errors quotes the first unknown key's message after "`ascribe check` lists them". The conformance case `model/unknown-key-newer` pins the diagnostic, and the message is tested in `crates/ascribe-cli/tests/all/mcp.rs`, since cases name diagnostics by slug, never by message. _Why:_ the Claude plugin's MCP server ran an older `ascribe` from Homebrew on a project with keys added since, and every tool answered only that `ascribe.toml` has errors, with nothing to say the binary was older than the project. Whether a later registry knows a key can't be told from this one, so the note goes on every unknown key. _From:_ the maintainer, 22 October 2026, in #849.
