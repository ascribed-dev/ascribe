section: The binary
---

**`ascribe addresses init`, `move`, `retire`, and `list` keep `ascribe.addresses`; `ascribe check` compares with the base when the file exists, taking `--base` and `--base-exact` as `ascribe diff` does; and a move made by `ascribe rename` or the editor records itself.** `init` leaves a file already there alone; `move` and `retire` record a move or a removal made another way, refusing a source that's still a file; `list` shows what each build's `redirects.json` has, with `--build` for one. Their JSON is `AddressesInitReport`, `AddressesRecordReport` (for `move` and `retire`), and `AddressesListReport`, each at `schema_version` 1. The check reads the base on a thread beside the rest, only for a whole-project check from the command line or the MCP tool, never for a page or files named, the editor, or the agents' hook. `refactor::will_rename` adds the entry to the same edit as the links when the file exists, so the command and the editor's moves both record; a fragment's move records nothing, since its ids' addresses don't move. _Why:_ a decision recorded where the move is made is one nobody has to remember, and a check that compares the whole project against a base is what CI runs (decision #904). _From:_ [#905](https://github.com/ascribed-dev/ascribe/issues/905), [redirects, phase 1](../redirects/phase-1-thread.md), tasks 4 to 6, 25 October 2026.
