section: The binary
---

**This page says what Ascribe knows about the active page, and is answered by one request, `ascribe/page`, which takes the page and the cursor.** It has sections: About, then Review while review is on, Health, Connections, and Memos. The heading at the cursor is the innermost heading with an id whose section holds the cursor, and Connections narrows to it. The server keeps the part that doesn't depend on the cursor for the file until the snapshot, the day, or a watched file changes, so a cursor move on the same page picks only the heading's share, asks one request, and costs no more than Used by's two requests did; `cargo bench -p ascribe-lsp --bench page` measures it. The view asks only while it's showing. The problems are VS Code's diagnostics, and the Review section is what the review already has, so a cursor move asks `ascribe/page` alone. Each row is decided by the code that decides the same fact for a check or an output (`description-too-long`'s measure, `review-overdue`'s comparison, `Project::dropped`, `pages.json`'s listing, `page-size`'s measure, the template's places, a snippet's example status), and a row warns only where its check reports the page; `crates/ascribe-cli/tests/all/page_parity.rs` compares the rows with `ascribe check`'s JSON and `pages.json`. `ascribe/page`'s result is a type the extension generates from the server's through `crates/ascribe-cli/src/shapes.rs`, and the two change together; it isn't a contract. _Why:_ it's the one view about where the author is, and memos need a home; one request in place of Used by's two, answered from what's kept, keeps a cursor move cheap while the view says more; a row that disagreed with `ascribe check` or a build would be a second answer to the same question. _From:_ the maintainer, on the editor's views plan ([README](../editor-ui/README.md), decisions 3 and 11) and its [proposal](../proposals/editor-ui.md#settled), settled 16 October 2026; the heading's section and the rows' parity from [#550](https://github.com/ascribed-dev/ascribe/pull/550), [#568](https://github.com/ascribed-dev/ascribe/pull/568), and [#572](https://github.com/ascribed-dev/ascribe/pull/572), 16 and 17 October 2026; recorded when the plan closed, with [#544](https://github.com/ascribed-dev/ascribe/issues/544).
