section: The binary
---

**`ascribe render` is renamed `ascribe resolve`, its MCP tool `ascribe_render` is renamed `ascribe_resolve`, and its JSON document's schema is `schemas/resolve.schema.json`, with no alias for the old names.** The command keeps its arguments, options, exit codes, and output, and the document keeps `schema_version` `1` and every field; only the names change, in the contracts of decisions 52 and 56. The command reference's `cli-render` permalink is retired, leading to `cli-resolve`. The command does SPEC §9.1's two middle stages for one page: it resolves the page for one build (§9.2), then writes it with the plain emitter, as `ascribe build --emit plain` would. _Why:_ the command doesn't render: it writes plain Markdown, and inside the codebase "render" means HTML (`render_site_html`, the preview, and AGENTS.md's "Two renderers must agree"), so the name promised something visual, as the [docs audit](../docs-audit.md) read it. The name was never weighed: the agents plan took it from the code it calls. Ascribe is before 1.0, so a project changes with it rather than carrying an alias. The brainstorm's section 22 keeps what the rename leaves room for: `--emit site`, and HTML. _From:_ the maintainer, who chose `resolve` over keeping `render` and adding HTML or folding the command into `ascribe build`, in [#665](https://github.com/ascribed-dev/ascribe/issues/665), 20 October 2026.
