section: The binary
---

**`ascribe versions release` removes or rewrites the marks for the target that name a version in the line it archives, as `available-same-in-every-line`'s fix does, and its JSON gains `cleared` and `cleared_features`.** Only where the release archives the old current line, which is where no build is versioned by the target. A mark is cleared when the check reports it once the line is archived and one of its entries for the target names a version in that line; a mark that said nothing before the release is left for `ascribe check`. Each fix is the check's own, taken whatever its applicability, since a badge build's badge is what the mark said and the release's output changes list the pages it's gone from. `cleared` lists each file with each mark's line, its entry as written, and the entry as rewritten, or null when the mark is removed; `cleared_features` each feature as `features` does elsewhere. The schema version stays 2, since no field is removed or changes meaning. _Why:_ every release turned the old line's marks into advice that `--deny-warnings` doesn't fail on and no step removed: 61 `ascribe 0.4.0` marks after 0.4.1, found later in the editor's Problems panel. _From:_ the maintainer, 22 October 2026, in #847.
