**The element library's script adds a copy button to each code block, element contract §12: a `<button class="ascribe-copy">` after the block's `<pre>`, outside it and its `<code>`, with no text of its own, that copies the `<code>`'s text and says "Copied" in a live region.** The site output doesn't change, and neither do the plain and agent Markdown outputs: the button is the script's, so with scripts off there's none and the page reads as it did. Its words, its name, and what the live region says are the stylesheet's generated content, so a site translates them once; `--ascribe-copy-display: none` leaves it out, and four color properties restyle it. The button isn't wrapped around the block with the `<pre>`: a wrapper would break a site's selectors such as `figure > pre`, so the button is the `<pre>`'s next sibling, and CSS anchor positioning, with an anchor name the script gives each block, puts it in the block's corner. _Why:_ readers of command-heavy docs expect one, and every Ascribe site gets it without work; it's additive, so no site breaks. Outside the `<pre>` and with no text of its own, the button never reaches what an HTML-to-text converter reads ([#1038](https://github.com/ascribed-dev/ascribe/issues/1038)), nor the copied code. _From:_ Kyle, on [issue #1011](https://github.com/ascribed-dev/ascribe/issues/1011#issuecomment-6418239507), 26 October 2026.
