section: The language
---

**`summary-missing` and `summary-long` are off unless a project names them in `[checks]`: the registry marks them `off-by-default = true`, and naming one with a level turns it on at that level, while a table without one, such as `[checks.summary-long] limit = 200`, turns it on at its registry severity, advice.** A project that ships `help.json` turns them on with `[checks] summary-missing = "warning"` (or `"advice"`); one that uses permalinks only for links that last hears nothing about summaries. The opt-in is the check's own key, not another signal such as a `[permalinks]` key, so one setting says both that the check runs and how loudly. `off-by-default` is a registry field any configurable check can have, `Checks::is_off` counts it, and the diagnostics reference marks such a check "off by default". The agents' skill says to write summaries only when `[checks]` turns `summary-missing` on. _Why:_ the check fired on every permalinked heading, so a team that uses permalinks for stable links got advice about a feature it doesn't use, as the first thing `check`, `build`, and the editor showed it, in `examples/quill` among them; and the check's own help already told a project that ships embedded help to raise it, so for those projects the default added nothing. _From:_ [#949](https://github.com/ascribed-dev/ascribe/issues/949), the clarity and noise review, 26 October 2026.
