section: The binary
---

**A project's baseline is `ascribe.baseline`, beside `ascribe.toml` and committed, kept by `ascribe baseline write` and `ascribe baseline prune`; `ascribe check` holds back the advice it lists, counts it, and reports an entry that matches nothing as the advice `baseline-entry-unmatched`.** The file is text: its first line is `# ascribe baseline 1`, naming the format and its version; a line that starts with `#` is a comment, a `#` anywhere else, as in a path, is text, and a blank line is ignored; an entry is `check fingerprint order file`, the four parts of a finding's identity (decision [#787](787-finding-identity.md)), separated by one space, the file last, the rest of the line after the third space, so a path with spaces needs no quoting, from the project's root with `/`. The commands write the lines sorted by file, then check, then fingerprint, then order, after the header and the comment `# Advice put off for now: ascribe baseline write adds, ascribe baseline prune removes.` and `# check fingerprint order file`, and write the whole file in that form, so `write` run twice gives the same bytes and a comment of the project's own isn't kept. A line that doesn't parse is an error naming it (`baseline_invalid`), and `check`, `write`, and `prune` exit with `2` on it; `check --no-baseline` neither reads the file nor holds anything back. **Only advice is held back:** an entry matches a finding of any severity, so one whose check a project has since raised to a warning or an error matches and doesn't hide it, and isn't stale. `write` adds every current advice to the entries the file has, and says how many errors and warnings it skipped and that the way to put one off is to lower its check to advice in `[checks]` and write again; `prune` removes the entries that match no finding of the whole project's check. Both run that check first, every build and Vale when `[checks.vale] in-check` says so, without the baseline, take `--format text|json`, and exit `0`, or `2` when they can't run; `prune` with no file writes nothing. `check` reports `baseline-entry-unmatched` (advice, configurable, area `project`) at the entry's line only when it checks the whole project for every build, since with paths, `--build`, or `--editor-build` it doesn't see every finding the file lists, and not for an entry of `prose` when Vale didn't run. The text summary adds `, N in the baseline`, and `check`'s JSON adds `summary.baselined`, left out when it's 0, at the same `schema_version` (decision 4). The baseline is the command line's for now: `ascribe build`, `ascribe report`, the language server, and the agents' hook and tools don't read it (#790). A malformed line has no conformance case: it stops the check rather than adding a diagnostic, and a diagnostic would need a SPEC §8.2 row for a file that isn't the language's, so the command's tests hold it. _Why:_ a team that turns on the advice checks in a large project wants to see only the advice it adds, and a committed, sorted list of findings puts the rest off where a reviewer can see what's put off. A warning is something a team has decided matters, so putting one off goes through a reviewed change to `[checks]`. A stale entry is reported so that a later finding with the same fingerprint isn't hidden by it. The file can't change once it ships, which is why its syntax is fixed here. _From:_ [#789](https://github.com/ascribed-dev/ascribe/issues/789), from the [cache proposal](https://github.com/ascribed-dev/ascribe/blob/bb56bfb3/project-docs/proposals/cache.md)'s "A baseline" and its Settled 2 and 3, decided by the maintainer on 20 October 2026; the syntax approved by the maintainer as proposed in the issue on 21 October 2026.
