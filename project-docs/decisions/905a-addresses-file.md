section: The language
---

**`ascribe.addresses` is SPEC §7.10, beside the permalinks list: a project that commits it has the addresses a base published compared with what it publishes now, build by build, and an address nothing accounts for is reported once per source, at the file.** An address is a page's route, its Markdown version's, and each explicit `@id`'s `route#id`; a generated id isn't one. It's accounted for by a `[moved]` entry for its source, or for the address, whose value is a page a build publishes now; by a `[retired]` entry; or by an availability mark that takes its page out of one build while another publishes it. An id is compared only while its page is at the same address. SPEC §8.2 gains four rows under "Addresses file": `addresses-file-invalid` (ASC254, error), `address-lost` (ASC255, warning), `anchor-lost` (ASC256, advice), and `addresses-build-gone` (ASC258, advice). `addresses-base-unreadable` (ASC257, a warning, configurable, area `project`) isn't a row, since a base is a repository's and not the language's; for a base with no project it's advice, since nothing was compared. Each is located at `ascribe.addresses`. The section is §7.10 rather than §7.6, so no section after §7.5 moves. _Why:_ the file is the record the redirects plan builds on, and a rule a second implementation must follow belongs in SPEC; reporting at the file, once per source, is the plan's decisions 6 and 7. _From:_ [#905](https://github.com/ascribed-dev/ascribe/issues/905), [redirects, phase 1](../redirects/phase-1-thread.md), task 9, on [decision #904](904-redirects-formats.md), 25 October 2026.
