section: The language
---

**Each of a glossary's problems has the next step that fixes it, and a definition is held to the limit a page's description is.** The codes, and where each is reported, are [decision #545a](545a-glossary-pages.md)'s and [decision #546a](546a-glossary-page-rules.md)'s. A `[glossary] terms` table is `model-unknown-key`, which keeps the next step it has for any key, `choose`. `model-glossary-page` (ASC238) and `term-off-glossary-page` (ASC242) are errors whose next step is `choose`, since which pages are the glossary is the project's to decide; `glossary-term-duplicate` (ASC239) and `glossary-definition-missing` (ASC240) are errors, and `glossary-definition-long` (ASC241) is advice, all three `write`. `model-glossary-page` reports a fragment, and a path that differs from the file's name only in case, with wordings of their own. The four about terms, ASC239 to ASC242, are checked with the project, not by the loader, since terms are read from pages. `DESCRIPTION_LIMIT`, 300 characters, in `crates/ascribe-resolve/src/llms.rs`, is the one limit for both `glossary-definition-long` and `description-too-long`, and a setting that changes it, if a project asks for one, is added to both at once. _Why:_ a definition and a description are each a sentence or two shown where there's no room for more, so one number serves both, and a plan about the glossary wasn't the place to change the description's check. _From:_ the maintainer, on the glossary pages plan ([README](https://github.com/ascribed-dev/ascribe/blob/395fe80d/project-docs/glossary-pages/README.md) decisions 9 and 19; [phase 1](https://github.com/ascribed-dev/ascribe/blob/395fe80d/project-docs/glossary-pages/phase-1-decisions.md) decision 5), 15 October 2026; recorded when the plan closed, with [#548](https://github.com/ascribed-dev/ascribe/issues/548).
