section: Process
---

**A new diagnostic's code is reserved on its issue by triage, when it moves the card to Ready, and the pull request uses only those codes.** Triage writes `Reserved codes: ASCnnn–ASCmmm` in a comment on the issue, picking the codes after the highest in `crates/ascribe-core/data/diagnostics.toml` and in any issue's reservation, and one or two more than it counts when it's unsure. A reserved code that goes unused stays unused, as a decision number does, and the registry's codes may have gaps: they go up in file order, and that's all a test asks of them. A card that needs more codes asks on the issue, and triage reserves more; it doesn't take the next free number. Merging `main` keeps both branches' entries, sorted by code. AGENTS.md, and the `triage` and `implement` skills, say so. _Why:_ two branches cut from the same `main` each took the next code by hand, so whoever merged second renumbered, regenerated the reference and `project-docs/surface.md`, and went back through review; October had four such merges. Triage runs one at a time, hourly, so two reservations can't race. A branch adding a diagnostic by slug, with a code assigned at merge, was turned down: it needs automation that commits to `main` after a merge or rewrites a branch inside one, and reviewers merge from GitHub. _From:_ the maintainer, in [issue #982](https://github.com/ascribed-dev/ascribe/issues/982), 26 October 2026.
