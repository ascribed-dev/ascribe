---
section: The language
---

**The site emitter writes an element with nothing inside, such as an empty widget, as its opening tag on one line and its closing tag on the next.** A custom element's two tags on one line aren't an HTML block to CommonMark: a custom name isn't one of kind 6's, and kind 7 needs the opening tag alone on its line, so every CommonMark renderer, ours and Astro's, read the line as inline HTML and wrapped it in a paragraph. On two lines the opening tag starts a kind 7 block, so the element renders alone, after its heading, in a list item, or where its directive was. The element contract's §0 and §6 and the site-render contract's §5 say so, the site-render fixture [`widget-empty`](../../tests/render/widget-empty/input.md) pins it for both renderers, and the anchor fixtures follow it: an empty widget that binds itself carries its anchor on its own tag, as every other element does, instead of a comment for the paragraph it used to be in. The attribute marker stays on one line, since it's inline by design. The site's stylesheet no longer hides a stray paragraph after each pillar's heading. _Why:_ the contract promised a block, and a paragraph around an empty widget is markup a site has to work around in its CSS; keeping the promise removes the workaround instead of documenting it. _From:_ [#818](https://github.com/ascribed-dev/ascribe/issues/818), option 1, chosen by the maintainer on 22 October 2026.
