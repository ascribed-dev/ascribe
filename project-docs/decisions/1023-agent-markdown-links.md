section: The binary
---

**In the Markdown a build publishes for agents (`[consumer] agents`), a link to a page the build publishes leads to that page's `.md`, with a fragment that lands on the same heading there.** A link written to `editor/agents.md#agents-in-vs-code` becomes `https://ascribed-dev.com/docs/editor/agents.md#agents-in-vs-code`, and a glossary link leads to the glossary's `.md`. The fragment is the anchor a Markdown reader gives the heading in the `.md`: the `github` slug of its text as the `.md` writes it, numbered across the page. That's the page id, except for a heading with an `@id` or one in a variant arm, whose `.md` heading ends with the arm's label, so the fragment is the `.md`'s own anchor for the heading the page id names. A link out of a line, a link to an operation, `_ascribe/help.json`'s sections, and the `plain` output without agents (`ascribe build --emit plain`, `ascribe resolve`) keep HTML addresses. _Why:_ `llms.txt` already sends agents to the `.md` versions, and a link that drops them back into HTML on the first hop works against that; most fetchers don't send `Accept: text/markdown`, so content negotiation doesn't bring them back. The HTML address stays canonical through the page records and the `.md`'s `Link` header, and the `.md` doesn't claim otherwise. _From:_ the maintainer, on [#1023](https://github.com/ascribed-dev/ascribe/issues/1023#issuecomment-6418262718), from the agent-reader review's finding F2, 26 October 2026.
