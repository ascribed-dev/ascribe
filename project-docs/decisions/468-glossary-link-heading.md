~~**A glossary term's `link` that names a heading its page doesn't have is an error, `glossary-link-target-missing`.**~~ Replaced by [decision #545a](545a-glossary-pages.md): a term is a heading on a glossary page, and has no `link`. A new SPEC §8.2 row, "Glossary | A term's `link` that names a heading its page doesn't have", with the code ASC203: an error at file level, next step `choose`, not configurable, reported at the `link` value in `ascribe.toml`. SPEC §5.4 says the id is a heading's source id on the page, written in it or in a fragment it includes, which is what the build links to. It's checked with the project, for every build, as `permalink-retired-target-missing` is, since ids depend on parsing; the loader's `model-glossary-link` still checks only that the page is there and isn't a fragment. And `ascribe rename` of a heading's id, and `F2` in the editor, change a glossary term's `link` and a retired permalink's `to` that name it, as they change links in pages. _Why:_ renaming a heading by hand, or before the rename followed `ascribe.toml`, left a term that was never linked, with nothing saying so, while a retired permalink with the same problem was already an error. _From:_ triage of [issue #468](https://github.com/ascribed-dev/ascribe/issues/468), on the question the issue left open, 14 October 2026.
