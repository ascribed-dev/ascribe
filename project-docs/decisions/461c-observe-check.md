section: The binary
---

**`ascribe observe --check` writes the same JSON document as a run, with `check` true, no `test`, `current`, and `changes`; a run's JSON gains `changes` too.** `test` is absent with `--check`, since nothing ran, and present on every run as before. `current` says whether the observation lists every example in the folder with the hash it has now and nothing else; `changes` lists the files added, removed, and changed, and the environment values that differ, against the observation a run replaced, or the folder for `--check`, and is absent when there was no observation. `--check` exits 0 when it's current, 1 when it's stale or missing, and 2 when the config or the observation can't be read, and doesn't need a `test`. _Why:_ one schema for one command keeps `--format json` the same shape to a tool whichever it asked; `test` becoming optional changes the schema `ascribe observe` shipped in the same unreleased version, before any reader relied on it. _From:_ the implementation of [issue #461](https://github.com/ascribed-dev/ascribe/issues/461), following [phase 4](https://github.com/ascribed-dev/ascribe/blob/180eee83/project-docs/tested-examples/phase-4-status.md), for Kyle's review in its pull request, 13 October 2026.
