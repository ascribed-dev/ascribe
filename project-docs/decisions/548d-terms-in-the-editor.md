section: The binary
---

**In the editor a term is its heading: a term in prose goes to it, the heading answers for the term's uses, and `@term` is offered only where it makes a term; terms are no outline of their own.** Go to definition on a term in prose opens its heading on the glossary page. Find All References on the heading, or on its `@term`, lists the term's uses, as `ascribe refs term:<id>` does, and the links to the heading, each place once. Hover on a term in prose shows its definition for the editor's build; on its heading, the definition and how many pages use the term. Completion offers `@term` only at the top of a section on a glossary page, or in a fragment one includes, and not on a heading that's a term already, and inside its braces its attributes and `match`'s values. `glossary-definition-missing`'s quick fix, **Write a definition of** the term, puts a paragraph under the heading and its directives and selects it with the client command `ascribe.selectRange`; an editor that doesn't run the command still gets the edit. **Add a stable @id** is offered on a term's heading as on any, since the term's id is the heading's. Renaming the `@id`, with `F2` or `ascribe rename`, renames the term; rewording a heading with no `@id` changes the term's id too, and the server says so. **Add to the glossary** writes a section, the heading marked `@term` and the definition under it, at the end of the first page `[glossary] pages` lists, and the Content model view opens a term at its heading. The server answers no document symbols for terms: VS Code's Markdown extension lists every heading in a page's Outline and `Ctrl+T`, a term's among them. _Why:_ a term is written as a heading, so every way to reach or change it goes through the heading, and a document symbol provider in the server would add a second outline beside the Markdown extension's, since VS Code shows a tree for each provider. _From:_ the maintainer, on the glossary pages plan ([phase 4](https://github.com/ascribed-dev/ascribe/blob/395fe80d/project-docs/glossary-pages/phase-4-editor.md)'s design, after [README](https://github.com/ascribed-dev/ascribe/blob/395fe80d/project-docs/glossary-pages/README.md) decisions 1, 2, 6, and 17), 14 and 15 October 2026, built in [#593](https://github.com/ascribed-dev/ascribe/pull/593) and [#600](https://github.com/ascribed-dev/ascribe/pull/600) by 18 October 2026; recorded when the plan closed, with [#548](https://github.com/ascribed-dev/ascribe/issues/548).
