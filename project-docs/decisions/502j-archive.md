section: The binary
---

**An archive is a line rendered once more by Ascribe alone into a folder of plain HTML that needs nothing else: `ascribe versions archive "<target> <line>" --to <folder>` writes it, and `ascribe build` never does.** It's a fourth emitter, `archive`, written through the store given a root, the `--to` folder, which keeps its manifest there as `archive.manifest.json`, naming the line's build (`site@3.4`); the ownership rules and the asset contract apply as they are, a second run replaces only what the manifest lists, and a folder with anything in it besides `.lock` and no manifest is refused, `archive_folder_not_empty`. The store's `.lock` stays in the folder after a run. The archive doesn't go in git, Ascribe doesn't host it, and the command writes nothing into the project: it prints the `[releases]` entry to add once the folder is hosted, and the live site lists an archived line by its `url` ([decision #502c](502c-versions-file.md)). Each page carries a statement, "Documentation for Self-managed 3.4. This version is no longer maintained.", with a link to the current documentation given `--current`, and nothing that's a date or a "latest" that would read wrongly later; a sidebar on every page, from the line's navigation as [decision #539b](539b-navigation-in-model-and-json.md) says; previous and next; `noindex`, with a `robots.txt`; and a print stylesheet. A contents page and `all.html`, every page in one document for one PDF, are beside them. The stylesheet is the element library's with the archive's own, and tabs are labeled sections one after another, as the element contract promises without JavaScript. A link to a page of the line, or to the page that takes its place there, is relative; a link to another line's page, or to a route the line doesn't have, is written as its text and listed by the command; and a link with a scheme, to another site, stays a link, printed with its address. An archive runs one script, its search: `search.js`, built from `packages/archive` and carried in the binary, the same file in every archive one version of Ascribe writes, draws the box where the sidebar's `<script>` is, so with scripts off there's none and the archive reads whole. Its index is `search-index.js`, which sets `globalThis.ascribeArchiveIndex` to the index as JSON and is added to the page the first time the box is used, uncompressed; a query ranks a page's title, then a heading, then the text. The pages' content security policy is `script-src 'self' file:`: no inline script runs, and a `<script src>` in a page's own raw HTML runs when the browser can load its file. The command says the index's size, and past 8 MB that a reader's first search waits for it to load, and writes it whatever its size (`search_index_bytes` and `search_index_large` in its JSON). It checks the build of the line it archives, and no other, and refuses when the checks find an error, `archive_has_errors`; it refuses an archived line, `archive_line_archived`. A planned line is built as `<build>@<line>` from the current line's build and checked as that build, and the command says it's not released; archiving the current line works, and the text says it's unusual. The [archive contract](../../docs/content/contracts/archive.md) has the folder's layout. The plan's decisions 69 and 71, an archive with no script and `script-src 'none'`, gave way to its decision 76, stated here. _Why:_ an archive is read years after its line left, where a site generator, a server, or a script may not work, so it depends on nothing but its search, and reads whole without that; a page at a `file:` address can't fetch a file but can load a script, and `'self'` doesn't match a page opened from a disk in every browser; a writer of its own would repeat the store's asset copying and ownership rules; a broken page is worse in an archive kept for years than in a build that's rebuilt, and an archived line's source is no longer in the project to render; and an outside address in a page is content, as it was when the line was live. _From:_ the maintainer, on the [versions plan](https://github.com/ascribed-dev/ascribe/blob/395fe80d/project-docs/versions/README.md), decisions 15, 68, 70, and 72 to 77, 10 and 16 October 2026 (70 to 74 confirmed with [#519](https://github.com/ascribed-dev/ascribe/pull/519), and 75 to 77, recorded before code, built in [#521](https://github.com/ascribed-dev/ascribe/pull/521)); recorded when the plan closed, with [#502](https://github.com/ascribed-dev/ascribe/issues/502).
