section: The language
---

**A mark whose versions are all before the oldest live line of its target, with its last state available, is `available-same-in-every-line` advice in a build that shows it as a badge, with a message of its own and an unsafe fix.** A build that badges availability and isn't versioned shows the mark, as does one filtered for another target that publishes the content; there the badge says only that the content is older than every live line. A version in the oldest line isn't reported in a badge, though a line's output leaves it out: with one live line, `ascribe 0.4.0` says what came with the current release, and the docs audit keeps those marks. The message says the badge is shown and says nothing a reader of a live line needs; the fix, the mark without its versions, removes the badge, so it's `unsafe` (decision 51), and stays `safe` where no output shows the versions. A build filtered for the target at a version before the window still decides by the mark's versions, so with one the check stays quiet, and `available-in-no-line` stays quiet while any build publishes the content. A project that keeps such badges, as Python's docs keep "new in 0.2", turns the check off in `[checks]`. This narrows [decision #496c](496c-inert-marks.md), which kept both checks quiet while any build showed the mark. _Why:_ a badge build keeps "Ascribe 0.2.0" badges for as long as the source says so, and nothing pointed at them; Ascribe's own docs had 191 such marks. _From:_ [#667](https://github.com/ascribed-dev/ascribe/issues/667), from the [docs audit](../docs-audit.md), 20 October 2026.
