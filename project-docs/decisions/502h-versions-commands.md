section: The binary
---

**`ascribe versions list`, `changes`, and `release` show and move a project's lines: each names a line as a mark does, `"self-managed 3.4"`, takes `--format text|json`, and exits 2 when it can't do what it was asked.** `list` shows each target's lines, newest first, with each one's status, each live line's output, base path, and page count on each build versioned by the target, `ends`, and an archived line's `url` and `ended`; it builds nothing. `changes "<target> <from>" <to>` says what differs between two declared lines from the marks alone, with nothing built: the pages, sections, blocks, and rows added, removed, or changed in state. A line holds what's marked for a version in it and not what's marked for a later one, though the current line's output shows that, so two lines are compared as they were released, whichever is current. A page added in place of one removed, which `replaces` links it with either way, is one entry, listed as added, with `in_place_of`. `--format markdown` writes a first draft of release notes. `release "<target> <line>"` rewrites every mark that names a feature whose version is in the line to the line's spec, points each such feature at the following planned line, or at `--next`, which it adds to `planned` (it exits 2 when it needs one and has neither), and moves the line from `planned` to `live`, in an order that changes no output. It also takes a line nobody planned, newer than the current line and older than every planned one. When no build is versioned by the target, it moves the line that was current to `archived`, with no address: `{}`, or `{ ended = <date> }` when `ends` gave its last day, whose entry in `ends` goes; a one-site project keeps one live line. When a build is versioned by the target, the old line stays live, and `retire` is the way out ([decision #502k](502k-retire.md)). It builds the site and plain outputs in memory before and after, not the JSON output, refuses when rewriting the marks or archiving the old line would change them, and lists by build what the release itself changes. It writes only files git can put back, each tracked and unchanged, or refuses and names them; `--force` writes anyway, and is needed outside a repository; `--dry-run` needs neither. It refuses a line that's live or archived already, so a second run changes nothing. _Why:_ release day was a list moved by hand and a follow-up pull request that rewrote the marks, and missed or wrongly rewrote those merged after the tag; the JSON output records each mark as written and where, so it changes with every rewrite however right; a release that's one commit is one to read, and `git checkout` undoes it; and release notes shouldn't change when a planned feature lands. _From:_ the maintainer, on the [versions plan](https://github.com/ascribed-dev/ascribe/blob/395fe80d/project-docs/versions/README.md), decisions 14, 20, 31, 33, and 45 to 48, 10 to 15 October 2026 (31 and 33 on [#494](https://github.com/ascribed-dev/ascribe/issues/494#issuecomment-6195368949); 45 to 48 confirmed with [#510](https://github.com/ascribed-dev/ascribe/pull/510)), with `in_place_of` from [#513](https://github.com/ascribed-dev/ascribe/pull/513); recorded when the plan closed, with [#502](https://github.com/ascribed-dev/ascribe/issues/502).
