section: The binary
---

**An older line says what it is and points at the current one, to a search engine, a reader, and an agent: its pages' canonical address is in the current line, each line's outputs for agents name the line, and `[listing] older-lines` can keep the older lines out of every index.** A page in an older line has for canonical address the same page in the current line, or the page the current line has in its place, following `replaces` as a link does; a page the current line has neither of keeps its own. The sitemap lists a page when it's listed and its `canonical` is its own address, so each current page once and an older line's page only where it's the one place the page is; the page records gain no key, and nothing is added to `robots.txt`. `[listing] older-lines`, a key beside `default`, `folders`, and `types`, is a level between the site's `default` and a folder's or a type's rule that only an older line's pages are under, and a record names it as `listing_from.level = "older-lines"`; it restricts and never loosens, and governs search engines and agents together. A page looser than it is a diagnostic of its own, `listing-loosened-in-line`, an error at the page level, per build, with no fix offered, not `listing-loosened`, which is at the file level. Each line publishes its own outputs for agents. A page's Markdown opens with "> Documentation for Self-managed 3.4.", then "Support ends on 31 January 2027." when `ends` gives the day, and in an older line "The current version is 3.5: <address>.", the address the page's canonical address when that isn't its own, and the current line's home otherwise. A line's `llms.txt` is headed `# <name> (<label> <line>)`, and an older line's opens, after the summary, with "This is an older version. The current version is 3.5:" and a link to the current line's `llms.txt`; `ascribe agents index` heads a line's index with the same words. A build with one live line writes none of this, so it builds what it built before versions. `ascribe agents index` and `ascribe resolve` without `--build` take a versioned build's current line. This replaces the plan's decision 35, which turned an older line's outputs for agents off until each line could publish its own. _Why:_ a search engine should index the current page, and still read an older page's canonical link, which a rule over the line's folder in `robots.txt` would stop it reading; whether an older line publishes a page is known per build, and the registry gives each diagnostic one level; a reader of the records asks why a page isn't listed, and the answer is the rule; an agent reads one page, with no banner to see; and naming the declared build is naming its current line everywhere else. _From:_ the maintainer, on the [versions plan](https://github.com/ascribed-dev/ascribe/blob/395fe80d/project-docs/versions/README.md), decisions 32, 50 to 52, 54, and 57, 15 and 16 October 2026 (32 on [#494](https://github.com/ascribed-dev/ascribe/issues/494#issuecomment-6195368949); 50 to 57 confirmed with [#515](https://github.com/ascribed-dev/ascribe/pull/515)), with the index's heading from [#518](https://github.com/ascribed-dev/ascribe/pull/518); recorded when the plan closed, with [#502](https://github.com/ascribed-dev/ascribe/issues/502).
