section: The language
---

**An edit of a key `[from]` takes is made in the file that writes it, at the same path, and says which file it changed.** The editor's model edits, renames (a renamed key `take` names is renamed in `take` too, and a phrase or a value is renamed in the pages of the project the other file is, which declares it and so uses it, or the rename is refused, naming the file; a file with no content root has no pages), the link updates when a page moves, Project Settings, the quick fix that retires a permalink, and `ascribe permalinks retire` parse the other file beside `ascribe.toml` and send each change at a taken key to it; the editor's open copy of that file is the one edited. `ascribe versions release` and `retire`, in a project that takes the target's lines, are made in the project that writes them: its marks are rewritten and its outputs compared, and the text and the JSON's new `from` name its `ascribe.toml`. A mark on a page of a project that takes the lines isn't rewritten, so RELEASING.md keeps the step that removes the site's own. `ascribe templates eject` and `ascribe vale eject` refuse a taken table, naming its file, as does the editor for a table written partly in each file; the glossary's fix to list a page isn't offered when `[glossary] pages` is taken. SPEC §7.9 and the contract's §2.1 say so, in place of #813's refusal. _Why:_ a taken key has one place it's written, so the edit goes there rather than nowhere; eject writes files beside the project's `ascribe.toml` that the other file would name from its own folder, and a fix carries edits to one file, so those are refused or left out rather than made wrong. _From:_ piece 5 of [the shorter content model](../proposals/shorter-content-model.md#5-one-project-takes-tables-from-another), the maintainer's issue [#814](https://github.com/ascribed-dev/ascribe/issues/814), 22 October 2026.
