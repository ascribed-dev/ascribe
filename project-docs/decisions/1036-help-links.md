section: The binary
---

**A diagnostic's `fix` in `crates/ascribe-core/data/diagnostics.toml` links to the docs only by permalink, `https://ascribed-dev.com/go/<name>/`, and the diagnostics reference writes each as a link to the page the permalink names.** So `help` in `ascribe check`'s JSON, `fix` in `ascribe explain`'s, and the editor's `help` have no relative link an agent can't follow, and the reference still links to its own pages. A test in `tests/conformance/tests/docs.rs` fails on a relative link in a `fix`, and on a permalink the docs don't publish. The docs gain ten permalinks for what the help links to: `availability-specs`, `intended`, `22-checks`, `intended-acknowledgements`, `121-releasestarget`, `addresses-base`, and the pages `vale`, `serve-markdown`, `baseline`, and `redirects`. A heading's permalink is its slug, so its anchor doesn't move, except `addresses-base`, which `the-base` was too vague a name for. `ascribe check`'s text summary says how many files have problems (`1 with problems`) where it said `reported on N`, and names the files the paths cover only with paths; `files_reported` in the JSON keeps its meaning. _Why:_ an address is what an agent can open, and the binary's addresses are permalinks so they don't move when a page does; "reported on 9" read as nine files with problems. _From:_ [#1036](https://github.com/ascribed-dev/ascribe/issues/1036), the agent-writer review's smaller things, 26 October 2026.
