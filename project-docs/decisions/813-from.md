---
section: The language
---

**`[from."<path>"] take = [...]` reads tables and keys of another `ascribe.toml` in the same repository as if they were written in this one, one step only.** `<path>` is relative to the folder `ascribe.toml` is in and is read through `FileSystem`; a file outside the repository, missing, or not TOML is `model-from-file`. `take` names a whole top-level table or one key of one (`dimensions.pm`, `consumer.site`), never `spec`, `project`, or `from`, which are each project's own (`model-from-take`). A key that's taken and also written here is `model-from-written`, so there is never a merge to explain. The other file's own `[from]` isn't followed, and a source it declares keeps its `path` from its own folder. What's taken is reported at the name in `take`. `ascribe model --format json` marks a taken setting with `from`, naming the file; the editor's hover says where a taken key is written and Go to Definition opens it; the server watches the file. Edit commands, the editor's and `ascribe versions release`, stop with an error naming the file that holds a taken key, rather than writing a second copy. `@ascribed/astro` and the extension, which read `ascribe.toml` themselves, ask the binary (`ascribe model`) when the file has `[from]`, so there is one reader of `[from]`. The contract's §2.1 and SPEC §7.9 say so, and site/home takes the releases, `dimensions.pm`, `phrases.version`, `sources.code`, and three `consumer` keys from the docs, with the same site. _Why:_ the site and the docs kept copies of the same values, and `facts.test.ts` compared them; one step and no merging keep where a value comes from answerable by reading two files. _From:_ piece 5 of [the shorter content model](https://github.com/ascribed-dev/ascribe/blob/bb56bfb3/project-docs/proposals/shorter-content-model.md#5-one-project-takes-tables-from-another), made the maintainer's issue [#813](https://github.com/ascribed-dev/ascribe/issues/813), 22 October 2026.
