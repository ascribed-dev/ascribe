section: The binary
---

**Every `address-lost` has its fixes: record git's renames (safe), forward it to one of the three pages most like it, or retire it with a placeholder reason; `ascribe addresses move --from-git` records git's renames as a command, and an `@id`'s rename records itself.** The fixes edit `ascribe.addresses` whole, as minimal line edits, so `ascribe check --fix` writes it beside the pages. Recording git's renames is one identical fix on every lost page, so applying the fixes applies it once. The pages most like a gone one are ranked by a cosine of their words as the base had it against each page's now, headings' and the title's counted twice. A lost `#id` is offered the same id on another page. Renames come from `git diff --name-status -M` against the base, as content paths; a copy isn't a move, and neither is a rename below git's similarity threshold. `Renaming::Id` adds `<page>#<old>` = `<page>#<new>` for a page, not a fragment, whose ids' addresses don't move. Moving a page rewrites the entries leading to its headings; retiring one retires the entries leading to it. The editor offers the fixes in `ascribe.addresses` from the extension, after Check Every Build, since the language server doesn't serve that file. _Why:_ a lost address with a one-step fix is one a writer settles in the pull request instead of in a ticket (decision #904). _From:_ [#906](https://github.com/ascribed-dev/ascribe/issues/906), [redirects, phase 2](https://github.com/ascribed-dev/ascribe/blob/9162c25a/project-docs/redirects/phase-2-decisions.md), tasks 1 to 3, 25 October 2026.
