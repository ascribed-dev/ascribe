section: The binary
---

**`ascribe_resolve` takes `emit`, `plain` or `site`, as `ascribe resolve` takes `--emit`, and returns the command's JSON with its `emit`.** `emit` is a string enum of `plain` (the default when it's left out) and `site`; `site` returns the page as `ascribe resolve --emit site --format json` writes it, its `text` the site output's Markdown and its `emit` `"site"`. `emit`, either value, with a `page` of `go:<name>` is the command's usage error, returned as the tool's error, since a permalink's help has one form. Any other value is an error naming the two. The tool stays read-only and writes nothing (decision 56). The rules `ascribe agents sync` writes and the skill's line for `ascribe resolve` say to ask for the site form to see what a reader of the site gets, and link to the docs' section on reading the site output, by its permalink `reading-site-output`. _Why:_ an agent with no shell sees what a site is given for one page, as one with a shell does with `--emit site` ([decision #913](913-resolve-emit.md)), and the tools' arguments are a contract (decision 56). _From:_ the maintainer, 24 October 2026, in [the proposal](../proposals/resolve-emit.md) and [the plan](../resolve-emit/README.md)'s decision 5, built in #914.
