---
section: The binary
---

**A personal memo is a memo file in `.ascribe/memos/`, in the same format, kept on one machine: the editor, `ascribe outline`, and `ascribe refs` read it and mark it personal, and `ascribe check` doesn't.** `.ascribe/` is the folder a project doesn't commit, so a personal memo isn't shared, and deleting the folder loses it. Where memos come from is one interface in the binary, `MemoStore` in `ascribe-resolve`, with two implementations: `Committed`, over `memos/`, and `Personal`, over `.ascribe/memos/`, both read through `ascribe_resolve::FileSystem`. What lists memos reads both; `ascribe check` and the agents' rules read the committed folder only, so what they say is the same on every machine; the language server reads both, and reports a personal memo's problems as it reports a team memo's. A later store, such as a server for people without a checkout, either writes memo files for the binary to read or lives in TypeScript, where GitHub access is: the binary gains no HTTP client. _Why:_ a writer has reasons that aren't yet the team's, such as what they were told and haven't confirmed, and those belong beside the page on their own machine; one interface keeps a second source of memos from changing anything that reads them, and [decision 1](../decisions.md) keeps the binary off the network. _From:_ the maintainer, on the memos plan ([README](https://github.com/ascribed-dev/ascribe/blob/395fe80d/project-docs/memos/README.md), decisions 12, 15, and 16, and [phase 6](https://github.com/ascribed-dev/ascribe/blob/395fe80d/project-docs/memos/phase-6-editor.md)), 14 October 2026, as [#561](https://github.com/ascribed-dev/ascribe/pull/561) shipped them on 17 October 2026; recorded when the plan closed, with [#536](https://github.com/ascribed-dev/ascribe/issues/536).
