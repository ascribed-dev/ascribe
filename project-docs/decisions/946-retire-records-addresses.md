section: The language
---

**Retiring a release line in a project with `ascribe.addresses` records, in the same change, each page address the line's builds published that goes to a page in the current line, as a `[moved]` entry keyed by the address from the host's root (SPEC §7.10), and `ascribe check --base` treats a base build of a line `[releases]` archives now as accounted for: its addresses aren't compared, and it isn't `addresses-build-gone`.** An address that goes to the line's archive isn't recorded, since a `[moved]` value is a page of the project and a redirect's `to` is from the host's root (output-layout contract §1.8); `versions retire` still lists it for the host's redirects. An address key, not a `[former]` entry, because the line's addresses are under its folder, which no routing setting the file records moves, and an address key is the form the file already has for an address no source stands for. `versions retire --format json` gains `recorded`. _Why:_ the build writes redirects from `ascribe.addresses` alone, so a retirement that only listed its addresses left the file's projects with neither the redirects nor a check that knew the build left on purpose. _From:_ [#946](https://github.com/ascribed-dev/ascribe/issues/946), 26 October 2026.
