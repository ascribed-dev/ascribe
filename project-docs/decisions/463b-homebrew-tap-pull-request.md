section: The binary
---

**A release updates the Homebrew tap, `ascribed-dev/homebrew-tap`, by opening a pull request on it, which the maintainer merges.** The release workflow's last job, `tap`, run after the GitHub release is published (with no approval since [decision #489](489-release-tag-is-the-sign-off.md)), writes the tap's formula, `ascribe.rb`, from the release's `SHA256SUMS` (`scripts/release/formula.ts`) and opens the pull request with `HOMEBREW_TAP_TOKEN`, a token scoped to the tap; without that secret it writes the formula and opens nothing. A pre-release opens none, so the tap installs releases only. A dry run writes the formula as an artifact and opens nothing. _Why:_ a pull request keeps a person between a release and what `brew` installs, and pushing to another repository needs a credential this one didn't hold. _From:_ the maintainer, 13 October 2026, in the tested examples plan's phase 6 ([#463](https://github.com/ascribed-dev/ascribe/issues/463)), taking the phase's recommendation.
