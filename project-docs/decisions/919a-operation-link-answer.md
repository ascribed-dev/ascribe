section: The binary
---

**`ascribe link` answers a link to an operation of a declared API with `kind: "operation"`, a new answer kind, and a new field, `operation`, which `ascribe_link` returns as the command's JSON.** `operation` has `api`, `operation_id` (null for an operation with none, which a link names by its method and path), `method` in lowercase, `path` as the spec writes it, `summary`, `tag` (the first), `deprecated`, and `address`, the operation's address in the published reference as the editor's build writes the link (null when the reference has none for it). It's absent for every other target, so no other answer changes, and `schema_version` stays 1 (decision 4). `path` is the spec's, from the content root, and `id` the fragment, decoded, as before; `title` stays null, since a link's empty text doesn't show the summary, and the text output writes the summary as the link's text, and as each closest operation's. The tool's name and arguments don't change (decision 56); its description says what it answers for an operation. _Why:_ an agent checks a link to an operation before writing it, as it checks one to a page, and needs to know it's the operation it means. _From:_ [#919](https://github.com/ascribed-dev/ascribe/issues/919), [OpenAPI, phase 3](../openapi/phase-3-editor.md), 25 October 2026.
