section: The binary
---

**The commands share their flags: `--dry-run` and the git guard with `--force` on every command that writes, `--check` as a dry run that exits `1` and prints the change as a unified diff, `--exit-code[=<level>]` for exiting `1` on findings with `--deny-warnings` kept as an alias of `--exit-code=warning`, `--format json` on every command that doesn't only print a file, the same `--format` words everywhere with `concise` wherever `text` is, and `--base` for a revision to compare with.** A new file in a project is `ascribe.<name>.toml` when you write it and `ascribe.<name>` when Ascribe writes it for you to commit; existing files keep their names. [CONTRIBUTING.md](../../CONTRIBUTING.md#command-line-conventions) writes the conventions down, and [`conventions.rs`](../../crates/ascribe-cli/src/conventions.rs) holds them over the `clap` definitions, with today's exceptions listed, which the pull requests after the first remove a group of commands at a time; a renamed option keeps its old spelling as a hidden alias for a release. _Why:_ the commands disagreed (`--check` and `--dry-run` for writing nothing, four spellings of failing on findings, a guard on two commands that write), so what one command taught didn't hold for the next, for people or agents. _From:_ Kyle, [#965](https://github.com/ascribed-dev/ascribe/issues/965), 26 October 2026.
