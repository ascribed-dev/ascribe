section: The binary
---

**`ascribe model --format json` has the project's navigation under `navigation`, and the JSON output has `_ascribe/nav.json`.** `navigation` is there without `--section`: the root section, each section `{ folder, label, page?, pages, sections, listed }`, where `listed` says whether `ascribe.nav` lists it, and each page `{ source, label, type? }`, every page that isn't `unlisted`, whatever the build. `schema_version` stays `1`, since a key is added. The JSON output's `_ascribe/nav.json` is the site output's file, `formatted.label` as a list of text and code pieces, as its pages' `formatted.title` is. An archive's sidebar, contents page, and previous and next follow its line's share of the navigation, so a line's archive and its site sidebar list the same pages in the same order. _Why:_ an agent that reads the model before writing a page should see where it will go, and each output carries a label in its own formatted form. _From:_ the maintainer, on the navigation plan ([phase 1](../navigation/phase-1-decisions.md), decisions 1 and 5; [README](../navigation/README.md) decisions 18 and 22), 16 October 2026; recorded with [#539](https://github.com/ascribed-dev/ascribe/issues/539).
