---
section: The language
---

**`@operation: <link>` is a built-in line directive, SPEC §4.13, whose identifier primary is a link to an operation in either form a link names one, checked as that link is, and which shows the operation's method, path, summary, and deprecation, linked to its address, and nothing else.** The primary goes through the same resolution as a link's destination (`resolve_reference`), so a missing operation is `link-operation-missing` with the closest as its fixes, a link by method and path to an operation with an id is `link-operation-by-path` with its safe fix, and a missing file is `link-target-missing`; anything else that resolves, a page, another file, the spec with no fragment, or a URL, is `operation-link-not-operation` (ASC276), an error. The name has no hyphen, since a hyphenated name is a project's widget (SPEC §6). It binds itself, and is a block a following-block directive can bind, as `@snippet` is. The plain output writes the line `GET /users/{id}: Get a user` as a link to the operation's address, absolute as a link is, then ` (deprecated)` outside the link when the spec says so; the JSON output writes a block of type `operation`, with `api`, `operationId` when it has one, `method`, `path`, `summary` when it has one, `deprecated`, and `address`, the same address a link to the operation gets. An `@operation` whose operation the spec doesn't have writes nothing in the site and plain outputs, and stays a `directive` block in the JSON output, since `ascribe check` reports it. _Why:_ a guide that names its call should show the call as the spec has it, and the proposal's phase 5 keeps the embed thin: a schema or parameters are the reference's, so the page links there. _From:_ [#923](https://github.com/ascribed-dev/ascribe/issues/923), [OpenAPI, phase 7](../openapi/phase-7-embed.md), 25 October 2026.
