section: The binary
---

**`ascribe sources fetch` and `update` copy a source's `ascribe.examples.toml` and every file in its `examples.observations/`, whatever its `include` says, and which there are is read from the commit's tree only when the repository is reached.** When every copy a source needs is in order, the pin's own list says which there are, so a fetch still runs no `git`; a pin made before Ascribe copied them gets them with the next `update`, or the next time any copy is fetched. One that isn't a regular file, is over the size limit, or isn't text is left out without an error, since no snippet named it, and its examples read as unobserved. In `ascribe sources status`, and its JSON, they're `current` when they're the files the lock pins, though no snippet uses them, and `source-copy-unused` never reports one. _Why:_ [phase 3](https://github.com/ascribed-dev/ascribe/blob/180eee83/project-docs/tested-examples/phase-3-remote.md) has them travel with the source and be locked like any copy, and "a source whose copies are all in order never runs `git`" is what lets `fetch` run offline in CI; reading the tree on every fetch to catch an older pin would give that up for a case one update fixes. Calling them `unused` would tell the reader `fetch` removes them, which it doesn't, so `current` widens to cover them rather than adding a state to the status JSON. _From:_ the implementation of [issue #460](https://github.com/ascribed-dev/ascribe/issues/460), for Kyle's review in its pull request, 13 October 2026.
