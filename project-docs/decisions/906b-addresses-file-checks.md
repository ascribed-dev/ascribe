**SPEC §8.2 gains nine "Addresses file" rows, ASC259 to ASC267, each reported at its entry of `ascribe.addresses`, and a `[moved]` chain leads where it ends.** `addresses-entry-not-a-page` (error), `addresses-entry-live` (advice, fix removes it), `addresses-entry-taken` (error), `addresses-entry-unpublished` (advice, needs the base; an entry already in the base's file is never reported, fix removes it), `addresses-key-twice` (error, read before the TOML, naming both values), `addresses-chain` (advice, fix forwards to the end; a cycle has no fix), `addresses-anchor-collision` (error), `addresses-file-deleted` (error, at `ascribe.toml`), and `addresses-soft-404` (advice, three or more entries leading to one index page). The comparison, the not-a-page check, and the emitter all follow chains with `AddressFile::follow`, so a build writes flat pairs. A project without the file reads the base's only when `--base` names it, so a check of one never starts `git` on its own, and CI, which names the base, still stops the file's deletion. _Why:_ the file is hand-mergeable, so what a merge or a hand edit can break is checked where the entry is (decision #904's phase 0 table). _From:_ [#906](https://github.com/ascribed-dev/ascribe/issues/906), [redirects, phase 2](../redirects/phase-2-decisions.md), task 4, 25 October 2026.
