section: The language
---

**A template's placeholder left in a page that publishes is an error, `template-placeholder-published` (ASC286), and in a draft it stays advice, `template-placeholder-left` (ASC195); a page started with `ascribe new`, VS Code's New Page, or the `new-page` prompt starts as a draft.** The two are found the same way, the placeholders and the frontmatter values still the template's, and which one a page has depends only on `draft: true` (decision [#1162](1162-drafts.md)), so `check`, `build`, the editor, the agents' hook, and the MCP tools say the same thing. ASC286 is configurable in `[checks]` as ASC195 is: it's about a page's text, not whether the project is valid. A template's own `draft` isn't a field a page must fill in. `ascribe new <type> <path> [--title]` writes the page from `ascribe_templates::start`, which the editor and the prompt use, with `type`, `title`, and `draft: true`, never over a file, and says that taking `draft` out publishes it. The edit hook reports ASC195 and `template-section-empty` in the files an agent wrote, though they have no fix, so it fills them in while the page is its own; ASC286 reaches it as an error. A draft in a section whose `pages` in `ascribe.nav` leaves it out isn't `nav-page-unplaced`. This replaces the page templates plan's decision 17 (#402), which made a placeholder advice everywhere so a page being written isn't covered in errors: a draft is now where that intent lives. _Why:_ a placeholder in a published page is never meant, and nothing stopped one; an error only at build time would have `build` report what `check` doesn't (#976, #985), and a warning everywhere doesn't stop CI. Two diagnostics, not one with a level that moves, because the registry gives each diagnostic one severity, and a project may want to set them apart in `[checks]` (as decision [#558](558-template-section-empty.md) reasoned). _From:_ Kyle, [#1005](https://github.com/ascribed-dev/ascribe/issues/1005), 26 October 2026.
