section: The binary
---

**The language server, the agents' hooks, the MCP server's `ascribe_check`, and its `fix` prompt read `ascribe.baseline` as `ascribe check` does; a held-back finding is reached in the editor through the hover on its line and a quick fix there, which moves it to an `@intended`.** The server holds back a file's diagnostics at a time, since a finding's order is among those of one file and one check, keeps what it held back for the file with the entry's identity in each one's `data.baseline`, and follows the file as it's typed and on disk, checking every file again when it changes. It publishes `baseline-entry-unmatched` on `ascribe.baseline` for an entry no finding of its last rounds matches only when the editor's build, with its other lines, is every build the project has, as `ascribe check` reports one only when it checks every build, and never for Vale's entries, since it runs Vale on open documents only, nor for those of the checks it doesn't run (`ascribe_check::NOT_IN_EDITOR`: `image-unused`, `image-large`); a line that doesn't parse is an error at that line (`baseline_invalid`, no registry entry, as the command's error has none), and nothing is held back until it's fixed. The quick fix, **Move out of the baseline, mark as intended, and write why**, is offered on a review check's held finding in a code action request at its range, whatever diagnostics the request sends, and deletes the entry's line, line end included, and writes the acknowledgement as **Mark as intended, and write why** does, placeholder reason and all. The hooks' answers say `` `ascribe.baseline` holds back N advice the project has put off for now, so the check leaves it out. `` when N isn't 0, and a hook still speaks only when it has errors or fixable advice to report; the check server counts what its language server held back in the files asked about. A baseline that can't be read stops `ascribe_check`, the `fix` prompt, and the stop hook as it stops `ascribe check`; after an edit, the hook checks the files without it, in its own process and through the check server alike, and its answer adds `` `ascribe.baseline` can't be read, so the check held nothing back: <the line and what's wrong>. Fix the line, then run `ascribe check`. ``, which it gives even with no error to report. _Why:_ an agent or an author working on a page shouldn't be sent after the backlog the project put off, and should hear that it was put off; a held-back finding isn't a diagnostic, so the editor needs a place where a person who means to keep one for good can find it, and the hover and the light bulb on its line are where they already look. The editor can't tell a stale entry from a finding in another build, so it says nothing rather than something wrong. _From:_ [#790](https://github.com/ascribed-dev/ascribe/issues/790), from the [cache proposal](https://github.com/ascribed-dev/ascribe/blob/bb56bfb3/project-docs/proposals/cache.md)'s "A baseline", 22 October 2026.
