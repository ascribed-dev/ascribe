section: The language
---

**What happened to a permalink no heading or page declares any more is recorded in `ascribe.addresses`, keyed `go:<name>`, and `ascribe.toml` has no `[permalinks]`: `[retired] "go:<name>" = "<reason>"` retires one, `[moved] "go:<name>" = "<page>#<id>"` moves it to a place, and `[moved] "go:<name>" = "go:<other>"` makes it an alias of another permalink, which only a `go:` key can have.** A moved name has no reason: its address leads somewhere, so a reader never sees one. A chain of `go:` entries ends where the file's chains end, at a declared permalink, a place, or a retirement, and an entry for a name the content declares does nothing (`addresses-entry-live`), as one for a restored page does. `ascribe.permalinks` stays the published list, written from the content and the file, with a `[moved]` table for the names moved to a place; its version stays 1. `[permalinks]` in `ascribe.toml` is an error that says `ascribe addresses init` moves its entries, and a base whose `ascribe.toml` still has it is read as if they had been moved. A name that goes away is lost, one word, as an address is: `permalink-removed` is `permalink-lost`. `model-permalinks`, `permalink-alias-target-missing`, `permalink-name-conflict`, and `permalink-retired-target-missing` are gone, each now one of the file's own checks. _Why:_ a permalink's address is one of the addresses the docs published, and where it went is the same question with the same answers as a page's; two files that each record it, with two vocabularies and two sets of checks, made a reader learn both, and let them disagree. _From:_ [#944](https://github.com/ascribed-dev/ascribe/issues/944), Kyle, 26 October 2026.
