section: Review

**A source anchor reaches the consumer as raw HTML: as attributes on an element Ascribe writes itself, and as an anchor comment before a block the markdown pipeline renders.** The [site-render contract §7.3](../../docs/content/contracts/site-render.md#73-how-an-anchor-gets-through-the-markdown-pipeline) has the form. _Why:_ the site output is markdown the consumer renders, and only raw HTML reaches a plugin unchanged: each of Astro's markdown processors (Sätteri, its default in Astro 7.3, and `unified()`) applies GFM and typographic replacements before a user plugin sees the tree, so an attribute written as text arrives with its quotes curled and its `--` and `...` turned into dashes and ellipses, as [decision #689k](689k-profile-fixes-ids-attributes-assets.md) found for heading ids. Raw HTML passes through every renderer unchanged, so an element Ascribe writes needs nothing else. For a block the pipeline renders, a comment: CommonMark makes an HTML comment an HTML block of its own (type 2) that ends on the line holding `-->`, and lets it interrupt a paragraph, so the comment never joins the block before or after it, the block after it starts where it would have, and a list whose blocks it sits between doesn't become loose, since there's no blank line. Both of Astro's processors hand a plugin the comment as a `raw` node that is a sibling of the block's element, and a consumer without the plugin renders it invisibly. _From:_ the site-render contract's §7.3 ([as it stood](https://github.com/ascribed-dev/ascribe/blob/23738c8/docs/content/contracts/site-render.md#73-how-an-anchor-gets-through-the-markdown-pipeline)), whose reasoning moved here so the contract says only what is; a file of its own since [issue #688](https://github.com/ascribed-dev/ascribe/issues/688), 21 October 2026.
