section: The binary
---

**`ascribe versions retire "<target> <line>" --url <address>` takes the oldest live line out of the window once its archive is hosted: it moves the line to `archived`, rewrites each mark for the target to the simplest spec that means the same in every line left, and proves no live line's output changed.** Archive first, then clean up: it refuses a line with no `--url`, naming `ascribe versions archive`, and the address comes from `--url` alone. It refuses a line that isn't live, so a second run changes nothing; the current line; a live line that isn't the oldest; and a target no build is versioned by, whose list `release` keeps to one live line. The line's `ended` is its date in `ends`, whose entry goes, or else today, UTC or `ASCRIBE_TODAY`. Each mark, in a page, its frontmatter, or a table row, and each feature's spec is rewritten through the function a line's output shows a spec with ([decision #502b](502b-versioned-builds.md)): a version at or before the new oldest line goes and its state stays, a history keeps the step in effect when the window opens, with its own version, a `ga` with no version left is the target alone, and a version inside the oldest line but newer than it, `3.5.1` with 3.5 the oldest, stays, since a line shows it. It builds the site and plain outputs in memory before and after and refuses when a live line's changes; a build that isn't a line of the target and changes, such as a badge build, or a filter build, is named with the pages it adds, removes, and changes, and the rewrite needs `--force`. Files git can't put back need `--force`, as with `release` ([decision #502h](502h-versions-commands.md)). It deletes nothing on its own: a page, section, block, or row in no live or planned line, and a mark that says nothing once rewritten (generally available alone, naming exactly the targets its scope allows, with nothing inside it giving one of those a version), listed as kind `mark`, are listed with `--show-unused` and deleted with `--remove-unused`, along with the `replaces` line of a page that replaced one it deletes. Both work on a line retired already, with `retired` false in the JSON. Redirects aren't written: it reports where each address the line published should go, the same page in the current line, the page that replaces it there, or its page in the archive, naming the replaced pages in its text and listing every address in its JSON as `from` and `to`, as the headers list writes them. _Why:_ after the clean-up the source no longer holds what the line needs, so its archive comes first; a line can't be live and archived at once, so a live line has no `archived` entry to give an address; every mark draws a badge, so removing one changes a line's output, and the rewrite is the step that changes none; listing what's left after the retirement and deleting it are separate reviews, which shouldn't need the line back; and a host's redirects are the host's to write. _From:_ the maintainer, on the [versions plan](https://github.com/ascribed-dev/ascribe/blob/395fe80d/project-docs/versions/README.md), decisions 16, 17, 21, 79 to 82, and 84, 10 and 16 October 2026 (79 to 84 confirmed with [#523](https://github.com/ascribed-dev/ascribe/pull/523)); recorded when the plan closed, with [#502](https://github.com/ascribed-dev/ascribe/issues/502).
