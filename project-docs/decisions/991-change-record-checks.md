section: Clean-ups and checks
---

**CI checks what a pull request records besides its code: a contract changed with no decision fails, and a change to the source with no changelog entry warns.** The `change record` job ([scripts/ci/change-record.ts](../../scripts/ci/change-record.ts)) fails a pull request that changes `SPEC.md`, a file in `docs/content/contracts/`, or `packages/elements/CONTRACT.md` and adds or changes no file in `project-docs/decisions/`. It warns in the run's summary when a file in `crates/*/src/` or `packages/*/src/` changes and no entry is added in `changes/`, unless the description has a line starting `Not user-visible:` that says why. A behavior change's conformance case and a clean-up's `optimization` label stay with the reviewer, and the `review` skill has it look for them. _Why:_ these rules had no mechanical check, and on the board the reviewer is the same kind of agent as the implementor, with the same blind spots; the changelog check only warns, because whether a change is one a user would notice is a judgment. _From:_ Kyle, in [#991](https://github.com/ascribed-dev/ascribe/issues/991), 26 October 2026, from the contributor-agent review of the repository.
