section: The binary
---

**`ascribe observe` asks before it runs the commands of `ascribe.examples.toml` when its standard input is a terminal; `--yes` skips the question, and without a terminal it runs them as it always has.** It lists the `test` and `[environment]` commands, from its own reading of the file, then asks **Run them? [y/N]** on standard error; only `y` or `yes`, in any case, runs them, and anything else, an empty line, or the end of input runs nothing, writes nothing, and exits 2. With `--format json`, the list goes to standard error too, so standard output holds the JSON alone; `--check` runs nothing, so it never asks. The editor's Observe Examples task is then a plain process, as Build and Sync Agent Files are ([decision #655a](655a-tasks.md)): `ascribe observe`, run in the folder of each source with tested examples, which the extension learns from `ascribe model --section sources --format json` (each source with `examples` and no `git`), with no `--config`, since `ascribe observe` takes none and runs only the config in its own folder. `tasks.json` names the source by its name, as `source`, left out when the project has one. The extension parses no TOML to find the sources or the commands, and never passes `--yes`; the tested-examples page's sentence that the editor never runs `ascribe observe` is replaced by this. _Why:_ the question can't drift from what runs when it's asked by the program that runs it, and a task shows what ran in a terminal, where the question is asked; CI and hooks have nobody to answer, so they're unchanged. _From:_ the maintainer, in decision 9 of [the editor's next views](../roadmap.md#decisions), after the review of [#735](https://github.com/ascribed-dev/ascribe/pull/735), 21 October 2026; built in [#738](https://github.com/ascribed-dev/ascribe/issues/738), where the property's name, `source`, was proposed, and confirmed by the maintainer in review of [#743](https://github.com/ascribed-dev/ascribe/pull/743).
