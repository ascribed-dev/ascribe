section: Process
---

**A new decision is a file of its own in `project-docs/decisions/`, named and cited by the number of the issue it was made for.** The file is `<number>-<slug>.md`, such as this one; a decision with no issue takes its pull request's number, and an issue that makes more than one gives each a letter (`381a-…`, `381b-…`, cited as decision #381a). It's cited as "decision #381", with a link to the file where one fits. Its frontmatter names its section, one of the `##` headings of [decisions.md](../decisions.md), and it holds what an entry there holds: the decision in a bold sentence, then the rest, _Why:_, and _From:_. A replaced decision stays, struck through, with a pointer to the one that replaced it; a file isn't deleted and its number isn't reused. The numbered decisions stay in decisions.md, and it takes no new ones; `pnpm test` fails on a number there above the last it had. `node scripts/repo-docs/decisions.ts list` prints the files' decisions under their sections, and `pnpm test` checks each file ([the folder's README](README.md)). A plan's own decisions stay in its `README.md` while it runs. _Why:_ every pull request that recorded a decision appended to decisions.md at the same place and claimed the next number, so two of them conflicted on the lines and on the number; GitHub numbers issues and pull requests in one sequence, so no two branches take the same one. Files numbered by the next number in a row were turned down, since two branches can both take it, and so were unnumbered files numbered when gathered, since a pull request couldn't cite its own decision. _From:_ the maintainer, in issue #381, 11 October 2026.
