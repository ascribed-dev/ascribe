section: The look
---

**The extension's webview views draw codicons with VS Code's own font, `@vscode/codicons`, shipped in the extension and read from its files.** The views' stylesheet imports the package's, and the build copies its `codicon.ttf` beside it in `dist/webview/`, with the font's license; the content security policy allows the font from the extension's files alone. Decision 48 ("no web font anywhere") is about a reader downloading a font for text, and doesn't reach an icon font the extension ships, as decision 50 already has it ship one. A product icon theme isn't followed in these views, as the tree's icons followed it. _Why:_ a webview gets no `ThemeIcon`, and the codicon font draws the same icons the rest of VS Code does, in the theme's colors, without a request. _From:_ the maintainer, decision 1 of [the editor's next views](https://github.com/ascribed-dev/ascribe/blob/62bf76a9/project-docs/roadmap.md#decisions), 20 October 2026, for [#651](https://github.com/ascribed-dev/ascribe/issues/651).
