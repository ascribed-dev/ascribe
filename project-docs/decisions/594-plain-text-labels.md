section: The language
---

**A page's label before a build is plain text wherever its type's `title` takes inline markup, as the navigation has it.** A page with no `nav-label` falls back to its title read as its `nav-label` is: as plain text when `title` sets `inline`, so `examples/astro-site/content/Reference/Options.md`, titled ``"`loom.yaml` options"``, is labeled `loom.yaml options`. A section labeled by its own page's title is labeled the same way. `ascribe_resolve::file_label` and `Section::label` make these labels, and `ascribe model`'s JSON and the editor's **Pages** view, which read them, change; `nav.json` and the sidebar already said `loom.yaml options`, so no build output changes, and the output comparison finds no difference to accept. _Why:_ the site's navigation falls back to the resolved page's plain title and keeps the markup apart as `formatted`, so `file_label` was the one place that kept the backticks, and a reader saw two names for one page. _From:_ the maintainer, on [#594](https://github.com/ascribed-dev/ascribe/issues/594#issuecomment-6240308058), found in review of [#592](https://github.com/ascribed-dev/ascribe/pull/592), 17 October 2026.
