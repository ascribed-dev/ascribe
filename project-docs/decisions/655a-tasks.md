section: The binary
---

**The extension's `ascribe` task type runs Build (`ascribe build`), Sync Agent Files (`ascribe agents sync`), and Observe Examples (`ascribe observe`) in the terminal, with the binary the project's server runs, and no problem matcher; `tasks.json` names one by `task` (`build`, `syncAgentFiles`, or `observeExamples`), `project` (the project's folder relative to the workspace folder, left out for the workspace folder's own), and, for Observe Examples, `source` (the source, by its name in `ascribe.toml`, left out when only one has tested examples).** Build and Sync Agent Files run in the project's folder, with `--config` naming its `ascribe.toml` when the project isn't the workspace folder. Observe Examples runs in the folder of a source in the repository (one with a `path` and no `git`) that has an `ascribe.examples.toml`, without `--config`, because `ascribe observe` runs only the file in the folder it's run from and takes no path to one; a project with no such source has no Observe Examples. Before each run it shows the commands the file names, `test` then each `[environment]` command, in the order observe runs them, and asks; declined, it runs nothing. The extension starts no task in Restricted Mode: it offers none, and resolves none `tasks.json` names. This replaces "the editor never runs it" of the tested examples' quick fix: **Copy the command** still only copies, and Observe Examples is the one way the extension runs `ascribe observe`. _Why:_ a task shows what ran, as CI would, and can be bound to a key; the Problems panel stays Check Every Build's and the editor's, so the two never disagree; and the commands are the repository's, the case Restricted Mode and the question exist for. _From:_ the maintainer, on [the Project view proposal](../proposals/project-view.md#actions) and [the editor's next views](../roadmap.md), 20 October 2026; built in [#655](https://github.com/ascribed-dev/ascribe/issues/655).
