section: The binary
---

**Build and Sync Agent Files are tasks of the extension's `ascribe` type: each runs the binary the project's server runs, in the terminal, in the project's folder, with `--config` naming its `ascribe.toml` when the project isn't the workspace folder, and with no problem matcher.** They're offered in the Project view's Actions and in **Tasks: Run Task**, and neither is offered or resolved in Restricted Mode. `tasks.json` names one by `task` (`build` or `syncAgentFiles`) and `project` (the project's folder relative to the workspace folder, left out for the workspace folder's own); the maintainer accepted those two property names, as [#735](https://github.com/ascribed-dev/ascribe/pull/735) proposed them, on 21 October 2026. Observe Examples isn't one of them here: by the roadmap's decision 9, `ascribe observe` asks for itself when its input is a terminal, and the task is a plain process, in its own phase, [#738](https://github.com/ascribed-dev/ascribe/issues/738). _Why:_ a task shows what ran, as CI would, and can be bound to a key; and with no problem matcher, the Problems panel stays Check Every Build's and the editor's, so the two never disagree. _From:_ the maintainer, on [the Project view proposal](https://github.com/ascribed-dev/ascribe/blob/62bf76a9/project-docs/proposals/project-view.md#actions) and [the editor's next views](https://github.com/ascribed-dev/ascribe/blob/62bf76a9/project-docs/roadmap.md), 20 October 2026, and the property names in the review of #735, 21 October 2026; built in [#655](https://github.com/ascribed-dev/ascribe/issues/655).
