section: The binary
---

**An observation in a format this version of Ascribe doesn't know is one `examples-config-invalid`, naming the `ascribe` that wrote it, and `observation-file-missing` is reported in the observation itself, at the line of the file it lists.** Nothing else in a newer format is read, since its keys may mean other things, and its files count as unobserved by it while the other observations still count. A missing file's diagnostic is in the observation, read as a code file is for a snippet, so `ascribe check` and a report show its path, line, and column; its message names the command that writes that observation again, with `--name` for one other than `default`. Only a file that isn't in the folder is missing: one `include` no longer matches is left to the next run. _Why:_ README decision 12 and phase 1's fourth decision put the third diagnostic "at the observation", and a project file can't hold the location of a file outside the content root, while a code file can; a newer format reported once for each key it has would bury the one fact that matters, which version wrote it. _From:_ the implementation of [issue #461](https://github.com/ascribed-dev/ascribe/issues/461), following [phase 4](https://github.com/ascribed-dev/ascribe/blob/180eee83/project-docs/tested-examples/phase-4-status.md), for Kyle's review in its pull request, 13 October 2026.
