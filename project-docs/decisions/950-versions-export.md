section: The binary
---

**The command that renders a line into a folder of HTML is `ascribe versions export`, and `ascribe versions archive` is its old name for one release.** "Archived" is a line's state alone: `[releases.<target>.archived]`, and what `ascribe versions retire` and `ascribe versions release` do to a line. The folder the command writes is still the line's archive, the [archive contract](../../docs/content/contracts/archive.md) is unchanged, and so are its error codes. `versions archive` is hidden from the help and runs `export` after a warning on standard error, and goes in the release after next. Its JSON is the same document under a new name: `VersionsExportReport`, in `schemas/versions-export.schema.json`, at `json-reports/versions.md#ascribe-versions-export`; the permalink `cli-versions-archive` is recorded as moved to `cli-versions-export`. This renames the command [decision #502j](502j-archive.md) names. _Why:_ the command writes a copy and doesn't archive the line, so "archive" meant two things across the commands and the content model; `export` says it writes files, and reads as plainly different from `ascribe preview`, while `snapshot` suggests a point-in-time state of the line, close to the meaning being left. The spec is a draft, but scripts and CI call the command, and a release of overlap costs little. _From:_ Kyle, [#950](https://github.com/ascribed-dev/ascribe/issues/950), 26 October 2026.
