section: The language
---

**A link to a declared spec with a fragment is a link to the operation whose `operationId` is the fragment, percent-decoded, and each output writes the operation's address in the published reference: Redoc's `<at>#operation/<operationId>`, or the template filled in, percent-encoded, joined to the site's `[consumer] base-path` unless it's absolute.** The resolution is `Resolution::Operation`, and depends only on the declaration, not on the spec's content, so whether the spec has the operation is checked with the page's problems (`link-operation-missing`, with the closest ids as its fixes), and the incremental project stays right when only the spec changes. The site output writes the address; the plain output writes it absolute when `[consumer] site` is set; the JSON output gives the link a target of type `operation`, with `api`, `operationId`, and `address`. In an older line of a versioned build the base path is the site's, without the line's folder: an API's reference isn't a line's. _Why:_ the address is in a URL space Ascribe doesn't own, so it's the renderer's, written from the declaration, and the end-to-end test is what proves it lands. _From:_ [#917](https://github.com/ascribed-dev/ascribe/issues/917), [OpenAPI, phase 1](https://github.com/ascribed-dev/ascribe/blob/9162c25a/project-docs/openapi/phase-1-thread.md), 25 October 2026.
