section: The language
---

**An entry in `_ascribe/help.json` for a section with a switcher has `choices`: the section's text with each arm chosen (output-layout contract §1.7).** It's keyed by each dimension the section's switchers are on, then by each value their arms name, both in the content model's order, and each is `text` as a build that selects that value alone writes it: the switcher on the dimension is the chosen arm's content, and every other group in the section is as it was, a labeled group included, which adds no key. `summary` isn't varied. A section with no switcher on a dimension has no `choices`. It's a key added to version 1, which changes none of its keys, and `ascribe resolve go:<name> --format json`, which writes the entry as the file does, has it too. The text is the section's blocks with the value selected by the code a build's selection uses (`ascribe_resolve::select`), rendered by the plain renderer, and the agreement test holds each choice to the page's plain output with it selected, and to a build's that selects it where the project has one. _Why:_ a product that knows its reader's package manager shows the arm they use, as a permalink's `?pm=pnpm` sets it on the site, and a choice made by the build's own selection can't read differently from a build that makes it. _From:_ [the embedded help plan](https://github.com/ascribed-dev/ascribe/blob/0c2b6372/project-docs/embedded-help/README.md)'s decision 4 and [phase 6](https://github.com/ascribed-dev/ascribe/blob/0c2b6372/project-docs/embedded-help/phase-6-arms.md), built in #883.
