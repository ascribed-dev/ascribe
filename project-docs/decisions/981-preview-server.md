section: The binary
---

**`ascribe preview` serves its folder at `127.0.0.1` alone, and that isn't using the network under decision 2.** It's the one socket in the binary: a listener on the loopback address that answers `GET` and `HEAD` with the files of `.ascribe/preview/`, and connects to nothing. It's written with `std::net`, not a server library, so decision 1's no HTTP library still holds, and `crates/ascribe-cli/tests/all/network.rs` keeps every other file off sockets and this one on the loopback address. The preview is the archive's renderer run on any build (`ascribe_emit::preview`), under a statement that it's a preview: the archive keeps `ascribe versions archive`, its folder, and its contract, and the two share one renderer. _Why:_ a person who has only the command should see a page as readers do, with no Node, editor, or Astro, and a browser needs an address to show a folder of pages with their search; a listener nothing beyond the computer can reach keeps decision 2's reasons, the same output anywhere and no credentials. _From:_ [#981](https://github.com/ascribed-dev/ascribe/issues/981), from the product design review, finding 2, 26 October 2026.
