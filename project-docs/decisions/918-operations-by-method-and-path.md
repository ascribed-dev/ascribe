section: The language
---

**A link to a declared spec whose fragment is a method in lowercase, then the path as the spec writes it, `#delete/users/{id}`, is a link to the operation with that method and path, so an operation with no `operationId` can be linked; a fragment that's an operation's id names that operation first, since an id is what a writer chose.** Redoc's address for an operation with no id is Redoc 3's, `<at>#paths/<pointer>/<method>`, the path as a JSON pointer token (`~0` for `~`, `~1` for `/`) and each part percent-encoded, which Redoc 3 opens and scrolls to; Redoc 2 needs its own slug of the tag there, and since Ascribe can't tell which Redoc a site runs, nothing reports it, and the docs say the form needs Redoc 3. A template has no placeholder for an operation with no id, so under one, a link to it by method and path is an error, `link-operation-form-unsupported` (ASC265). A link by method and path to an operation that has an id is advice, `link-operation-by-path` (ASC266), with a safe fix that writes the id, and is written as the id's address in every output. The JSON output's `operation` target has `method` and `path` in place of `operationId` for an operation with no id. A link to a missing operation offers, as its closest, the ids and, for the operations with none, their methods and paths. _Why:_ .NET's generators write no ids by default, and 10% of published specs have none (the proposal's spikes); the README's decision 2 narrowed the proposal's Settled 3 to Redoc 3 on 24 October 2026. _From:_ [#918](https://github.com/ascribed-dev/ascribe/issues/918), [OpenAPI, phase 2](../openapi/phase-2-no-id.md), 25 October 2026.
