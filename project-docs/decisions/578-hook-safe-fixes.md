section: The binary
---

**After an edit, `ascribe agents hook` reports the advice in the files the agent wrote that has a safe fix, and names the fix; it never applies one.** The answer lists the errors as before, then each advice with a safe fix, at most 10, as its concise line followed by `Fix:` and the fix's title, which says what to change and where ("Add `new.md` to `guides/`'s pages in ascribe.nav"). Every advice with a safe fix is reported, not only `nav-page-unplaced`; warnings and the advice without one still aren't. The advice is what the editor shows in the files: the file-level and page-level checks', and those of the checks across the project that hold for every build (`ascribe_check::diagnose_every_build_in`), which the language server runs on save and `ascribe check <file> --editor-build` leaves out, so the hook's own process and its check server report the same. The stop hook still blocks on errors alone. This replaces decision 60's "never … reaches an agent from `ascribe agents hook`" for advice with a safe fix. _Why:_ an agent that adds a page never heard of `nav-page-unplaced`, so the page stayed unplaced; applying the fix would write `ascribe.nav`, a file the agent didn't touch, as a side effect it might not see, so the hook stays read-only and the agent makes the edit, at the cost of one more turn. _From:_ the maintainer's choice of "Report" on [#578](https://github.com/ascribed-dev/ascribe/issues/578), 17 October 2026.
