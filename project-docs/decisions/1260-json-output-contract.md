section: The language
---

**The `json` output is a contract, and its keys are snake_case.** Its format is the [JSON output contract](../../docs/content/contracts/json-output.md), with a schema, `schemas/json-page.schema.json`, generated from the types that write it as the commands' are; it moved there from `crates/ascribe-emit/README.md`. Its keys, and the names its fields' values are, such as a block's `type` (`block_quote`, `thematic_break`) and a directive's `binding` (`following_block`), are snake_case, as every other JSON document Ascribe writes is, so the [JSON report contract](../../docs/content/contracts/json-reports.md)'s rule holds for all of them; only the language server's and the MCP server's messages are camelCase, as their protocols are. Renaming keys changes their meaning, so `schema_version` is `2`. _Why:_ SPEC §9.4 names the JSON output, and the docs offer it "for your own tools", so a reader builds on it whether or not it's written down; and it was the one exception to snake_case, which with no users cost nothing to change. _From:_ Kyle, on [#1260](https://github.com/ascribed-dev/ascribe/issues/1260), 3 November 2026, after the docs review of that day.
