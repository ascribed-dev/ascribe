---
section: The language
---

**A description field's `default` is the page's description in every output, and `description-too-long` reports a long one once, where `ascribe.toml` writes it.** A page that leaves its description field out, or leaves it empty or blank, has the field's default as its description: its line in `llms.txt`, its record in `pages.json`, and the agents' compact index all show it, `page-description-missing` doesn't report it, and This page's Description row measures it. A field without a default keeps the page's empty value, as before. `description-too-long` measures a default as it measures a page's own description and reports it at the `default` in `ascribe.toml`, not on each page that leaves the field to it; a page's own description is still reported on the page. `description-duplicate` compares only the descriptions pages write, since the pages that share a default share it by design. This page's Description row warns "too long" only where `description-too-long` reports the description, so not when the check is off. `ascribe_resolve::llms::written_description`, which `ascribe_check::roles::description` is, says what a page's description is for all of them. _Why:_ a field's default is the value a page has when it leaves the field out (SPEC §7.2), and `page-description-missing` already counted a default as a description, so the outputs leaving it out disagreed with the check; an empty own value falls back so that the check and the outputs agree on it; reporting a default once points at the one place to change it. _From:_ triage, acting for the maintainer, on [#573](https://github.com/ascribed-dev/ascribe/issues/573), 17 October 2026; leaving shared defaults out of `description-duplicate` from its implementor, for the maintainer's review.
