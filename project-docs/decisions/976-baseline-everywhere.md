section: The binary
---

**`ascribe build` and `ascribe report` read `ascribe.baseline` as `ascribe check` does: they hold back the advice it lists, count it (`summary.baselined` in the build's JSON, `problems.baselined` in the report's), and report everything with `--no-baseline`.** The baseline is applied in `ascribe_check::diagnose_with`, which takes a `Request` (the builds, and whether the baseline applies), so a command that checks a project's builds gets the baseline from the check rather than applying it itself. The report's `inventory` leaves out what the baseline holds back too, so its lists of unused entries and orphan pages match `problems`. _Why:_ the spec promises the same rules everywhere (§1.2, 7; §9.1), and a project with a baseline saw a few advice from `ascribe check` and thousands from the build and the report, for the same files; applying the baseline in each caller is how the two commands were missed. _From:_ [#976](https://github.com/ascribed-dev/ascribe/issues/976), the tensions between features and the spec, 26 October 2026; the architecture review's comment there points at [#985](https://github.com/ascribed-dev/ascribe/issues/985) for the rest of the callers.
