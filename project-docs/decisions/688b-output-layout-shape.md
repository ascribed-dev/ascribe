section: The binary
---

**Each build and emitter writes to a root of its own, with paths that mirror the source's, and its manifest beside the root rather than in it; a build fails on a user's file instead of overwriting it.** The [output layout contract](../../docs/content/contracts/output-layout.md) has the rules. _Why:_ one root per build and emitter, with nothing shared, keeps each output self-contained (SPEC §9.4) and lets a consumer point at exactly one directory, such as an Astro content collection at `.ascribe/build/site/site/`. Mirrored paths make the output's structure the source's, keep relative references between pages and assets valid, and make collisions between different files impossible (asset contract §3.1). A manifest beside the root keeps the root holding only output, so a consumer loading every file in it loads nothing else. And output never destroys what Ascribe didn't create. _From:_ the output layout contract's §5, "Why this shape" ([as it stood](https://github.com/ascribed-dev/ascribe/blob/23738c8/docs/content/contracts/output-layout.md#5-why-this-shape)), which moved here so the contract says only what is; a file of its own since [issue #688](https://github.com/ascribed-dev/ascribe/issues/688), 21 October 2026.
