section: The binary
---

**Every surface that checks a project goes through `ascribe_check::Request`: `ascribe check`, `ascribe build`, `ascribe report`, the agents' hook and MCP tool, and the language server.** A `Request` names the builds (or the editor's build), the scope, whether the baseline applies, and whether Vale ran. `Request::find` checks the project, and `Request::settle` applies the policy: the levels `[checks]` sets, the advice `ascribe.baseline` holds back (counted), the stale entries when the check is whole, and what counts for the scope. `diagnose_with` is the two together. `baseline::apply` is gone, so no caller can hold back on its own, and the language server holds back a file at a time with `Request::hold` and says which entries are stale with `Request::unmatched`, with the same list of checks it didn't run. `ascribe check` adds Vale's findings and the addresses compared with a base between the two, so they're settled with the rest; its output is unchanged. _Why:_ a rule every surface should honor was honored only where someone remembered to call it, which is how `build` and `report` missed the baseline (#976). _From:_ [#985](https://github.com/ascribed-dev/ascribe/issues/985), the architecture review (finding A2), 26 October 2026.
