---
section: The language
---

**`draft: true` in a page's frontmatter makes it a draft, which every build drops; it's a ninth reserved key, a boolean, and a fragment can't use it.** A draft is dropped as a page a build's modes rule out is (SPEC §9.3), so nothing that lists a build's pages lists it: no output, navigation entry, page record, `llms.txt` line, or permalink. The build view and This page say a build leaves it out. A link to a draft from a published page is `link-page-dropped`, an error in every build, with a message of its own that names no build. `ascribe check` checks a draft as content no build publishes, so a project with a draft always has that pass. A content model can't declare a field named `draft`, as for every reserved key. `ascribe build --drafts`, the Astro option, the banner, review, and the report of drafts are later phases of [the drafts proposal](../proposals/drafts.md). _Why:_ #1005's template placeholders need a way to tell a page that isn't finished from one that publishes, and Hugo, Astro, Docusaurus, and Jekyll already read `draft: true` the same way; whether a doc is finished is a question of its own, not one `listing` or availability answers. _From:_ Kyle, on the drafts proposal (25 October 2026) and [#1162](https://github.com/ascribed-dev/ascribe/issues/1162), 26 October 2026.
