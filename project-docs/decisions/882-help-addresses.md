section: The npm packages
---

**`@ascribed/astro` serves each help entry at an address of its own, for a product to fetch its line's: `<path><name>.json` for the current line, beside the permalink's address, and `<base>go/<name>.json` for an older line, `/docs/3.4/go/connect.json`.** The answer is the line's `help.json` narrowed to that entry: `version`, `build`, and `line` as the file has them, and `help` with the one entry under its name, so a product reads a fetched entry and its bundled file with the same code. An alias has its own address; a line that has left the window has none. The build's `_ascribe/headers.json` gives each address its own rule, `Access-Control-Allow-Origin: *`, matched exactly as every rule there is, so `[consumer] headers = "netlify"` writes them into `_headers`, and `astro dev` sends the header itself. Nothing else in the build's outputs changes. A product fetches from its own line's folder, uses an answer only when its `line` is the bundled file's, and falls back to the bundled copy offline, on any error, and when its line is gone (output-layout contract §1.4 and §1.7, the integration's reference, and the embedded help page). _Why:_ a permalink's own address leads to the current line, so a product on 3.4 fetching `go/<name>` would show 3.5's text; the line in the path keeps each release to its own docs, and an entry at a time costs a product one small request. The text is already public, so any origin may read it. _From:_ the maintainer's [embedded help plan](../embedded-help/README.md), phase 5, built in #882.
