section: The binary
---

**The VS Code extension ships Ascribe's skill to VS Code's chat, and offers it only while no workspace folder has a copy chat loads.** Its `chatSkills` entry is `./dist/skills/ascribe/SKILL.md`, in the extension's package,, with `when: ascribe.active && !ascribe.agentsSynced`. The extension sets `ascribe.agentsSynced` only for a copy in a folder chat loads skills from: `.github/skills/ascribe/`, `.claude/skills/ascribe/`, or `.agents/skills/ascribe/` at the top of a workspace folder, which takes in both of `ascribe agents sync`'s, and it watches them, so creating or deleting a copy sets the key again. The shipped copy is built from `packages/cli/skills/ascribe/`, the skill's one home, and `scripts/release/pack.ts` fails a `.vsix` whose copy differs. The rules aren't shipped: they're made from a project's content model, so they stay with `sync` and the MCP server's `ascribe://instructions/{+project}`. The extension writes nothing into a project. _Why:_ a project that never ran `sync` gets the skill, and chat never has two copies or none; it writes nothing, so the editor still sets up no agent files. _From:_ the maintainer, on the editor's views plan ([README](https://github.com/ascribed-dev/ascribe/blob/395fe80d/project-docs/editor-ui/README.md), decisions 8 and 16) and its [proposal](https://github.com/ascribed-dev/ascribe/blob/395fe80d/project-docs/proposals/editor-ui.md#settled), settled 16 October 2026; shipped in [#591](https://github.com/ascribed-dev/ascribe/pull/591), 17 October 2026; recorded when the plan closed, with [#544](https://github.com/ascribed-dev/ascribe/issues/544).
