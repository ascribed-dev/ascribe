section: The binary
---

**Each build writes `_ascribe/redirects.json` in its site output (output-layout contract §1.8), and with `[consumer] host = "netlify"` Netlify's `_redirects` and `_headers` in `_ascribe/host/` (§1.9), which `@ascribed/astro` places at the built site's root.** `redirects.json` comes from `ascribe.addresses` alone, never the base, so a redirect stays once the base has moved past the move: a `301` for each address a `[moved]` key had, the page's and its Markdown version's, to the value's, flat, leaving out a pair whose `from` is live or equals its `to` once case and a final `/` are ignored, and an id's entry, which no host sees; `gone` for each `[retired]` key's. `[consumer] headers` is replaced by `host` (content-model contract §15), and is `model-unknown-key` with the message `consumer-headers`, which names `host`. The integration reads the host's files, not the JSON: it merges every project's, keeps a site's own `public/_redirects` after Ascribe's rules, fails the build when a redirect's address is a page the site publishes, and under an Astro `base` that isn't `/` prints the lines. This supersedes the search and answers plan's decisions 9 and 35, which had the integration write `_headers` from `headers.json` for `[consumer] headers`. _Why:_ the compiler writing the host's files gives a site built without Astro the same files to copy, and Netlify uses the first rule that matches, so Ascribe's go first (decision #904). _From:_ [#905](https://github.com/ascribed-dev/ascribe/issues/905), [redirects, phase 1](https://github.com/ascribed-dev/ascribe/blob/9162c25a/project-docs/redirects/phase-1-thread.md), tasks 7 and 8, on [decision #904](904-redirects-formats.md), 25 October 2026.
