---
section: The language
---

**A term is linked to its heading on the first page in `[glossary] pages` that a build publishes, and never on a glossary page that shows it.** A heading that two glossary pages show, through a fragment they both include, is one term, not a duplicate, and the order of `pages` chooses where a build that publishes both links it; two different headings with the same text are still `glossary-term-duplicate`. A build that publishes none of a term's glossary pages doesn't link it. On a glossary page that shows a term, neither an occurrence nor an author's link to the term's heading is the term's: the link stays as written. Matching is in prose only, never in headings, link text, code, or raw HTML. Where a term is linked only at its first occurrence (`match = "first"`), an author's link to its heading counts as that occurrence, so no later one on the page is linked. _Why:_ one source is one term, so a glossary split by product writes its shared terms once, and `pages` is already in the order a project chose; a page that defines a term has nothing to link it to; and a reader sees a term's link once on a page, whoever wrote it. _From:_ the maintainer, on the glossary pages plan ([README](https://github.com/ascribed-dev/ascribe/blob/395fe80d/project-docs/glossary-pages/README.md) decisions 11, 16, and 21; [phase 1](https://github.com/ascribed-dev/ascribe/blob/395fe80d/project-docs/glossary-pages/phase-1-decisions.md) decisions 2 and 7), 14 to 16 October 2026; recorded when the plan closed, with [#548](https://github.com/ascribed-dev/ascribe/issues/548).
