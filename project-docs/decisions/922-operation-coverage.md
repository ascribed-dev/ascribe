section: The language
---

**An operation of a declared spec that no link names, by its `operationId` or by its method and path, is advice, `api-operation-unreferenced` (ASC282), a content check in area `project`, reported once for each operation at the API's `spec` in `ascribe.toml`; an operation the spec marks `deprecated` isn't reported.** A link in any page or fragment counts, in the text or as an `@operation`'s, from the source index, so the answer holds for every build, as `fragment-unused`'s does; a word in prose that matches an id doesn't, and a link to a missing operation covers none. Its next step is `write`, not `review`, so it has no `[[intended]]` place: a team that doesn't mean to cover an API from guides turns it off in `[checks]`. `ascribe report inventory` gains, for each API whose spec was read, its operations, how many a link names, and how many a checked example claims (`examples`, zero until checked examples are built), as `inventory.apis` in the report's JSON: a field added, which decision 4 allows without a new schema version, and absent when the project declares no API. _Why:_ a spec grows faster than its guides, and an endpoint shipped without one should show in the next check; a deprecated operation is on its way out, and needs no guide. _From:_ [#922](https://github.com/ascribed-dev/ascribe/issues/922), [OpenAPI, phase 6](../openapi/phase-6-coverage.md), 25 October 2026.
