section: The binary
---

**The editor, review, and the tools take a line as the build it is, and show a page the lines share once.** The editor checks every line of a versioned `[editor] build`, its own line first, and a problem only some lines have ends "(only in build `site@3.4`)"; diagnostics don't follow the line chosen in the build lens, which the plan's phase 6 had asked for. `ascribe/targets` and `ascribe/preview` list a versioned build's lines under it as `lines`, each with `name`, `line`, and `current`, the current line first, and a build that isn't versioned has none; a client's picker offers each line as a build, by its name. A line's page is rendered under the line's folder wherever it's drawn: `ascribe render`, `ascribe_render`, the preview, and the review report give `/3.4/install/`, with the line's links. `ascribe diff`'s JSON keeps a line as a build of its own, its pages' routes under its folder; its text lists a versioned build's lines together, each changed page once, with "in every line" or the lines it changed in; the report's data gives each build its `line`, and the report lists the page once, with a switch between its lines. `ascribe model` has a `releases` section, before `builds`: each target's lines, newest first, with `status` and the builds that are each, and a versioned build gains `versions` and `line`. A hover on a version in a mark says the line it's in and its status, and nothing for a version older than every declared line; a hover on `replaces` says which page each line publishes, and Go to Definition opens the replaced page. _Why:_ the language server doesn't know what a client chose, and the Problems panel would change with a picker, while every line is what `ascribe check` reports, so the editor agrees with CI; a line is already a build everywhere a name is taken, so the lens, the preview, and `[editor] build` need nothing new; an older line's route without its folder is an address no site has; the JSON says what each output publishes, which a reader compares line by line, while a person reads a page once; the agent that writes a mark needs the lines it can name; and a version before every line is shown as the target alone, which a hover on every old mark would only repeat. _From:_ the maintainer, on the [versions plan](https://github.com/ascribed-dev/ascribe/blob/395fe80d/project-docs/versions/README.md), decisions 61 to 66, confirmed with [#514](https://github.com/ascribed-dev/ascribe/pull/514), 16 October 2026; recorded when the plan closed, with [#502](https://github.com/ascribed-dev/ascribe/issues/502).
