section: The language
---

**Three defaults change, each a row of the settings registry: a source always leaves out `node_modules` and `.git` folders; `[consumer] agents` is `true` when `site` is set and `false` when it isn't; and `prose-not-checked` is reported only where the project asked for prose checks everywhere.** A source's files in a folder named `node_modules` or `.git`, at any depth, are never readable, before and whatever its own `ignore` lists; the registry's default for `ignore` is the two patterns, `**/node_modules/**` and `**/.git/**`, applied always rather than in place of the key, and `ascribe model` shows a source's own patterns only. An `agents` left out follows `site`; an explicit `agents = true` without `site` is still `model-consumer-agents-site`, and an explicit `false` turns the outputs off. A project that never set `agents` and has a `site` now publishes `llms.txt`, each page's Markdown laid out by route with its files under `_ascribe/files/`, and the pointer on each page, so its plain output and its site output change: the comparison's `outputs changed` block in the pull request accepts them. `prose-not-checked` is said by `ascribe check` with `--vale`, and by anything that checks with `[checks.vale] in-check = true`; the language server, which runs Vale on open and save whenever there's `[checks.vale]`, drops it without `in-check` (`ascribe_check::prose::said`). SPEC §7.3, §9.4, and §9.5, the content model's contracts for `[consumer]` and `[checks.vale]`, and the reference's tables say so. The docs' `ascribe.toml` drops its `ignore`, its `agents = true`, and its `prose-not-checked = "off"`, which the new defaults make what it already said, and the landing site's drops its `ignore`. _Why:_ no project wants a dependency folder or a repository's own database readable as code examples; Ascribe's position is docs that agents read, and the Markdown is the page's own text, already public, but its links need the site's origin (SPEC §9.4), so without a site the default stays `false` and nothing new is reported; and a machine without Vale isn't one a project that checks prose only in the editor or in CI asked to check. _From:_ [#812](https://github.com/ascribed-dev/ascribe/issues/812), piece 4 of the [shorter content model proposal](../proposals/shorter-content-model.md#4-defaults-that-change), with its Settled 2 answered by the maintainer on 21 October 2026.
