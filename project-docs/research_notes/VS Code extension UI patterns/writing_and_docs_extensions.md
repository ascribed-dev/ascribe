# UI patterns of VS Code extensions for documentation, writing, content management, and knowledge bases

Research date: 2026-10-16. Scope: Foam, Dendron, Markdown All in One, Markdown Preview Enhanced (MPE), Front Matter CMS, Mintlify, Learn Authoring Pack (Microsoft Learn), AsciiDoc, Esbonio, Quarto, MyST, Vale, LTeX/LTeX+, Code Spell Checker, Grammarly-style, markdownlint, Mermaid extensions. Several sources were fetched through a summarizing tool, so quotes are as that tool reported them; where a source page didn't cover a point, it's listed under Gaps.

Status markers used below: **ACTIVE** (releases in 2025–2026 seen), **MAINTENANCE** (no active development), **ARCHIVED/DEAD**.

## Key question 1: Which VS Code surfaces does each extension use (sidebars and tree views, webviews and previews, custom editors, dashboards, hovers, CodeLens, decorations, status bar, quick picks, walkthroughs)?

### Takeaway
The extensions that last put persistent, structured browsing in **native tree views in their own activity-bar container**: Foam (Connections, Tags, Placeholders, Orphans, Smart Folders, Notes Explorer) and Dendron (Tree, Backlinks, Calendar, Lookup). Rich or visual work goes in **webviews**: graphs, the Front Matter dashboard and panel, previews. Checking extensions (markdownlint, cspell, Vale, LTeX+) use only **diagnostics + quick fixes + Problems panel**, and at most one status bar item. One finding comes up again and again: big status-bar toolbars were removed (Microsoft's "Gauntlet" toolbar), and **command menus moved into a single quick pick** (Learn's Alt+M menu).

### Cited Findings

**Foam** (ACTIVE; changelog runs to 0.46.0)
- README lists a Backlinks panel ("notes that reference the active note, with the context of each reference and a preview"), a Tag Explorer panel (hierarchical tags), Orphans and Placeholders panels ("Orphans are notes that have no inbound nor outbound links"; placeholders are dangling links), and a `Foam: Show Graph` command — [Foam README](https://github.com/foambubble/foam)
- Editor-side integration goes through native language features rather than custom UI: link previews on hover, go-to-definition, peek references, wikilink autocompletion (including placeholders, section links, aliases, minimal unique identifiers), rename-updates-links, syntax highlighting that tells wikilinks from placeholders, and diagnostics for ambiguous wikilinks — [Foam README](https://github.com/foambubble/foam)
- Recent view additions: "the new Smart Folders panel lets you view a subset of your notes via saved filters" (0.44.0); "Various improvements to notes explorer, including filtering" (0.36.0); the Connections panel gained a toggle between all connections and notes-only, and its commands, icons, and sorting were consolidated (0.44.1) — [Foam CHANGELOG](https://raw.githubusercontent.com/foambubble/foam/main/packages/foam-vscode/CHANGELOG.md)
- Hover previews are cached (0.44.4), and "command links in hover tooltips" were limited to an allowlist (0.44.6). Decorations: clickable link ranges now match VS Code's markdown styling, "Wikilinks no longer include the surrounding brackets" (0.44.5) — [Foam CHANGELOG](https://raw.githubusercontent.com/foambubble/foam/main/packages/foam-vscode/CHANGELOG.md)
- Foam became a web extension in 0.26.0 (late 2024) — [Foam CHANGELOG](https://raw.githubusercontent.com/foambubble/foam/main/packages/foam-vscode/CHANGELOG.md)

**Dendron** (MAINTENANCE since Feb 2023)
- README: "Dendron is currently in maintenace only, active development has ceased." Features listed: Lookup ("one combined way to find and create notes"), backlinks, graph view — [Dendron README](https://github.com/dendronhq/dendron)
- Lookup is a quick pick that both finds and creates notes. Keywords match in any order (`rename dendron` matches `dendron.dev.design.commands.rename`), fuzzy matching uses fuse.js, ties sort by last updated time, and `Tab` autocompletes one hierarchy level at a time — [Dendron Lookup docs](https://wiki.dendron.so/notes/a7c3a810-28c8-4b47-96a6-8156b1524af3/)
- Schemas give "autocomplete hints when creating new notes" and "automatically apply common templates to notes on creation" — [Dendron wiki](https://wiki.dendron.so/notes/0bjhqk8bkikfsl4eobcj2r2/)
- Tree view history (from search snippets of Dendron's docs, not fetched in full): a 2021 design note proposed a webview tree because the native tree view "limits customization ... and makes certain features like drag-and-drop impossible". Release 0.93 then "removes web view version of tree view, as well as the enableWebUI feature flag" and added a Dendron side bar container holding Tree View, Backlinks, Calendar View, and Lookup View. Some developer docs still describe a `DendronTreeViewV2` webview provider, so the sources conflict — [Dendron "Better Tree View"](https://docs.dendron.so/notes/ba8cf4c5-6254-4eca-8072-8001ca5afda7), [Dendron "Tree Webview"](https://docs.dendron.so/notes/56duiQ7JImvrplRYK6lt4)

**Front Matter CMS** (ACTIVE but the maintainer has cut back; see Q4)
- The editor panel opens from its own activity bar icon. Its sections: **SEO status** (title ≤60, description ≤160, slug ≤75, article length 1760 words by default; `-1` disables a check), **Content Health** (Flesch Reading Ease, broken internal links, optional external link check, freshness warning after 180 days, Copilot quick fixes for long sentences), **Actions** (optimize slug, set publish and modified dates, publish or revert to draft; hidden via `frontMatter.panel.actions.disabled`), **Metadata** (front matter form driven by content types; tag and category pickers show "+" to add unknown values to the config; YAML/TOML/JSON), **Content type actions** (when front matter doesn't match a type: create a type, add missing fields, or set an existing type), **Recently modified** (latest 10), **Other actions**, and Global settings (hidden by default). "View modes" choose which panel sections show (`panel.seo`, `panel.metadata`, `panel.contentHealth`) — [Front Matter panel docs](https://frontmatter.codes/docs/panel)
- The dashboard is a set of views, each opened by a command: `frontMatter.dashboard` (Contents, the default), `.media`, `.snippets`, `.data`, `.taxonomy` — [Front Matter dashboard docs](https://frontmatter.codes/docs/dashboard)
- Content view: configurable cards (`title`, `description`, `state`, `date`, tags from `frontMatter.dashboard.content.cardTags`); filters by content folder, tags, categories, and custom front matter fields; draft/published status filter (custom draft field supported); sorting (Last modified, Filename, custom by `string`/`date`/`number`); grouping (Year, Draft, custom); pagination of 16 items by default; pinning; an "Open on startup?" checkbox per project; custom card UI through a "UI extensibility library" — [Front Matter content view docs](https://frontmatter.codes/docs/dashboard/content-view)

**Markdown Preview Enhanced** (ACTIVE; releases through 0.8.30, 2026-06-08)
- Preview modes: `previewMode` = Single Preview, Multiple Previews, or Previews Only. Previews Only is a beta in-preview editor that "will automatically modify the `workbench.editorAssociations` setting", so it acts as a custom editor (0.8.0, 2023-10-05) — [MPE CHANGELOG](https://raw.githubusercontent.com/shd101wyy/vscode-markdown-preview-enhanced/master/CHANGELOG.md)
- Preview lock commands "lock a preview to a specific file so it doesn't switch when the active editor changes" (0.8.25, 2026-05-05) — [MPE CHANGELOG](https://raw.githubusercontent.com/shd101wyy/vscode-markdown-preview-enhanced/master/CHANGELOG.md)
- A sidebar TOC inside the preview webview is "resizable via drag handle, persistent width", with collapsible sections (0.8.24, 2026-04-21) — [MPE CHANGELOG](https://raw.githubusercontent.com/shd101wyy/vscode-markdown-preview-enhanced/master/CHANGELOG.md)
- An "Obsidian-style interactive note graph" with Global/Local modes (0.8.23, 2026-04-19); All/Direct/Front/Back filters on the local graph (0.8.27); backlinks shown in the preview by "Clicking the bottom right link icon" (0.7.4, 2023) — [MPE CHANGELOG](https://raw.githubusercontent.com/shd101wyy/vscode-markdown-preview-enhanced/master/CHANGELOG.md)
- "VS Code" theme options for the preview, code block, and Reveal.js themes; zoom controls; an image lightbox; `useVSCodeThemeForContextMenu` (0.8.24–0.8.25) — [MPE CHANGELOG](https://raw.githubusercontent.com/shd101wyy/vscode-markdown-preview-enhanced/master/CHANGELOG.md)

**Learn Authoring Pack (Microsoft Learn)** (ACTIVE as a pack; guide updated 2024-03)
- A bundle of seven extensions: Learn Markdown, markdownlint, Code Spell Checker, Learn Preview (renders with Learn's CSS, including custom Markdown), Learn Article Templates, Learn YAML (schema validation), Learn Images (compression) — [Microsoft Learn contributor guide](https://learn.microsoft.com/en-us/contribute/content/how-to-write-docs-auth-pack)
- **Alt+M opens a single quick pick menu** of authoring commands: insert link, image, include, snippet, alert, template, and so on. You type to filter, then Enter — [Microsoft Learn contributor guide](https://learn.microsoft.com/en-us/contribute/content/how-to-write-docs-auth-pack)
- The legacy "Gauntlet" toolbar in the status bar was deprecated "because the toolbar took up a large space on the VS Code status bar and did not follow best practices for extension UX". It can be turned back on in settings, but "Newer commands added to the extension will not be available from the toolbar." — [Microsoft Learn contributor guide](https://learn.microsoft.com/en-us/contribute/content/how-to-write-docs-auth-pack)
- Other surfaces: an "Update ms.date Metadata Value" context-menu item; completion of code-fence language identifiers with warnings and auto-correction for unrecognized ones; a "Learn: Generate main redirection file" command whose results go to the Output pane — [Microsoft Learn contributor guide](https://learn.microsoft.com/en-us/contribute/content/how-to-write-docs-auth-pack)
- Insert link/image works only when the workspace is scoped to the root of the cloned repo. Custom Markdown "will not render correctly unless published" — [Microsoft Learn contributor guide](https://learn.microsoft.com/en-us/contribute/content/how-to-write-docs-auth-pack)

**Quarto** (ACTIVE)
- **Quarto: Preview** (Ctrl+Shift+K, or a Preview button at the top right of the editor) opens a side-by-side preview in VS Code for HTML and PDF formats; Word and other formats open in external programs. The **Preview Type** setting is internal, external, or none. Render on Save is off by default — [Quarto VS Code docs](https://quarto.org/docs/tools/vscode/index.html)
- **Quarto: Render Document** offers the declared formats in a quick pick. There's a WYSIWYG **Visual Editor** for `.qmd`, and an **Assist Panel** in the sidebar shows contextual help, a live LaTeX equation preview, and image thumbnails when the cursor is on a markdown image. Live preview of math and Mermaid/Graphviz diagrams updates as you type (Ctrl+Shift+L) — [Quarto VS Code docs](https://quarto.org/docs/tools/vscode/index.html)
- YAML intelligence completes project files, front matter, and cell options, and invalid YAML is underlined "when documents are saved". The Outline view lists headers, and Ctrl+T searches headings across the workspace — [Quarto VS Code docs](https://quarto.org/docs/tools/vscode/index.html)

**Esbonio (Sphinx)** (ACTIVE; v1/v2 migrations documented)
- The language server "resolv[es] references, provid[es] completion suggestions and highlight[s] errors", and live previews keep "your local build ... always up to date" — [Esbonio docs](https://docs.esbon.io/en/latest/)
- The preview protocol: the client calls `esbonio.server.previewFile`, and the server returns a localhost URL or sends `window/showDocument` to open it "in your web browser". The editor sends `view/scroll` with the top visible line, and the preview scrolls the editor back only if the client supports the `selection` field of `showDocument`. "The preview will automatically reload each time a Sphinx build completes." Previews work only for HTML builders — [Esbonio previews](https://docs.esbon.io/en/latest/integrating/previews.html)

**Mintlify** (ACTIVE; extension `mintlify.mintlify-snippets`, launched March 2024)
- Live preview inside the editor (needs the Mintlify CLI and a valid `docs.json`). Autocomplete for built-in components and imported snippet components. **Hovering over a snippet component previews the snippet file's contents.** Diagnostics for unresolved snippet imports and unknown components, which `mintlify.diagnostics.enabled` turns off. The launch post described "Surround" snippets that wrap content in components such as CardGroup and CodeGroup — [Mintlify MDX extension docs](https://www.mintlify.com/docs/cli/mdx-extension), [Mintlify launch post](https://www.mintlify.com/blog/mdx-vscode-extension)

**AsciiDoc** (ACTIVE)
- "live preview, syntax highlighting, and snippets for the AsciiDoc format using Asciidoctor". Full docs live at docs.asciidoctor.org/vscode-extension — [asciidoctor-vscode README](https://github.com/asciidoctor/asciidoctor-vscode)

**Markdown All in One** (ACTIVE-ish; 447 open issues at fetch time)
- Mostly keybindings and editor commands, with no views of its own: bold/italic/strikethrough, heading level up/down, task toggle (Alt+C), "Create Table of Contents" ("automatically updated on file save by default", `<!-- omit from toc -->`), section numbers, list continuation and auto-renumbering, table formatter, print to HTML, completion of paths, math functions, and reference links. Preview is VS Code's built-in one — [Markdown All in One README](https://github.com/yzhang-gh/vscode-markdown)

**Checkers: markdownlint, Code Spell Checker, Vale, LTeX+**
- markdownlint: violations show as warnings ("wavy green underline") and in Problems. Severity can be remapped with `markdownlint.severityForError` / `severityForWarning` (Error/Warning/Information/Hint/Ignore). Quick fixes for about 35 auto-fixable rules; clicking a warning in the quick-fix dialog opens the rule's help. It registers as a **formatter** and has a `source.fixAll.markdownlint` code action on save. `markdownlint.lintWorkspace` runs the CLI in a terminal and feeds Problems through a problem matcher. **`markdownlint.focusMode`** hides issues on the cursor's line, or N lines around it. There's a toggle-linting command. No status bar item — [vscode-markdownlint README](https://github.com/DavidAnson/vscode-markdownlint)
- Code Spell Checker: diagnostics at **Information by default** (`cSpell.diagnosticLevel`; "Hint" stays out of Problems). The lightbulb offers suggestions and "the option to add the word". **Clicking the status bar item opens an "Info screen"** where checking can be turned on per file type — [cspell Marketplace](https://marketplace.visualstudio.com/items?itemName=streetsidesoftware.code-spell-checker)
- Vale VS Code: a "Detailed Problems View" (file location, style, rule ID), a "View Rule" action that jumps to the rule's implementation in `StylesPath`, and quick fixes through code actions when the rule implements one ("Spelling errors are not currently supported") — [vale-vscode README](https://github.com/errata-ai/vale-vscode)
- LTeX+: "Issue highlighting with hover description", "Replacement suggestions via quick fixes", server commands `_ltex.addToDictionary`, `_ltex.disableRules`, `_ltex.hideFalsePositives`, a "Check All Documents in Workspace" command, and an `ltex.statusBarItem` setting — [vscode-ltex-plus README](https://github.com/ltex-plus/vscode-ltex-plus)

**Mermaid/diagram extensions**
- The official Mermaid Chart extension shows diagrams from the Mermaid Chart service in an **explorer tree view**; clicking a diagram inserts it at the cursor, with links to view it in a VS Code tab or edit it in the browser. It needs an account (free tier: 5 diagrams) — [vscode-mermaid-chart](https://github.com/Mermaid-Chart/vscode-mermaid-chart/)
- A separate local preview extension detects diagrams in markdown code blocks and `.mmd` files and follows the VS Code theme by default — [vscode-mermaid-preview](https://github.com/mermaid-chart/vscode-mermaid-preview)
- mjbvz's vscode-markdown-mermaid extends **the built-in Markdown preview** rather than adding its own, with zoom, pan, and resize controls for large diagrams — [vscode-markdown-mermaid (via Algolia DocSearch index)](https://docsearch.algolia.com/mcp/docs/repo/mjbvz/vscode-markdown-mermaid)

### Inferences
- Two families appear. **Contributors to native surfaces** (Foam, Markdown All in One, markdownlint, cspell, Vale, LTeX+, vscode-markdown-mermaid) feel like part of VS Code and age well. **Webview apps** (Front Matter dashboard, MPE, the graphs, Dendron's old webview tree) can do more but have to re-create theming, keyboard handling, and state. Dendron going back to a native tree and MPE adding "VS Code" theme options both suggest webviews drift from the editor's look.
- Learn's Alt+M quick pick, which replaced a status bar toolbar, is a sign for Ascribe: insertion of directives, phrases, and glossary terms fits better in one filterable quick pick plus completions than in toolbars.
- Checkers converge on: Problems panel diagnostics, lightbulb quick fixes, adjustable severity, "go to rule" or "rule docs" links, fix-all on save, and a workspace-wide check command. Ascribe's checks can take these over directly. markdownlint's focus mode (no squiggles on the line being typed) is a cheap fix for noise.
- Mintlify's hover-preview of a snippet's content maps directly onto Ascribe phrases, glossary terms, and includes (hover a `{phrase}` key to see its resolved text per variant).

### Gaps
- Walkthroughs (`contributes.walkthroughs`): no source found showing that any of these extensions ships a Getting Started walkthrough. Not checked per Marketplace page.
- CodeLens: none of the fetched sources reports CodeLens in these writing extensions. Quarto's docs list cell-running commands but don't mention CodeLens. Not confirmed either way.
- AsciiDoc's sync-scroll, Antora, and preview-security details: the docs page returned 404, so they aren't covered.
- MyST VS Code (`jupyter-book/myst-vs-code`): the repo URL returned 404, so its current status and features are unverified.
- Whether Front Matter's panel and dashboard are webviews isn't stated in the fetched docs (it's widely understood to be React-in-webview, but no source was fetched).

## Key question 2: How do they show backlinks, outlines, graphs, tag/taxonomy browsers, content dashboards, frontmatter editing, snippet/fragment insertion, and synchronized preview scrolling?

### Takeaway
Backlinks live in a **sidebar tree that follows the active editor** (Foam's Connections, Dendron's Backlinks) or, in MPE, inside the preview. Graphs are always **webviews** with heavy controls (color modes, filters, local/global views). Taxonomy lives in a tag tree (Foam) or a dashboard view (Front Matter). Front matter is edited in a **form panel generated from content types**, with "add to config" affordances and schema-mismatch fixes. Snippet insertion uses **parameterized templates with a fields form**. Synchronized scroll is editor→preview by visible top line; preview→editor is best-effort and can fight the user.

### Cited Findings
- **Backlinks**: Foam's panel lists referencing notes "with the context of each reference and a preview" — [Foam README](https://github.com/foambubble/foam). Its Connections panel toggles between all connections and notes-only (0.44.1), and related notes, placeholders, and graph got "improved active-editor detection" so they track the right note (0.44.0) — [Foam CHANGELOG](https://raw.githubusercontent.com/foambubble/foam/main/packages/foam-vscode/CHANGELOG.md). MPE shows backlinks in the preview via a bottom-right link icon (0.7.4) — [MPE CHANGELOG](https://raw.githubusercontent.com/shd101wyy/vscode-markdown-preview-enhanced/master/CHANGELOG.md)
- **Graphs**: Foam's graph kept gaining controls: "Tag hierarchy now visible in graph" (0.26.8, 2025-03), node color mode dropdown with appearance, forces, and selection panels (0.29.2), color-by-type as default (0.35.0), "Rework graph view controls panel" (0.37.0), node groups (0.38.0), a standalone `foam-graph` component with graph focus and a backlink panel (0.39.0), and an option to show the graph on startup (0.29.1) — [Foam CHANGELOG](https://raw.githubusercontent.com/foambubble/foam/main/packages/foam-vscode/CHANGELOG.md). MPE added a Global/Local graph with All/Direct/Front/Back filters in 2026 — [MPE CHANGELOG](https://raw.githubusercontent.com/shd101wyy/vscode-markdown-preview-enhanced/master/CHANGELOG.md)
- **Tags/taxonomy**: Foam's Tag Explorer supports hierarchical tags. Links in tags navigate to the matching Tag Explorer item (0.26.6), and "tag navigation and peek" was added (0.28.0) — [Foam CHANGELOG](https://raw.githubusercontent.com/foambubble/foam/main/packages/foam-vscode/CHANGELOG.md). Front Matter has a dedicated taxonomy dashboard view (`frontMatter.dashboard.taxonomy`) — [Front Matter dashboard docs](https://frontmatter.codes/docs/dashboard). Once a project is initialized, tags and categories move into `.frontmatter/database/taxonomyDb.json` — [Front Matter settings](https://frontmatter.codes/docs/settings/overview)
- **Saved filters as a view**: Foam's Smart Folders panel shows "a subset of your notes via saved filters" — [Foam CHANGELOG](https://raw.githubusercontent.com/foambubble/foam/main/packages/foam-vscode/CHANGELOG.md)
- **Content dashboard**: Front Matter's content view has cards, filters, sort, group, pagination, pinning, and default state per project (details under Q1) — [Front Matter content view docs](https://frontmatter.codes/docs/dashboard/content-view)
- **Frontmatter editing**: Front Matter's Metadata section is a form driven by content-type field definitions. Unknown tag and category values show "+" to add them to the configuration, and when a page doesn't match its content type, the panel offers to create a type, add missing fields, or set an existing type — [Front Matter panel docs](https://frontmatter.codes/docs/panel). Learn adds a context-menu action to update `ms.date`, and its templates fill `author`, `ms.author`, and `ms.date` from settings — [Microsoft Learn contributor guide](https://learn.microsoft.com/en-us/contribute/content/how-to-write-docs-auth-pack). Quarto validates front matter YAML with completions and underlines on save — [Quarto VS Code docs](https://quarto.org/docs/tools/vscode/index.html)
- **Snippet/fragment insertion**: Front Matter snippets have `[[placeholder]]` fields, typed `string` or `choice`. Defaults can use `{{year}}` or `FM_SELECTED_TEXT`. Insertion runs from an "Insert snippet" button or command and shows a form for the fields. **Inserted snippets are wrapped in `<!-- FM:Snippet:Start data:... -->` / `<!-- FM:Snippet:End -->` comments that record the snippet ID and field values**, so they can be edited again later (on by default). Media snippets are inserted from media cards — [Front Matter snippets docs](https://frontmatter.codes/docs/snippets). Learn inserts through its Alt+M quick pick and applies templates from a central GitHub repo of Markdown templates — [Microsoft Learn contributor guide](https://learn.microsoft.com/en-us/contribute/content/how-to-write-docs-auth-pack). Mintlify has component completion and Surround snippets — [Mintlify launch post](https://www.mintlify.com/blog/mdx-vscode-extension). Quarto has an Insert Snippet command, and snippet suggestions in IntelliSense are off by default — [Quarto VS Code docs](https://quarto.org/docs/tools/vscode/index.html)
- **Outline**: Quarto relies on VS Code's Outline view and symbol search (Ctrl+Shift+O, Ctrl+T across the workspace) — [Quarto VS Code docs](https://quarto.org/docs/tools/vscode/index.html). MPE puts a collapsible, resizable TOC sidebar inside the preview — [MPE CHANGELOG](https://raw.githubusercontent.com/shd101wyy/vscode-markdown-preview-enhanced/master/CHANGELOG.md). Markdown All in One writes the TOC into the document and updates it on save — [Markdown All in One README](https://github.com/yzhang-gh/vscode-markdown)
- **Synchronized scrolling**: Esbonio sends the editor's top visible line (`view/scroll`), and syncs preview→editor only if the client supports `showDocument` selection — [Esbonio previews](https://docs.esbon.io/en/latest/integrating/previews.html). MPE fixed scroll sync bugs and in 2026 made "User scroll now cancels any in-progress programmatic scroll animation immediately" (0.8.23) — [MPE CHANGELOG](https://raw.githubusercontent.com/shd101wyy/vscode-markdown-preview-enhanced/master/CHANGELOG.md). MPE 0.8.30 stopped "forcing the preview tab to the front when switching markdown files", leaving auto-reveal behind a setting that is off by default — [MPE CHANGELOG](https://raw.githubusercontent.com/shd101wyy/vscode-markdown-preview-enhanced/master/CHANGELOG.md)
- **Preview fidelity**: Learn Preview uses the real site's CSS for accuracy — [Microsoft Learn contributor guide](https://learn.microsoft.com/en-us/contribute/content/how-to-write-docs-auth-pack). Esbonio and Quarto show the real build output (Sphinx HTML, Quarto render) rather than an approximation — [Esbonio docs](https://docs.esbon.io/en/latest/), [Quarto VS Code docs](https://quarto.org/docs/tools/vscode/index.html). Mintlify's preview runs the Mintlify CLI — [Mintlify MDX extension docs](https://www.mintlify.com/docs/cli/mdx-extension)

### Inferences
- For Ascribe, the preview should come from the real compiler output (like Esbonio, Quarto, Mintlify, Learn Preview) rather than a markdown-it approximation, because custom syntax "will not render correctly" otherwise (Learn's own warning).
- Scroll sync and follow-the-editor behavior are where previews annoy people: auto-revealing tabs, scroll fighting. Defaults that come out of these fixes: editor→preview sync on, preview never steals focus, user scroll cancels programmatic scroll, and a "lock preview to this page" command.
- Front Matter's snippet wrapper comments are a workaround for Markdown having no structured fragments. Ascribe's `@` directives already are structured, so "edit this directive's fields" can work straight from the parse, through a CodeLens or quick pick, without marker comments.
- A content-model browser for Ascribe (phrases, glossary, features, dimensions/variants, note types, builds) matches Foam's tree views (Tag Explorer, Smart Folders) better than a Front Matter-style dashboard. A dashboard fits cross-page reports, such as pages by note type or status, or check results.
- Graph views keep pulling in feature work (colors, forces, groups, filters) without clear payoff for docs. They are most useful as a "local graph" of one page.

### Gaps
- Dendron's backlinks panel and Calendar view details weren't fetched beyond release-note snippets.
- No source measured how much people use graph views compared with backlinks panels.
- AsciiDoc's sync-scroll mechanics are uncovered (docs 404).

## Key question 3: How do they handle multi-root workspaces and many projects?

### Takeaway
Multi-root support is mostly an afterthought, added late or left to per-folder config files and `${workspaceFolder:name}` variables. Foam fixed multi-root templates only in 0.46.0. Front Matter added a `frontMatter.projects` list for several sites. Checkers find config relative to the file being checked, which handles many projects naturally.

### Cited Findings
- Foam 0.46.0: "The `new-note` and `daily-note` templates are found in any workspace folder, checked in order", and notes in folders renamed outside VS Code no longer "linger" — [Foam CHANGELOG](https://raw.githubusercontent.com/foambubble/foam/main/packages/foam-vscode/CHANGELOG.md). 0.46.0 also restored placeholders that had been hidden outside `foam.files.include` — same source.
- Front Matter: `frontMatter.projects` "Allows you to specify a list of projects you want to manage with Front Matter CMS," and each project can override global settings. `frontMatter.extends` takes paths or URLs that extend the config, and `frontMatter.config.dynamicFilePath` sets a config file used at init — [Front Matter settings](https://frontmatter.codes/docs/settings/overview). The content dashboard filters by content folder "when multiple are registered", and "Open on startup?" applies per project — [Front Matter content view docs](https://frontmatter.codes/docs/dashboard/content-view)
- Code Spell Checker: config precedence runs from the folder's `cspell.json` to `.vscode/cspell.json` to `.config/cspell.json` to VS Code settings. In multi-root it recommends `${workspaceFolder:client}/...` and warns `${workspaceFolder}` "might no[t work] as expected in a multi-root workspace". Relative paths resolve against the **first** folder — [cspell Marketplace](https://marketplace.visualstudio.com/items?itemName=streetsidesoftware.code-spell-checker)
- markdownlint: config files are found by directory hierarchy (`.markdownlint-cli2.*` beats `.markdownlint.*` in the same or parent directory), `${workspaceFolder}` in `configFile` "can be scoped per workspace folder", and `markdownlint.appliesTo` covers files inside or outside the workspace — [vscode-markdownlint README](https://github.com/DavidAnson/vscode-markdownlint)
- Vale: without `vale.valeCLI.config`, it uses the default `.vale.ini` search "relative to the current file". Settings accept `${workspaceFolder}` — [vale-vscode README](https://github.com/errata-ai/vale-vscode)
- Learn Markdown requires the workspace to be scoped to the root of the cloned repo for relative links and images — [Microsoft Learn contributor guide](https://learn.microsoft.com/en-us/contribute/content/how-to-write-docs-auth-pack)
- Esbonio has a "Sphinx Project Lookup" reference page for finding `conf.py`, but its contents weren't retrieved — [Esbonio docs](https://docs.esbon.io/en/latest/)

### Inferences
- Finding the project from the file (nearest `ascribe.toml` upward, the way markdownlint and Vale find config) is the pattern that handles both multi-root and many projects in one folder. Every project-scoped view (content model tree, preview, checks) then needs to show **which project it's showing**, with a switcher. Front Matter's `projects` list and per-project startup option are the closest precedent.
- Resolving relative to "the first folder" (cspell) is a known trap to avoid.

### Gaps
- No source showed a tree view that groups content by project in multi-root, or a project switcher UI, in these extensions.
- Esbonio's project discovery and Dendron's multi-vault UI weren't fetched.

## Key question 4: What do users praise or complain about, and which features were removed or redesigned and why?

### Takeaway
The removals and redesigns point one way: **less chrome, more native**. A status-bar toolbar was removed for breaking UX guidance (Learn). Dendron's webview tree went back to native. Previews stopped stealing focus and fighting scroll (MPE). Grammar backends died with their vendors (Grammarly SDK, Vale Server). Users praise "builds itself" link and graph features, and complain when the extension takes over the editor's layout. Projects that depend on one maintainer or one company stall (Dendron, Front Matter, Vale VS Code).

### Cited Findings
**Removals and redesigns**
- Learn's "Gauntlet" status-bar toolbar was deprecated because it "took up a large space on the VS Code status bar and did not follow best practices for extension UX", and the Alt+M quick pick replaced it — [Microsoft Learn contributor guide](https://learn.microsoft.com/en-us/contribute/content/how-to-write-docs-auth-pack)
- Dendron's tree view: a webview tree was proposed for drag-and-drop and customization, then "removes web view version of tree view, as well as the enableWebUI feature flag" in 0.93, with Tree, Backlinks, Calendar, and Lookup gathered into one Dendron sidebar container (from search snippets; conflicting dev docs exist) — [Dendron "Better Tree View"](https://docs.dendron.so/notes/ba8cf4c5-6254-4eca-8072-8001ca5afda7), [Dendron "Tree Webview"](https://docs.dendron.so/notes/56duiQ7JImvrplRYK6lt4)
- MPE: `singlePreview` was replaced by a three-way `previewMode` (2023). Anchor insertion was reverted "as it's causing a lot of problems". Transform hooks were removed because "these two caused the confusion". js-sequence-diagram and flowchart.js rendering were removed (2023). Forced preview reveal was removed in 2026 — [MPE CHANGELOG](https://raw.githubusercontent.com/shd101wyy/vscode-markdown-preview-enhanced/master/CHANGELOG.md)
- Foam consolidated Connections panel commands, icons, and sorting (0.44.1). It restored placeholders that were wrongly hidden (0.46.0), and added an option to turn footnotes off because the preview rendered "a second, empty footnotes section" (0.45.0) — [Foam CHANGELOG](https://raw.githubusercontent.com/foambubble/foam/main/packages/foam-vscode/CHANGELOG.md)
- Vale VS Code: "As of v0.15.0, the extension drops support for Vale Server which has ceased development". The repo was archived 2023-04-14, and development continues in a fork (ChrisChinchilla/vale-vscode) — [vale-vscode README](https://github.com/errata-ai/vale-vscode)
- LTeX lineage: "LTEX is a fork of the abandoned LanguageTool for Visual Studio Code extension", and "Until version 13.1.0, Julian Valentin developed LTEX+ as LTEX" (now ltex-plus) — [vscode-ltex-plus README](https://github.com/ltex-plus/vscode-ltex-plus)
- Grammarly: Grammarly discontinued its Text Editor SDK effective January 10, 2024 — [AlternativeTo news](https://alternativeto.net/news/2023/7/grammarly-to-discontinue-text-editor-sdk-shifts-focus-to-core-product-and-ai-integration/). znck's unofficial Grammarly packages are deprecated and archived — [notesolution/grammarly](https://github.com/notesolution/grammarly). That the extension broke *because* of the SDK shutdown is likely but not confirmed by a source.

**Project health**
- Dendron (announced Feb 2023): "Dendron, the extension, will no longer be actively developed ... maintenance mode". Reason: "not able to find product market fit for a venture backed business", plus burnout. The license moved to Apache 2.0 — [Dendron discussion #3890](https://github.com/dendronhq/dendron/discussions/3890)
- Front Matter's README says major changes depend on "personal motivation, company commitment, or significant community support" and the maintainer is shifting focus to other projects (via search summary) — [vscode-front-matter](https://github.com/estruyf/vscode-front-matter). Open dashboard issues include "dashboard fails to load", a request for a command bar on the contents and media dashboards, and custom scripts appearing only on the main dashboard — [ecosyste.ms OpenCollective issues](https://opencollective.ecosyste.ms/collectives/frontmatter/issues?page=2)

**User sentiment**
- Dendron users: "If dendron was built, not as an vscode extension but as a dedicated app, it would have been a success" (v3ss0n). "There is no other piece of software that I value more!" (djradon). "So far I can see no real active fork" (kbudde). In 2026 a user suggested Foam, and the reply was that Dendron "was better in the way it organize things" — [Dendron discussion #3890](https://github.com/dendronhq/dendron/discussions/3890)
- Foam with VS Code "constantly fucks up my tabs layout, closes the graph and ... is not as fluent" (compared with Obsidian and Notion). Another user: "I never manage to get into foam coming from Obsidian, possibly because I use VSCode/Codium for coding", and Dendron "didn't stick either" — [Lemmy thread (about 3 years old)](https://lemmy.linuxuserspace.show/comment/595556)
- A Hacker News commenter chose Foam for easy setup and a graph view that builds itself, and because it's fully open source (via search summary) — [HN thread mirror](https://brianlovin.com/hn/25760066)
- Code Spell Checker: 18,445,267 installs, 314 ratings averaging roughly 4.5 stars (read from the star graphic) — [cspell Marketplace](https://marketplace.visualstudio.com/items?itemName=streetsidesoftware.code-spell-checker)

### Inferences
- Tab and layout hijacking is the most specific complaint (Foam users; MPE's forced reveal, now removed). Ascribe's preview and graph-like views shouldn't open or reveal themselves without a request, and a webview shouldn't close when the layout changes.
- Running knowledge-base workflows inside a code editor puts off some writers (the Lemmy and Dendron comments). For Ascribe, whose users are docs-as-code writers in a repo anyway, that's less of a risk, but it argues for keeping the extension thin over the CLI and language server (as Esbonio, Vale, LTeX, and Mintlify do), so a lapse in the editor layer doesn't strand users the way Dendron's did.
- Grammar and style checkers that depended on a vendor service died with it. A local, offline engine (cspell, markdownlint, LTeX+'s bundled LanguageTool) is part of why they last.
