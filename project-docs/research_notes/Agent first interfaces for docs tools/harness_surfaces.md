# Extension surfaces that AI coding harnesses offer to third-party developer tools (state as of 2026-10-04)

Scope: Claude Code, GitHub Copilot (VS Code agent mode, Copilot CLI, cloud coding agent), Cursor, OpenAI Codex (CLI, app, cloud), Gemini CLI, Windsurf (now documented as "Devin Desktop" at docs.devin.ai), Amp, OpenCode, Zed's agent, JetBrains Junie. All official documentation below was fetched on 2026-10-04 unless marked otherwise. Items marked **[2025-era]** come from training knowledge or 2025 documentation and were not re-verified today; items marked **[third-party]** come from non-vendor sources.

Three cross-cutting facts that shape everything below:

- Documentation URLs moved for two vendors this year: OpenAI Codex docs redirect from `developers.openai.com/codex/*` to `learn.chatgpt.com/docs/*` (308), and Windsurf docs redirect from `docs.windsurf.com` to `docs.devin.ai/desktop/*` (307), where the product is called "Devin Desktop" and `.devin/` paths are preferred over legacy `.windsurf/` paths — [Codex redirect observed](https://developers.openai.com/codex/guides/agents-md); [Windsurf redirect observed](https://docs.windsurf.com/windsurf/cascade/memories); [Devin Desktop rules page](https://docs.devin.ai/desktop/cascade/memories).
- Two open standards now sit under most harnesses: **Agent Skills** (`SKILL.md`, agentskills.io) and **Agent Plugins 1.0** (root `plugin.json` + `skills/` + `mcp.json`, agent-plugins.org, TSC from Amazon, Cursor, Microsoft, OpenAI, Vercel) — [agentskills.io spec](https://agentskills.io/specification); [agent-plugins.org](https://agent-plugins.org/).
- **AGENTS.md** is stewarded by the Agentic AI Foundation under the Linux Foundation and lists Codex, Jules, Gemini CLI, Devin, Aider, goose, opencode, VS Code, Zed, Warp, JetBrains Junie, Cursor, UiPath, Amp, Factory, RooCode, Kilo Code, Phoenix, Semgrep, GitHub Copilot, Ona, Windsurf, Augment Code as supporters; Claude Code is not listed on agents.md but now reads AGENTS.md natively (see KQ1) — [agents.md](https://agents.md/).

## KQ0: Per-harness inventory of every plug-in mechanism (instruction files, skills, hooks, agents, commands, MCP config, plugins, styles)

### Takeaway
Every harness exposes four shared surface classes (instruction file, SKILL.md skills, MCP server config, custom agent persona), eight of ten have shell hooks, and six have a plugin/marketplace format; the file paths and field names differ per harness but Claude Code's paths (`.claude/skills`, `.claude/agents`, `.claude-plugin/plugin.json`, `.claude/settings.json` hooks) are read as compatibility fallbacks by Copilot/VS Code, Cursor, OpenCode, Amp, and Windsurf.

### Cited Findings

#### Claude Code
- Instruction files, load order broadest to narrowest: managed policy `/Library/Application Support/ClaudeCode/CLAUDE.md` (macOS), `/etc/claude-code/CLAUDE.md` (Linux/WSL), `C:\Program Files\ClaudeCode\CLAUDE.md` (Windows); user `~/.claude/CLAUDE.md`; project `./CLAUDE.md` or `./.claude/CLAUDE.md`; local `./CLAUDE.local.md` (gitignored). Files in the directory hierarchy above cwd load at launch; files in subdirectories load on demand when Claude reads files there — [Memory](https://code.claude.com/docs/en/memory)
- `@path/to/import` imports in CLAUDE.md: relative or absolute, resolved relative to the importing file, recursive to a maximum depth of four hops; parsing skips code spans and fenced blocks; paths with spaces need backslash escapes; imports resolving outside the working directory trigger a one-time approval dialog — [Memory](https://code.claude.com/docs/en/memory)
- `.claude/rules/*.md` (recursive) load at launch with the same priority as `.claude/CLAUDE.md`; a `paths:` frontmatter list of globs makes a rule load only when Claude works with matching files; `~/.claude/rules/` is user-level; symlinks supported; `claudeMdExcludes` setting (glob array, merges across layers) skips ancestor files; managed `claudeMd` key in `managed-settings.json` inlines org instructions — [Memory](https://code.claude.com/docs/en/memory)
- Block-level HTML comments in CLAUDE.md are stripped before injection (free maintainer notes) — [Memory](https://code.claude.com/docs/en/memory)
- Skills: `~/.claude/skills/<name>/SKILL.md`, `.claude/skills/<name>/SKILL.md`, enterprise managed-settings `.claude/skills/`, nested `<subdir>/.claude/skills/` (load when Claude first accesses files there), `--add-dir` dirs, plugin `<plugin>/skills/<name>/SKILL.md` (invoked `/plugin-name:skill-name`), and claude.ai-synced skills in `~/.claude/skills/synced/`. Legacy `.claude/commands/<name>.md` still works — [Skills](https://code.claude.com/docs/en/skills)
- Skill frontmatter: `name`, `description`, `when_to_use`, `disable-model-invocation`, `user-invocable`, `allowed-tools`, `disallowed-tools`, `argument-hint`, `arguments`, `model`, `effort`, `context: fork`, `agent`, `background`, `hooks`, `paths` (globs: auto-load only for matching files), `shell`, `metadata`, `license`, `compatibility`. Description + when_to_use capped at 1,536 chars. Substitutions: `$ARGUMENTS`, `$0..$N`, `$name`, `${CLAUDE_SKILL_DIR}`, `${CLAUDE_PROJECT_DIR}`, `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_PLUGIN_DATA}`, `${CLAUDE_SESSION_ID}`. Dynamic context via `` !`command` `` (2-minute timeout, non-zero exit aborts the skill). Skill content persists in context after invocation (not re-read) — [Skills](https://code.claude.com/docs/en/skills)
- Skill visibility overrides: `skillOverrides` setting with `on | name-only | user-invocable-only | off`; `/skill-doctor` reports context cost and unused skills (v2.1.252+); permission rules `Skill(name)` — [Skills](https://code.claude.com/docs/en/skills)
- Subagents: `.claude/agents/*.md`, `~/.claude/agents/*.md`, plugin `agents/`, `--agents` JSON flag, managed settings. Frontmatter: `name`, `description`, `tools`, `disallowedTools`, `model`, `permissionMode`, `maxTurns`, `skills` (preloaded), `memory: user|project|local`, `background`, `isolation: worktree`, `color`, `mcpServers` (inline or by reference), `hooks`, `initialPrompt`, `omitClaudeMd`, `effort`. Invoke by description-based delegation, `@agent-<name>` or `@agent-<plugin>:<name>` mention, or run the whole session as the agent with `claude --agent <name>` / `"agent"` setting — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Output styles: `~/.claude/output-styles/*.md`, `.claude/output-styles/*.md` (nested dirs up to repo root; closest wins), managed-settings `.claude/output-styles`, plugin `output-styles/<name>.md`. Frontmatter `name`, `description`, `keep-coding-instructions`, `force-for-plugin` (plugin applies its style automatically). Selected via `/output-style <name>` or `outputStyle` setting. Built-ins: Default, Proactive, Concise, Explanatory, Learning. Styles do not apply to subagents — [Output styles](https://code.claude.com/docs/en/output-styles)
- MCP config: local scope in `~/.claude.json` under `projects["/path"].mcpServers`; project scope `.mcp.json` at repo root with `mcpServers`; user scope top-level in `~/.claude.json`; plugin `.mcp.json` or manifest `mcpServers` (also accepts `.mcpb`/`.dxt` packaged servers); subagent frontmatter `mcpServers`; managed `managed-mcp.json` with `allowedMcpServers`, `deniedMcpServers`, `managedMcpServers`. Fields: `type: stdio|http|sse|ws|sdk`, `command`, `args`, `env`, `url`, `headers`, `headersHelper`, `timeout`, `oauth`. `${VAR}` and `${VAR:-default}` expansion. Settings `enableAllProjectMcpServers`, `enabledMcpjsonServers`, `disabledMcpjsonServers`. CLI `claude mcp add --scope project|user`, `claude mcp add-json`, `claude mcp add-from-claude-desktop` — [MCP](https://code.claude.com/docs/en/mcp)
- Plugins: manifest `.claude-plugin/plugin.json`; components `skills/<name>/SKILL.md` (or a single `SKILL.md` at plugin root), legacy `commands/<file>.md` (becomes `/<plugin>:<file>`; manifest `commands` key for alternate paths or inline content), `agents/*.md` (plugin agent files ignore `permissionMode`, `hooks`, `mcpServers`, `initialPrompt`), `hooks/hooks.json` (same shape as settings `hooks`; `modules` key for JavaScript hook modules = "mods"), `.mcp.json`, `.lsp.json` (LSP servers for diagnostics; manifest `lspServers`), `output-styles/<name>.md`, `settings.json` (only `agent` and `subagentStatusLine` keys honored), `userConfig` manifest key for user-supplied options (surfaced as `${user_config.*}` / `CLAUDE_PLUGIN_OPTION_<KEY>`), `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_PLUGIN_DATA}` (`~/.claude/plugins/data/<id>/`). Plugins with a top-level `bin/` are not installable on claude.ai/Cowork — [Plugin components](https://code.claude.com/docs/en/plugins/components)
- Hooks config locations: `~/.claude/settings.json`, `.claude/settings.json`, `.claude/settings.local.json`, managed policy settings, plugin `hooks/hooks.json`, skill frontmatter `hooks:`, subagent frontmatter `hooks:` — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Bundled skills include `/verify` ("Build and run app to confirm changes"), `/run`, `/code-review`, `/debug`, `/doctor`, `/loop`, `/batch`; `disableBundledSkills` turns them off — [Skills](https://code.claude.com/docs/en/skills)
- `/init` reads other tools' instruction files (`.github/copilot-instructions.md`; with `CLAUDE_CODE_NEW_INIT=1` also `AGENTS.md`, `.devin/rules/`, `.windsurf/rules/` or `.windsurfrules`, `.clinerules`) and folds them into the generated CLAUDE.md — [Memory](https://code.claude.com/docs/en/memory)

#### GitHub Copilot (VS Code agent mode, Copilot CLI, cloud coding agent)
- Repository instruction files: `.github/copilot-instructions.md` (repo-wide); `NAME.instructions.md` within or below `.github/instructions/` with `applyTo` glob frontmatter (comma-separated patterns, e.g. `"**/*.ts,**/*.tsx"`, `"src/**/*.py"`) and `excludeAgent: code-review | cloud-agent`; `AGENTS.md` at any depth with the nearest file taking precedence; alternatively a single `CLAUDE.md` or `GEMINI.md` at repo root. Precedence when several apply: personal > repository > organization, all are provided — [GitHub Docs: repository instructions](https://docs.github.com/en/copilot/how-tos/configure-custom-instructions/add-repository-instructions)
- Prompt files: `.github/prompts/*.prompt.md` and user profile; frontmatter `name`, `description`, `agent` (`ask|agent|plan|<custom>`), `model`, `tools` (supports `<server>/*`), `argument-hint`; invoked as `/name` with `key=value` args, `${input:var}` variables, `#file:` and `#tool:` references. "Prompt files are deprecated for Agent Host sessions and aren't loaded by Agent Host"; migration to agent skills is recommended. `chat.useCustomizationsInParentRepositories` enables monorepo parent discovery — [VS Code prompt files](https://code.visualstudio.com/docs/copilot/customization/prompt-files)
- Skills in VS Code: project `.github/skills/`, `.claude/skills/`, `.agents/skills/`; personal `~/.copilot/skills/`, `~/.claude/skills/`, `~/.agents/skills/`. Frontmatter `name`, `description`, `argument-hint`, `user-invocable`, `disable-model-invocation`, `context: fork`. Invoked automatically, via `/` picker, or `/skill-name`. `chat.agentSkillsLocations` is deprecated. Skills are stated to work in VS Code, Copilot CLI, the Copilot app, the Copilot cloud agent, and (experimental) OpenAI Codex through Agent Host — [VS Code agent skills](https://code.visualstudio.com/docs/copilot/customization/agent-skills)
- Custom agents in VS Code: `.github/agents/*.agent.md`, `.claude/agents/*.md` (Claude format; VS Code maps Claude tool names), user `~/.copilot/agents` or `~/.claude/agents`. Frontmatter `name`, `description`, `argument-hint`, `tools` (incl. `<server>/*`), `agents` (allowed subagents, `"*"` or `[]`), `model` (string or prioritized array), `user-invocable`, `disable-model-invocation`, `target: vscode | github-copilot`, `mcp-servers`, `handoffs` (`label`, `agent`, `prompt`, `send`, `model`), `hooks` (agent-scoped, preview), `infer` (deprecated). Legacy `.chatmode.md` files should be renamed `.agent.md`. Org agents discovered via `github.copilot.chat.organizationCustomAgents.enabled` — [VS Code custom agents](https://code.visualstudio.com/docs/copilot/customization/custom-agents)
- Custom agents on GitHub (cloud agent): repository `.github/agents/CUSTOM-AGENT-NAME.md`; organization `/agents/NAME.md` in the org's `.github` or `.github-private` repo; enterprise `/agents/NAME.md` in a designated org's `.github-private`. Fields documented: `name` (optional), `description` (required), `prompt` (required), `tools`, `mcp-servers`. Available via the Agents tab/panel, issue assignment, PRs; used by the cloud agent on github.com and in IDEs, the Copilot app, and Copilot CLI — [GitHub Docs: about custom agents](https://docs.github.com/en/copilot/concepts/agents/coding-agent/about-custom-agents)
- Hooks (VS Code Local harness): `.github/hooks/*.json`; Claude-format `.claude/settings.json` / `.claude/settings.local.json` / `~/.claude/settings.json` when `chat.useClaudeHooks` is set (Local "ignores matcher values, so every command for the event runs"); `~/.copilot/hooks/*.json`; `.agent.md` frontmatter `hooks`; plugin `hooks.json` or `hooks/hooks.json`; extra via `chat.hookFilesLocations`. Events: `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PreCompact`, `SubagentStart`, `SubagentStop`, `Stop`. Command fields `type: command`, `command`, `windows|linux|osx`, `timeout`, `env`, `cwd` — [VS Code hooks](https://code.visualstudio.com/docs/copilot/customization/hooks)
- Hooks (Copilot CLI and cloud agent reference): see KQ2 for the full event/field list — [GitHub Docs: hooks configuration](https://docs.github.com/en/copilot/reference/hooks-configuration)
- MCP config in VS Code: `.vscode/mcp.json` (`servers` object), portable `.mcp.json` (`mcpServers`), user profile mcp.json via **MCP: Open User Configuration**, `~/.copilot/mcp-config.json` or `$COPILOT_HOME/mcp-config.json` (`mcpServers`), Claude Desktop auto-discovery via `chat.mcp.discovery.enabled`, `devcontainer.json` `customizations.vscode.mcp`. Fields `type: stdio|http|sse`, `command`, `args`, `env`, `envFile`, `sandboxEnabled`. MCP prompts appear as `/<server>.<prompt>` — [VS Code MCP servers](https://code.visualstudio.com/docs/copilot/customization/mcp-servers)
- MCP config for the cloud coding agent: repository **Settings > Copilot > MCP servers** JSON (`mcpServers` → `type: local|stdio|http|sse`, `command`, `args`, `url`, `tools` (required allowlist, `"*"` for all), `env`, `headers`); secrets must be prefixed `COPILOT_MCP_` and are substituted as `$VAR`, `${VAR}`, `${VAR:-default}`; GitHub MCP server and Playwright MCP are on by default; remote OAuth servers unsupported; `.vscode/mcp.json` is not read directly ("switching from `inputs` to `env` and adding the required `tools` field") — [GitHub Docs: coding agent MCP](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/coding-agent/extend-coding-agent-with-mcp)

- Plugins (Copilot CLI): manifest at `plugin.json`, `.plugin/plugin.json`, `.github/plugin/plugin.json`, or `.claude-plugin/plugin.json` (Agent Plugins 1.0 `$schema` takes precedence); legacy manifest keys `agents`, `skills`, `commands`, `hooks`, `mcpServers`, `lspServers`; directories `skills/`, `agents/*.agent.md`, `hooks/hooks.json` or `hooks.json`, `.mcp.json` or `mcp.json`, `com.github.copilot/` namespace for Agent Plugins; marketplace `marketplace.json` in `.github/plugin/` or `.claude-plugin/` with `name`, `owner`, `plugins[]{name, source, ...}`; install `copilot plugin install plugin@marketplace`, `copilot plugin marketplace add SOURCE`; installed to `~/.copilot/installed-plugins/MARKETPLACE/PLUGIN` — [GitHub Docs: CLI plugin reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-plugin-reference)
- Plugins (VS Code): recognizes Agent Plugins 1.0 (`plugin.json` with `$schema` `https://agent-plugins.org/schemas/1.0.0/plugin.schema.json`), Claude (`.claude-plugin/plugin.json`), and Copilot legacy; contributes skills, MCP servers, custom agents, hooks, automation templates, slash commands; defaults marketplaces `copilot-plugins` and `awesome-copilot`; more via `chat.plugins.marketplaces` — [VS Code agent plugins](https://code.visualstudio.com/docs/agent-customization/agent-plugins)
- VS Code extension APIs (already planned by the audience; not re-fetched): `McpServerDefinitionProvider` and `vscode.lm.registerTool` language-model tools **[2025-era]**.

#### Gemini CLI
- Context files: global `~/.gemini/GEMINI.md`; project root and ancestors; just-in-time loading of `GEMINI.md` in accessed directories; `context.fileName` in settings.json accepts a list, e.g. `["AGENTS.md", "CONTEXT.md", "GEMINI.md"]`; `@file.md` imports (relative or absolute); `/memory show`, `/memory reload` — [Gemini CLI context files](https://geminicli.com/docs/cli/gemini-md/)

## KQ1: Which instruction files does each harness read, from where, nested AGENTS.md, and does Claude Code read AGENTS.md natively?

### Takeaway
Claude Code reads AGENTS.md natively since v2.1.277 (only when no CLAUDE.md/CLAUDE.local.md exists in cwd or above, unless the Project instructions setting is `claude-md-and-agents-md`), and most harnesses read nested AGENTS.md on access, but Codex is the notable exception (root → cwd only, never below cwd) and Zed reads a single root file.

### Cited Findings
- Claude Code: "Reading `AGENTS.md` directly requires Claude Code v2.1.277 or later." Default behavior table: AGENTS.md alone → reads AGENTS.md; AGENTS.md plus any `CLAUDE.md`/`.claude/CLAUDE.md`/`CLAUDE.local.md` in cwd or above → CLAUDE.md only; `~/.claude/CLAUDE.md`, managed CLAUDE.md and `.claude/rules/` do not count and keep loading alongside — [Claude Code memory](https://code.claude.com/docs/en/memory)
- Claude Code reads at session start "every `AGENTS.md` and `.claude/AGENTS.md` in your working directory and the directories above it" and, as Claude works, "a subdirectory's `AGENTS.md`, when Claude opens a file there with the Read tool and that subdirectory has none of the three `CLAUDE.md` files"; `@path` imports inside AGENTS.md are expanded; `AGENTS.local.md`, `AGENTS.override.md`, and `.agents/` are not read — [Claude Code memory](https://code.claude.com/docs/en/memory)
- Claude Code Project instructions setting values: `claude-md-or-agents-md` (default), `claude-md-and-agents-md` (CLAUDE.md first then AGENTS.md per directory, dedupes imported/symlinked copies), `claude-md`, `managed-only`; set via `/config` or under the built-in `agents-md` plugin's ID in `pluginConfigs` (user/managed settings only). `InstructionsLoaded` hooks do not fire for AGENTS.md read through the setting. Sessions on versions before v2.1.281 (e.g. Bedrock, telemetry disabled) read CLAUDE.md only; the documented workaround is `@AGENTS.md` inside a CLAUDE.md, or `ln -s AGENTS.md CLAUDE.md` (with a Windows caveat) — [Claude Code memory](https://code.claude.com/docs/en/memory)
- Codex: global `~/.codex/AGENTS.override.md` else `AGENTS.md`; from Git root to cwd, each dir checks `AGENTS.override.md`, `AGENTS.md`, then `project_doc_fallback_filenames`; "does not read subdirectories below your current location"; cap `project_doc_max_bytes` 32 KiB — [Codex AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
- Copilot: `AGENTS.md` "at any depth, where the nearest AGENTS.md file in the directory tree will take precedence," or a single root `CLAUDE.md` or `GEMINI.md` — [GitHub Docs](https://docs.github.com/en/copilot/how-tos/configure-custom-instructions/add-repository-instructions)
- Cursor: `AGENTS.md` "in project root or subdirectories" alongside `.cursor/rules/*.mdc` and legacy `.cursorrules` — [Cursor rules](https://cursor.com/docs/context/rules)
- Gemini CLI: GEMINI.md from global, project root and ancestors, and just-in-time from accessed directories; AGENTS.md only via `context.fileName` — [Gemini CLI context files](https://geminicli.com/docs/cli/gemini-md/)
- Windsurf/Devin: AGENTS.md "can exist in any directory; root-level is always-on; subdirectories auto-glob to that directory" — [Devin Desktop rules](https://docs.devin.ai/desktop/cascade/memories)
- Amp: subtree AGENTS.md loads "when the agent reads a file in the subtree"; `CLAUDE.md` is a legacy fallback — [Amp AGENTS.md](https://ampcode.com/docs/customize/agents-md)
- OpenCode: AGENTS.md traversal up from cwd; `CLAUDE.md` and `~/.claude/CLAUDE.md` fallbacks; glob `instructions` for monorepos — [OpenCode rules](https://opencode.ai/docs/rules/)
- Zed: first match in a fixed list (`.rules` … `GEMINI.md`); nested discovery not documented — [Zed instructions](https://zed.dev/docs/ai/instructions)
- Junie: `.junie/AGENTS.md`, root `AGENTS.md` + `.junie/playbook.md` + `.junie/rules/*.md`, legacy `.junie/guidelines.md`; nested discovery not documented — [Junie guidelines](https://junie.jetbrains.com/docs/guidelines-and-memory.html)
- agents.md convention: "Agents automatically read the nearest file in the directory tree, so the closest one takes precedence" — [agents.md](https://agents.md/)

### Inferences
- A docs tool that wants path-scoped instructions has three native options: Claude Code `.claude/rules/*.md` with `paths:`, Copilot `.github/instructions/*.instructions.md` with `applyTo`, Cursor `.mdc` `globs`, Windsurf `trigger: glob`, Amp `globs` frontmatter on @-included files, and Codex has none (only nested AGENTS.md above cwd). Nested `docs/AGENTS.md` is the only cross-harness path-scoping mechanism, and it does not work for Codex when the user launches from repo root.
- Because adding `CLAUDE.local.md` silently disables Claude Code's AGENTS.md read, a tool's installer should write `@AGENTS.md` into any CLAUDE.md it creates rather than rely on the default.

### Gaps
- Whether Codex Cloud and the IDE extension use the same AGENTS.md discovery as the CLI is not stated ("Assume consistency unless documented otherwise").
- Junie and Zed nested-file behavior is undocumented.

## KQ2: Which hook events exist per harness, what JSON they receive/return, how output reaches the model, and does Claude Code PostToolUse exit-0 stdout reach the model?

### Takeaway
Eight of ten harnesses have shell hooks; Claude Code (33 events), Codex (12), Copilot (14), Cursor (~22), Gemini CLI (11), and Windsurf (12) all use stdin JSON → stdout JSON with exit 2 as "block", and the Claude Code shape (`decision`/`reason`, `hookSpecificOutput.additionalContext`, `permissionDecision`) has been copied nearly verbatim by Codex and Copilot. For Claude Code PostToolUse, plain exit-0 stdout does NOT reach the model; only `UserPromptSubmit`, `UserPromptExpansion`, `SessionStart`, and `PostModelSwitch` add plain stdout to context, so a PostToolUse linter must emit JSON `hookSpecificOutput.additionalContext`, `decision: "block"` + `reason`, or exit 2 with stderr.

## KQ4: How do Copilot custom agents, Claude Code subagents, and Cursor's equivalents let a tool ship a "docs writer" persona, and is that worth it versus a skill?

### Takeaway
All three (plus Codex, OpenCode, Gemini extensions) accept a Markdown/TOML persona file with `name`, `description`, tool allowlist, model, and optional MCP servers, and Copilot/Cursor read Claude's `.claude/agents/*.md` format directly; but a persona runs in a separate context, cannot be path-triggered, and Claude Code plugin agents cannot carry hooks or MCP servers, so for a docs linter a skill (optionally with `context: fork` and `agent:`) is the lower-cost default and an agent is worth shipping only when isolation, a different model, or a restricted toolset is the point.

### Cited Findings
- Claude Code subagent definition fields include `tools`, `disallowedTools`, `model`, `permissionMode`, `skills` (preloaded; "The full content of each listed skill is injected into the subagent's context at startup"), `memory` (persistent `MEMORY.md` under `.claude/agent-memory/<name>/`), `mcpServers`, `hooks`, `isolation: worktree`; subagents do not receive conversation history, output style, or already-invoked skills; combined descriptions capped at 15,000 tokens — [Claude Code subagents](https://code.claude.com/docs/en/sub-agents)

- Claude Code skills can run in an isolated subagent with `context: fork` and `agent: Explore|Plan|general-purpose|<custom>`, defaulting to background — [Claude Code skills](https://code.claude.com/docs/en/skills)
- Claude Code output styles can change Claude's role entirely (e.g. "a writing assistant"), and a plugin can set `force-for-plugin: true` to apply its style automatically, but styles are not enforced and do not reach subagents — [Output styles](https://code.claude.com/docs/en/output-styles)
- Copilot VS Code custom agents: `.github/agents/*.agent.md` with `tools`, `agents`, `model`, `handoffs`, `target`, `mcp-servers`, `hooks`; also reads `.claude/agents/*.md` and maps Claude tool names — [VS Code custom agents](https://code.visualstudio.com/docs/copilot/customization/custom-agents)
- Copilot cloud agent custom agents: `.github/agents/NAME.md` with `description`, `prompt` (required), `tools`, `mcp-servers`; org/enterprise distribution via `.github`/`.github-private` repos — [GitHub Docs: about custom agents](https://docs.github.com/en/copilot/concepts/agents/coding-agent/about-custom-agents)

- Codex custom agents are TOML with `developer_instructions`, `sandbox_mode`, `mcp_servers`, `skills.config` — [Codex subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)
- OpenCode agents support `mode: primary|subagent|all`, `prompt`, `permission`, `steps` — [OpenCode agents](https://opencode.ai/docs/agents/)
- Gemini CLI extensions may ship `agents/` sub-agent markdown — [Extensions reference](https://geminicli.com/docs/extensions/reference/)
- Claude Code's own guidance: use a skill for "Instructions for one kind of task" (loaded only when invoked or matched) and a subagent for "A helper with its own instructions, model, and tools for a focused task" — [Output styles comparison table](https://code.claude.com/docs/en/output-styles)
- Every Claude-invocable agent's name and description sits in context on every turn — [Plugins overview](https://code.claude.com/docs/en/plugins)

### Inferences
- A "docs writer" persona is cross-harness-portable only as a Claude-format `.claude/agents/docs-writer.md` (Claude Code, Copilot/VS Code, Cursor read it) with `name`, `description`, `tools` fields; Codex (TOML) and OpenCode (different fields) would need separate files.
- Because Copilot's `.agent.md` and Codex agents can embed `mcp-servers`/`mcp_servers`, an agent file is the one place a docs tool can bundle its MCP server without touching the user's global MCP config on those two harnesses; on Claude Code that role belongs to the plugin `.mcp.json`.

### Gaps
- No harness documents measured quality differences between a skill and an agent for the same task; the trade-off above is architectural, not empirical.
