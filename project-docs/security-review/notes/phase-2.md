# Phase 2 notes: running other programs

Hardening notes from [phase 2](../phase-2-programs.md), reviewed on 27 October 2026 by one agent and checked by a second, adversarial one, each reproduction rebuilt from the first's description. **No exploitable finding** (README decision 2): nothing a project's content or another program's output can make Ascribe run, and nothing a revision or a URL can turn into a `git` option. Each note says where it is, what it costs, one recommendation, and a size.

## H1: `file://` is the fifth transport a `[sources]` repository may use

- **Where:** `crates/ascribe-sources/src/remote.rs` (`SETTINGS`, `protocol.file.allow=always` after `protocol.allow=never`), `crates/ascribe-model/src/loader.rs` (`is_git_url`), and the contract: SPEC §7.4, `crates/ascribe-model/settings.toml`'s `git` key, and `docs/content/examples/sources.md`, which all name `file://`. The review's README said four transports; the code and the contract have five, and the README now says so.
- **What it costs:** `ascribe sources fetch` and `update`, run by a person in a repository whose `ascribe.toml` they haven't read, copy the files its snippets name out of any git repository at an absolute path on that machine into `sources/<name>/`, naming each copy on the terminal and recording the URL in `ascribe.lock`. Only those two commands reach another repository: `check`, `build`, the language server, the MCP server, the hook, the extension (which runs only `ascribe model --section sources`), and every workflow in `.github/workflows/` never fetch, verified by running each. The same actor and boundary already run a project-supplied `[checks.vale] command` from `ascribe check`, which decision 76 leaves to the person. `ext::` and a URL starting with `-` are refused at model load.
- **Recommendation:** phase 6 chooses. Accept, as decision 76 did for the same class: one sentence in `docs/content/examples/sources.md` that a `file://` source reads any repository on this machine, so read `ascribe.toml` before the first `fetch` in a repository you didn't write. Or close: `fetch` and `update` refuse a `file://` source unless opted in (an environment variable `crates/ascribe-sources/tests/common/mod.rs` and `scripts/sources-fixture/setup.ts --local` set), with a diagnostic; the language keeps `file://`. Removing it from the language is a contract change (`SPEC.md`, `settings.toml`, the docs page) and breaks every fetch test in `crates/ascribe-sources/tests/`, so it isn't the change.
- **Size:** small to accept; medium to close, with its decision.

## H2: the review package's `git` calls pass a revision without `--end-of-options`

- **Where:** `packages/review/src/github/requests.ts` (`rev-parse --verify --quiet <revision>`), `packages/review/src/github/session.ts` (`cat-file -e`, `merge-base --is-ancestor`, `diff <base>...<head> -- :(literal)<path>`), `packages/review/src/place/lines.ts` (`cat-file <commit>:<file>`), and `packages/astro/src/review/github.ts` (`rev-list --left-right --count HEAD...<oid>`). The Rust side does it right: `crates/ascribe-diff/src/git.rs`'s `commit_of` passes `--end-of-options`, and every path listing passes `--`; `ascribe diff`, `drift`, `check`, and `addresses move --from-git` with `--base=--version` are refused as "isn't a revision", and a bare `--output` is refused by clap.
- **What it costs:** every revision at those lines is an object id from GitHub's GraphQL fields, the checkout's own `HEAD`, or `origin/<baseRefName>`, and GitHub and `git check-ref-format` refuse a ref name starting with `-`, so nothing reaches `git` as an option today. The TypeScript checks none of that itself, so a future call site with a looser value, or a ref name that reaches it another way, would hand `git` an option.
- **Recommendation:** add `--end-of-options` before the revision in each of those calls, as `ascribe-diff` does, and a unit test beside `packages/review/test/git.test.ts` that holds every `git` argument list in the package to it.
- **Size:** small.

## H3: the review package's `git diff` doesn't pass `--no-textconv`

- **Where:** `packages/review/src/github/session.ts` and `packages/review/src/place/lines.ts`, which pass `--no-ext-diff` and not `--no-textconv`.
- **What it costs:** a `diff.<driver>.textconv` command in the checkout's `.git/config` with a `.gitattributes` naming the driver does run while the patch is generated; the second reviewer saw it fire under the package's exact flags on git 2.43, and not with `--no-textconv`. It stays a note because the command must be in `.git/config` or a global configuration, which committed content can't deliver, and a planted bare repository is refused by decision 76's `safe.bareRepository=explicit`.
- **Recommendation:** add `--no-textconv` beside `--no-ext-diff` in both calls.
- **Size:** small.

## H4: `[checks.links] command` and `[checks.vale] command` choose the binary that runs

- **Where:** `crates/ascribe-check/src/tool.rs` (`program`: a command with a path separator is resolved against the project root, a bare name against the `PATH`); `crates/ascribe-model/src/checks.rs` and `prose/`. The site check's command is the fixed bare name `afdocs`.
- **What it costs:** the project's content picks which program runs for the link check and the prose check. Decision 76 bounds Vale: the MCP server never starts it, the hook runs only a bare name, and the language server asks once. The link and site checks are report-only (`stage = "report"` for ASC168 to ASC171 in `tests/conformance/diagnostics.toml`), so lychee and afdocs run only from `ascribe report`, which this repository runs on a schedule on `main` (`report.yml`), never on a pull request's checkout. Arguments are a list, never a shell, and lychee reads its addresses on standard input, so the program's name is the only lever. If `ascribe report` or a link check were ever run on a fork's checkout, a project-supplied binary would run in CI.
- **Recommendation:** give the link check's `command` the rule decision 76 gives Vale's (a bare name on the `PATH` from an agent's surface; a question from the editor), and have phase 5 record that no workflow runs `report` on an untrusted checkout.
- **Size:** small to record; medium to extend decision 76's rule to the link check.

## H5: the extension runs a `.cmd` shim through a shell on Windows

- **Where:** `packages/vscode/src/environment.ts` (`runVersion`), `ui/tasks.ts` (`askSources`), `ui/checkEveryBuild.ts`, and `ui/agentFiles.ts`, each with `shell: usesShell(file)`, true only on Windows for a `.cmd` or `.bat` file.
- **What it costs:** the project's `node_modules/.bin/ascribe.cmd` runs through `cmd.exe`. The path is double-quoted and a Windows path can't contain `"`, the arguments are static, and the whole activation waits on Workspace Trust (`extension.ts`), with `tasks.ts` rechecking `isTrusted` at every entry; running the project's own binary after trust is the extension's declared design (`package.json`'s `untrustedWorkspaces`). Nothing to inject today.
- **Recommendation:** none required. For defence in depth, run the shim as an explicit `cmd /c` argument list instead of `shell: true`.
- **Size:** small.

## H6: `rust.yml` runs `ascribe observe` on a pull request's checkout

- **Where:** `.github/workflows/rust.yml`, the tested example's seam in `examples/tested/code` (`ascribe observe --name node-22`, then `observe --check`), called by `ci.yml` on `pull_request`. The threat model said no workflow did, and was corrected.
- **What it costs:** nothing today: the job already runs `cargo test --workspace` on the same checkout, `ci.yml` calls `rust.yml` with `with:` and no `secrets: inherit`, `rust.yml` sets `permissions: contents: read`, and `ci.yml` never uses `pull_request_target`. `observe`'s own guards hold: it reads only the `ascribe.examples.toml` in the folder it's run in, refuses one that arrived as a `sources fetch` copy, and substitutes nothing into the line. The cost is that the invariant is unwritten, so a job that gained a secret or a write token while running `observe` on a fork's checkout would be exploitable with no tripwire.
- **Recommendation:** a line in `scripts/ci/` (which already checks every job has a timeout) that fails when a job running `observe`, `cargo test`, or `pnpm test` on a `pull_request` checkout inherits secrets or has a write permission.
- **Size:** small.

## Checked, nothing found

Each question of the phase, what was tried, and the outcome. Reproductions were built in a scratch folder with `ASCRIBE_CACHE_DIR` set so nothing touched the real cache.

- **A revision starting with `-`**, through `ascribe diff --base`, `drift --base`, `check --base`, `addresses move --from-git --base`, and the MCP tool's revision (the same path). Tried `--base=--version`, `--base '--output=<file>'`, `--base '--all'`: clap refuses a bare option, and `Repository::commit_of` passes `--end-of-options`, so the rest are "isn't a revision". No file written, no option honoured. A `[sources]` `branch` is held to `is_branch_name`, which refuses a leading `-`; a `ref` is held to `is_commit`.
- **The protocol allowlist on every `git` that can reach a remote.** `ascribe-sources` is the only crate that fetches; `ascribe-diff` runs only `rev-parse`, `merge-base`, `ls-tree`, `diff --name-status`, `status`, `cat-file`, and `rev-list`, so SSH, credential, and proxy configuration never apply there. `ext::` and a `-` URL are refused at model load; `file://` is H1.
- **A checkout's own `.git/config` running a command.** A committed folder shaped like a bare repository is refused by `safe.bareRepository=explicit` (reproduced). A crafted non-bare `.git/config`, which committed content can't deliver, with `core.fsmonitor`, `core.hooksPath`, `diff.external`, `core.pager`, `core.sshCommand`, and a textconv driver, under `ascribe diff --base HEAD~1` with `GIT_TRACE`: none fired. `core.fsmonitor=false` on the command line wins over the file; `diff --name-status` makes no patch, so `diff.external` and textconv don't apply; no read-only command runs a hook; the pager is bypassed when output is piped; `sshCommand` needs a fetch. The review package's patch-making `git diff` is H3.
- **A remote source's links, submodules, LFS, and hooks.** A remote with a symbolic link out of it and a regular file: the link is refused ("a symbolic link or a submodule, not a file") and its target never read; only the regular file is copied. `Remote::tree` takes only `100644` and `100755` blobs; `fetch` passes `--no-recurse-submodules` and `--filter=blob:none`; the cache's `core.hooksPath` points at a folder that doesn't exist.
- **How lychee, afdocs, and Vale are found and run.** One `Command::new(program)` in `tool.rs` with a fixed argument list, never a shell; lychee's addresses on standard input; afdocs gets `check <site> --format json --quiet`. Program choice by content is H4.
- **Timeouts and output limits.** `tool::run` stops a program at its deadline (unit test `a_slow_program_is_stopped`) and fails past 64 MiB of output, keeping 64 KiB of standard error. Callers pass bounds: links 30 minutes, site 15 minutes, Vale 600 seconds for a project and 30 for a file. Nothing unbounded.
- **The binary the editor runs, and Workspace Trust.** Activation waits on `onDidGrantWorkspaceTrust` before any server, task, or process starts, on a restart too; `tasks.ts` rechecks `isTrusted` at every entry. `ascribe.path` is `machine-overridable`, so a workspace can set it, and it takes effect only after trust.
- **`@ascribed/astro`'s `run.ts`, `project.ts`, and `review/diff.ts`; `@ascribed/review`'s `git.ts`.** `execFile`, no shell; the binary from the `binary` option, `ASCRIBE_BIN`, then the bundled one, which the site's author sets, not a page; `review/diff.ts` puts `--` before its path. `git.ts` applies `ascribe_core::git`'s `OPTIONS` and `CLEARED`, held to the Rust lists by `packages/review/test/git.test.ts`. What's missing is H2.
- **The hook's check server.** `checker.rs` starts `current_exe()` as `agents hook-server` with absolute paths it built; on Windows it starts `powershell.exe -NoProfile -NonInteractive` with paths single-quote-escaped. The mailbox and the binary's copy live in the user's cache folder, not the project.
- **`ascribe observe`.** The one shell start, `sh -c` or `cmd /C`. It asks at a terminal and runs nothing on a no; `--yes` or no terminal runs it. It reads only the `ascribe.examples.toml` in the current folder, refuses one that's a `sources fetch` copy, and substitutes nothing. Where CI runs it is H6.
