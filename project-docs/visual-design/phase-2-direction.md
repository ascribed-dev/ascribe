# Phase 2: The mark and the palette

Part of [Visual design](README.md). Needs no other phase; easier after phase 1. Design work, ending in a choice only the maintainer makes.

## Goal

Candidates for the three things everything else is made from, shown together so they can be judged together:

- **the mark,** with a wordmark;
- **the palette:** a neutral scale, one accent, and the semantic colors;
- **the type scale:** sizes, weights, and line heights over the system font stacks.

The phase ends when the maintainer has chosen. It doesn't apply the choice anywhere.

## Context

- The README's "What VS Code allows" and decisions 5 to 8: the constraints the mark and palette must meet.
- What needs a semantic color today. Read them in the stylesheets rather than trusting this list:
  - note types: note, tip, important, warning, caution (`packages/elements/css/style.css`);
  - availability states: the default, GA, preview, beta, deprecated, and the rest in the same file;
  - review: added, changed, removed, moved, focus, flash (`packages/review/src/marks/marks.css`);
  - the chrome: text, muted text, background, surface, border, accent, code background (`site/src/styles/site.css`).
- What the product is, for whoever draws: documentation as code, one source resolved into several outputs, `@` directives, variants and availability. `README.md` and `docs/content/index.md`.
- `design/tokens.toml` from phase 1, if it exists: the candidates are alternative `[palette]` and `[color]` sections.

## Design

### The brief for the mark

- Reads in one color at 16 pixels, and holds up at 128. Test both before showing a candidate.
- Works on light and dark backgrounds without a second drawing. A second color is allowed in the full-color version only.
- Square, or sits well in a square: the Marketplace icon, the favicon, and the GitHub avatar are all square.
- Not a plain `@` in a circle and not a generic document glyph: both already mean email and "file" in every toolbar it will sit in.
- A wordmark set in a system font, or drawn as outlines. No font license to carry (decision 7).

### The brief for the palette

- A neutral scale of about ten steps and one accent hue with enough steps for text, borders, and tinted backgrounds in both schemes.
- The semantic colors keep their meanings: green stays "added" and "tip", red "removed" and "caution". What changes is the hues' exact values and how they sit together.
- Every pairing the stylesheets use passes decision 5's contrast, in light and in dark. Compute it; don't judge it.
- Distinguishable with red-green color blindness wherever two colors appear side by side with different meanings (added and removed; GA and deprecated), with the existing shapes and labels as the backstop.

### The specimen page

`design/specimen.html`: one local, self-contained file, generated by `scripts/design/specimen.ts`, opened in a browser. It's a file in the repository, not a published page. For each candidate, in light and dark side by side:

- the mark at 16, 24, 32, 64, and 128 pixels, in one color and in full color, on both backgrounds, and as a mock activity bar and browser tab;
- the palette as swatches with their names and contrast ratios;
- real markup from the element library (each note type, steps, tabs, availability badges), a page with review marks of each kind, and the docs site's header, sidebar, and a code block;
- the type scale.

The specimen reads candidate files (`design/candidates/<name>.toml`, and the candidate marks as SVG beside them), so adding a candidate adds no code.

## Tasks

1. The specimen generator, first showing today's values as the baseline candidate.
2. Three to five candidate marks as SVG, and two or three candidate palettes. Fewer, better candidates beat many.
3. A contrast table for each palette, generated, with every failing pair listed.
4. **Stop.** Open a pull request with the specimen and a short note on each candidate: what it's going for, and where it's weak. The maintainer chooses, asks for another round, or brings in a designer for the mark.
5. After the choice: the chosen mark as `design/mark.svg` (one color, using `currentColor`), `design/mark-color.svg`, and `design/wordmark.svg`; the chosen palette and type scale recorded as `design/candidates/chosen.toml`. Remove the candidates that lost. The specimen stays, showing what's chosen.

## Out of scope

Changing `design/tokens.toml` or any stylesheet (phases 4 and 5); making sizes and rasters (phase 3).

## Acceptance criteria

- The maintainer has chosen a mark, a palette, and a type scale, and the pull request records the choice.
- The chosen mark's sources are in `design/`, each a clean SVG: no editor metadata, no embedded raster, no font reference, a `viewBox`, and paths that render the same in a browser and in `sharp`.
- The chosen palette passes decision 5's contrast for every pairing in use, by test.

## Verify

```sh
pnpm format:check && pnpm lint && pnpm typecheck && pnpm test
node scripts/design/specimen.ts && open design/specimen.html
```
